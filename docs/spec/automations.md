# 自动任务与日程

在中书里看见、管理 DSH 原生[自动任务](../../CONTEXT.md)，接住它们的运行结果，让 Agent 能用一句话[主动通知](../../CONTEXT.md)用户，并用日历把过去和未来放在一张图上。边界见 [ADR 0021](../adr/0021-automations.md)。界面以 2026-11-08 用户认可的交互原型为准（日程页五个标签、对话里的自动任务条、通知直达、例行任务的历次运行、月/周日历与拖动改期）。用户选择本切片一次做全，日历包含工作区时间轴文件。

| 用户行为 | 可观察结果 |
| --- | --- |
| 看全部安排 | 侧栏「日程」：日历（月/周）、今天、未来、回看、全部任务。原生自动任务与时间轴条目按类型着色，标出已完成、已通知、接近触发、下一个、迟到、已暂停；可筛选类型；顶部汇总待跑、通知、迟到、暂停与密集日 |
| 管理任务 | 新建（表单）、暂停、恢复、立即运行、修改、删除，均写原生并做冲突检查。周视图拖动尚未运行的一次性任务改期；循环任务在表单里改 |
| 自动运行 | 投递到任何对话（含无人阅读的）都显示运行中，结束后计未读、按规则推送。被投递的指令原样显示并标明来自哪个任务。宿主重启后补投的标为迟到 |
| 每次新开的任务 | 任务新建的会话如在已登记工作区内，接入为中书对话，侧栏每个任务只占一行，点开可切换历次运行 |
| 对话里 | 有任务投递进来的对话顶部显示「这段对话的自动任务」：每个任务的时间、状态和一句话结论 |
| 主动通知 | Agent 调用中书提供的通知工具（摘要与可选的工作区文件），手机收到这句话，点开落到那一轮并高亮；无法确定所属对话时，通知改为打开日程 |
| 时间轴 | 日历读取工作区 `.zhongshu/timeline.jsonl`：每行一条事件（日期、可选时间与时区、类型 action / event / decision / research、标题、说明、工作区内链接），同一 id 以最后一行为准。中书只读，格式错误的行跳过并提示 |

不做：Codex 自动任务、条件引擎、写入或读取任何提醒应用、在中书里编辑时间轴、日历订阅导出、haokun-stock 的迁移与技能改写（另行进行，验收时用它的真实任务）。

## 实现要点

- 第一步先打通最小真实路径：中书在预发实例读到原生任务列表；DSH 容器能调用中书的通知工具，工具记录出现在会话里并能对应到对话。两者任一不通就回到 ADR 0021 重新对齐。
- 投递消息在原生里是带 `source.kind = "schedule"` 的用户消息，用投递回执的消息编号对应任务。
- 通知工具由中书以 MCP 提供，DSH 以 `mcp__zhongshu__notify_user` 调用。工具调用不带会话身份，中书从它观察到的工具记录确定对话与轮次。连接地址与鉴权是实例配置，不进源码。

## 验收

- 预发实例真实 DSH：Agent 建投递到原对话、首次新建后复用、每次新建三种目标的任务；离开页面后的投递显示运行、未读与推送；投递指令可见；新建会话接入并归在任务下；主动通知直达那一轮；暂停、恢复、立即运行、修改、删除、拖动改期在原生读回一致，并发修改给出冲突提示；宿主重启后的补投标为迟到。
- 时间轴文件：有效、重复 id、格式错误、越界链接各一组样本。
- 作者在桌面与手机宽度自测；用户在测试实例用手机收真实推送并验收。本切片不做独立执行验收（用户决定）。
- `npm run typecheck`、`npm test`、`npm run build`、`npm run check:docs` 通过；新增功能地图。
