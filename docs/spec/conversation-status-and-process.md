# 对话状态提示与过程展示

## Goal

来源：2026-11-10 用户对真实对话（PROD 上 jianwei 研究对话）的三项体验反馈。用户希望优化对话中的使用与交互展示，并在讨论中确认了两个取舍。本工作单只处理这三项反馈，不扩大成整体视觉改版。

三项问题与根因：

1. 「暂时无法核对原生状态；已有内容保留，任务不会自动重发。」与「正在核对执行结果。」出现在输入框上方；很多出现时机是正常发送后的短暂等待，用户不知道它们代表什么状态。
2. 工具过程在运行中自动展开、整轮结束后自动收起并清空用户选择，相邻多组工具反复开合；命令详情应默认收起，只在读者主动展开时展开。
3. 「失败于「bash」」的判定是从“最后一条工具记录失败”推断的；工具记录按连续条目分组，一轮中 Agent 插话就会切成多组，运行中某组最后一条命令失败时会提前显示失败、之后又变回已完成。整批失败的条件既不清晰也不稳定。

## Users and stories

阅读一段正在执行或刚结束的对话时：用户能分清“正常在等”“原生状态读不到、需要核对”“是真的失败了”；过程块不因数据更新改变开合状态；个别命令失败只作为事实呈现，不被写成整批失败。

## Scope / Non-goals

| 范围 | 可观察行为与边界 |
| --- | --- |
| 对话级状态提示 | 正常发送后的短暂等待（排队、派发中、上一条消息尚未拿到原生轮次）不显示提示条。只有原生会话状态无法核实、存在结果未知的操作、或对话准备/配置被阻断时，在正文区顶部（标题栏下、正文之上）显示一条紧凑提示；提示说明当前是什么状态、已知原因、已保留内容与不自动重发的承诺，并提供「查询原生结果」；原生状态未知时页面打开期间会自动重试。同一时刻最多一条，出现在输入框上方的重复提示移除。原因码都有对应人话，不再落到兜底句。 |
| 过程展示 | 工具过程摘要行默认收起；运行中用转圈图标并在摘要里显示当前步骤名；结束后用对勾/警示/问号等图标表达事实。开合只由读者点击决定，数据更新、运行结束、下一轮出现都不自动改变。步骤行同样默认收起。 |
| 失败语义 | 摘要不把“最后一条工具记录失败”推断为整批失败：有未成功步骤时显示「N 项未成功」（警示色），运行中不出现失败结论；只有原生轮次终态为失败时显示「本轮失败」，中断显示「已中断」，状态不足显示「状态未明」。失败步骤在展开后带 X、状态和退出码。 |
| 保持不变 | 不编造原生状态，未知不显示为成功；真实工具状态、消息与图片、发送/停止/恢复语义不变；不改 Harness 协议、数据库结构或服务端持久化。 |

不包含：整体视觉重做、输入框/队列改造、审批与问答、新 Harness、发布。原生状态提示的文案与位置调整不改服务端的核对逻辑。

## Implementation decisions

用户 2026-11-10 已确认的两个取舍：

- **提示位置**：正文区顶部一条紧凑提示，不再出现在输入框上方；正常的核对等待完全不显示。
- **失败显示**：只报事实（X 项操作 · Y 项未成功，警示色），只有原生确认整轮失败时才显示「本轮失败」。

实现安排：

- 过程块的开合状态只由读者选择决定；运行状态、轮次终态由工作台从对话状态传入（`state.runId` / `terminalRunId` / `terminalStatus` / `latest`），历史轮次缺少终态时按步骤事实中性展示，不推断为整轮失败。
- 对话级提示的判定抽成纯函数，便于自动检查；渲染为独立模式组件，位置固定在正文区顶部。
- 「查询原生结果」动作文案保持不变，与执行、恢复、子 Agent 地图中的同一动作一致。
- 正常发送后的“等待原生轮次”只作为被阻塞的发送条件保留，超过一段明确延迟仍未核实时才升级为提示，避免每次发送闪烁。新建对话或切换对话时原生状态的初始未知也加约 2 秒宽限，只有持续无法核实时才显示提示，避免页面一闪。

## Testing decisions

- 定向自动检查：纯函数覆盖“哪些状态才显示提示”和“摘要如何表达成功/未成功/整轮失败”；`npm run typecheck`、`npm test`、`npm run build`、`npm run check:docs`。
- Storybook：过程展示各状态（运行中收起、完成、中途失败、整轮失败、中断、状态未明、长内容）与对话级提示各状态，可切换并截图。
- 真实页面：本地调试实例上用真实 DSH 跑一轮含“中途失败后继续成功”的命令，核对默认收起、运行中摘要、完成后摘要与展开明细、刷新后仍收起；另跑停止与原生状态未知分支。刷新、切换对话与既有发送路径回归。
- 完成后更新 [界面 I06](../features/interface.md)、[对话基本可用性 U03 与新增状态提示场景](../features/conversation-usability.md)、[执行](../features/execution.md)、[恢复](../features/continuity.md) 中受影响的操作入口描述。用户实际使用确认是退出条件的一部分。
