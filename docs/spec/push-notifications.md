# 通知与安装

## Goal

用户在手机和电脑之间交替使用中书。离开页面后，也要知道对话完成、失败、Agent 在等回答或审批，以及 Harness 账号需要处理。规则与依据见 [ADR 0018](../adr/0018-push-notifications.md)。

2026-11-07 用户确认了两件事：

- 安卓与桌面 Chrome 的推送经由 Google 的推送服务。手机要连得上 Google 才能及时收到；连不上时由推送服务代存、补送，超时作废。打开和使用中书不受影响。用户接受这一依赖，保留通知。
- 不先做推送自检，直接做完整功能。

界面原型经用户确认（2026-11-07）。同日用户决定：通知显示对话标题（ADR 0018 已注明）；“Harness 账号需要处理”在 Harness 账号切片接通并验收；本切片不做独立执行验收，由用户在测试实例验收。

用户已授权实施，本文不表示已经实现。

## Users and stories

1. **安装。** 在手机或电脑上把中书安装成独立窗口，图标清晰。iOS 需要先从 Safari 添加到主屏幕，页内给出提示。
2. **开启。** 在设置中为这台设备开启通知。浏览器拒绝或不支持时说明原因。可以给这台设备发一条测试通知。
3. **触发。** 离开页面后，以下事件推送到每台已开启的设备，通知显示对话标题与事件：
   - 对话完成；
   - 对话失败或意外中断；
   - Agent 在等回答或审批；
   - Harness 账号需要处理（随 Harness 账号切片接通）。
4. **不打扰。** 任何设备正在看这个对话时，不推送；用户主动停止的对话不推送。
5. **直达。** 点开通知，打开或切到对应对话；Harness 账号的通知打开设置。
6. **管理。** 在设置中查看已开启的设备和最近一次送达情况，移除任意一台。
7. **角标。** 平台支持时，应用图标显示未读数。

## Scope / Non-goals

范围：Android 与桌面 Chrome；iOS 主屏幕应用按平台能力尽力支持。

非目标：

- 离线缓存；
- 通知中出现消息正文、提问内容或文件内容；
- 按对话或事件类型的通知偏好；
- 不经浏览器推送服务的提醒渠道。

## Implementation decisions

- service worker 只处理推送和点击通知，不拦截请求。
- 推送消息按 Web Push 标准端到端加密，用实例自己的密钥签名。密钥首次使用时生成，存放在实例数据中。
- 只向主流浏览器的推送服务发送；推送地址视为凭据，不写日志。
- 推送服务报告订阅失效时，删除该订阅。
- 界面先在 Storybook 做原型，用户确认后再接功能（[ADR 0008](../adr/0008-storybook-ui-prototypes.md)）。

## Testing decisions

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| N01 加密与签名 | 用 RFC 8291 附录的中间值核对加密输出；签名能用公钥验证 |
| N02 送达 | 真实浏览器订阅后，服务端经真实推送服务发出，浏览器的 service worker 收到并显示通知；不以服务端返回 201 为准 |
| N03 触发与不打扰 | 真实 Harness 的完成、失败和等待各触发一次推送；同一对话正被阅读时不推送；用户停止不推送。账号事件在 Harness 账号切片验收 |
| N04 直达与管理 | 点通知切到对应对话；移除设备后不再收到；失效订阅被清理 |
| N05 内容 | 推送载荷只含事件类型、对话标题、对话编号、未读数和固定文案，不含消息、提问或文件内容 |
| N06 安装 | Android 与桌面 Chrome 识别为可安装，安装后以独立窗口打开 |
| N07 交付 | 作者在浏览器中自测；四项仓库检查通过；更新功能地图；用户在测试实例完成手机与跨端验收。不做独立执行验收（用户决定） |
