# 多年使用与极限规模：上线前联合规格

本轮范围修订：普通文件编辑不再要求停机或独占运行组，以 [ADR 0014](../adr/0014-observation-lifetime-and-concurrent-editing.md) 为准；下文旧门禁要求仅适用于遗留窗口恢复及管理操作，不作为新编辑的验收目标。

## 来源与范围

来源为本轮多年使用讨论、工程边界实验后的完整架构方案，以及用户要求先修改架构和 ADR、再正式化规格的指令。五类问题全部属于上线前范围。全量后台阅读存档、巨型正文有限预览与完整阅读器、容量不足保全旧存档并暂停新增工作和上传，均为已确认决定。用户已授权按联合计划持续实现、集成与验证，全部退出条件仍须满足。

目标职责由 [ADR 0012](../adr/0012-bounded-data-paths.md) 唯一维护，正文与容量承诺见 [ADR 0010](../adr/0010-durable-reading-archive.md)，执行与写入协议见 [ADR 0011](../adr/0011-managed-workspace-execution.md)。当前实现仍以[架构地图](../architecture.md)和 feature maps 为准。

## 子规格与联合交付

| 子规格 | 用户结果 | 依赖 |
| --- | --- | --- |
| [受管工作区编辑](managed-workspace-editing.md) | 历史对话多时仍可进入编辑；执行、保存和恢复不竞争写入 | 统一入口、持久未决登记、两个 Harness 的控制器 |
| [后台阅读存档](history-archival.md) | 不翻阅也能补齐可获取正文，中断后沿进度继续 | 正文持久化与容量准入；与执行状态分离 |
| [有界对话阅读](bounded-conversation-reading.md) | 长对话和巨型消息可读，输入、滚动及切换不随累计历史扩大工作量 | 摘要/正文分离、完整内容接口 |
| [多年容量与恢复](storage-longevity.md) | 跨越累计上限后继续工作，容量不足保全历史，扩容与恢复可继续 | 持久身份、存档提交与备份一致性 |
| [大目录与工作区导航](workspace-directory-index.md) | 找到尚未展开的旧工作区和大目录后续文件 | 稳定索引、清单代次和查询预算 |

五个子规格的产品承诺保持，剩余验收范围按用户在 2026-11-05 确认的 [ADR 0013](../adr/0013-bounded-recovery-acceptance.md) 收敛。通用文档附件、多用户、跨主机数据库和恢复原生模型上下文不在本轮范围。原有身份、权限、未知回执不重派、同一对话原生绑定及图片持久性不得退化；相关旧 spec 的未完成验收继续保留。

实施切片、依赖、并行所有权、expand–contract 与回退安排唯一维护在[执行计划 #23](https://github.com/Lanbasara/zhongshu/issues/23)。计划先贯通真实编辑与存档路径，再汇合五类能力；各子规格链接对应任务。本页维护产品承诺与联合退出条件，不复制任务进度。

## 固定收口与停止条件

| 项 | 本轮动作与通过条件 |
| --- | --- |
| 正常负载 | 在当前实例总资源预算的本地隔离现场，复用 60,000 条单段、10,001 段对话及百万历史总量，验证打开、翻页、输入、完整正文及后台推进；既定延迟预算保持。明确合成源与真实原生边界，客户端资源另列 |
| Codex 故障 | 一次运行中原生进程终止；受控恢复原容器与绑定，旧正文摘要一致，原未知操作不重发，恢复后可执行新工作；恢复失败不得伪报完成 |
| DSH 故障 | 同上，仅该端一次固定场景，不扩展原生故障时序矩阵 |
| 网关重启与编辑保护 | 同数据重启保留操作及编辑窗口；窗口内原生不得被恢复器启动，保存字节独立核对；显式退出窗口后恢复原绑定 |
| 容量压力 | 用最终存储版本复用真实 ENOSPC/配额场景，旧档可读、未提交不发布、空间恢复后可继续；复验原观察累积现场，补计固定观察次数的主库及 Host 账本增长 |

原 Codex 空对话配置问题和观察未决累积问题只按上述恢复与保护标准关闭。范围内实现完成后冻结一个候选并执行一次固定验收；必验项失败则停止本轮并给出具体不通过结论，不自动进入新一轮修复。测试装配错误单独记录，可修正驱动后执行原场景，不得改结果或扩大场景。范围外问题只记录。

不再新增规模、平台、权限组合、固定时长或原生轮次总量门槛。原 40/1,000 真实原生扩展不再继续；保留既有证据及失败记录。未受影响的通过证据按源码/依赖映射复用。所有实验使用独立本地资源，不连接或修改 VPS 当前实例。

## 共同证据要求

- 固定候选提交、依赖与两个原生版本；先复现旧版本的有区分力反例，再用同一数据与动作验证改进。数据使用合成输入，期望集合、原文长度和摘要独立于被测实现生成。fixture、真实原生协议、真实模型和部署链路分别记录，不互相外推。
- 在同一硬件与相同当前工作量下增加历史总量：前台请求实际读取/传输的条目与字节、DOM、缓存和正常保存的原生调用量仍受预算约束；不得靠丢正文、截断目录、跳过身份核对或移除故障分支获得通过。
- 联合施加回填、当前执行、目录刷新和阅读，覆盖冷启动、慢客户端、重连、磁盘压力及持续运行；记录首屏、输入响应、保存、事件循环延迟、RSS/堆、WAL 与队列曲线。只测孤立热缓存接口不构成整组通过。
- 从兼容旧库迁移并校验原生绑定、正文与旧操作身份，再备份恢复到新目录。源码恢复点不代替数据库备份；旧二进制不得直接打开已升级 schema，回退使用匹配的旧库副本，核对原生副作用后再开放执行。
- 四项仓库检查通过，受影响地图按[独立执行验收](../features/README.md#独立执行验收)更新并取得真实证据。分别列出未验证与受阻项；上述五项验收通过后才关闭本轮，不以单项成功替代其他结果。

持续使用验收按明确工作量、重复生命周期后的资源保留、压力递增与恢复、故障及存档完整性取得证据，不以固定墙钟时长作为硬门槛；延迟、内存和数据预算不变。长时间耐久测试仅在存在具体时间相关缺陷假设时按需执行。已中断长测保留实际前缀和失败/中断原因，不改标为完整长测通过；短循环也不外推为多年无故障。

## 工程测量与未验证条件

范围和架构方向已确定。本轮在实施前固定了可复跑的[工程测量配置](../../test/support/performance-profile.ts)，用于同条件比较与退出判定，不代表目标实例 SLA。真实目标部署与手机设备的适用性须分别验证；同步吞吐和恢复时限需要结合原生源能力给出测量依据，不能依据最终测量反向放宽阈值。

[P0 基准任务](https://github.com/Lanbasara/zhongshu/issues/24)维护测量依据与原生能力探测；数值以工程测量配置为唯一来源，其余切片共同引用，不各自放宽。

受控入口与进程收束、两端有界历史/状态能力、旧库初始化是需要实现及实验关闭的技术条件，不交给用户猜测协议事实。可继续实现已明确的机制，但在这些条件和量化验收未关闭前，不宣称整组已可上线。
