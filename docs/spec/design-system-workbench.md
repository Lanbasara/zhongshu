# 主界面与设计系统

## Goal

将已认可的原型转译为干净的产品实现，建立与功能解耦、可以持续扩展的视觉与交互体系。

## Users and stories

用户在一致的工作台中切换对话、阅读正文与工具过程、组织文字/图片/引用、发送、停止和恢复；桌面与窄屏保持可用。开发者通过同源组件工作台发现组件及其真实状态。

## Scope / Non-goals

本轮包含完整主界面布局、真实对话输入与状态、导航和阅读区的协调、设计基础及公共组件、Storybook、同仓参考原型及发布隔离。原型是设计参考，不能用其内存数据或模拟执行替换产品行为。保留既有认证、权限、上传限制、持久化、操作身份与恢复契约；不扩展原生能力或发布生产实例。

## Implementation decisions

按完整体验理解设计意图，再以产品职责确定组件边界。功能拥有业务状态，展示模式消费状态与操作，基础组件维护交互与外观。参考原型、stories 与开发构建独立于产品入口；检查依赖来源、静态资源与实际运行产物，错误引入必须使构建失败。正式实现和参考原型分别维护，不形成运行依赖。

## Testing decisions

四项仓库检查、Storybook 构建与状态操作、隔离检查的有效反例、真实应用的对话与恢复路径、窄屏/键盘/减少动效验证。更新相关功能地图并按共同入口取得独立执行证据。fixture 与原生验证分别报告，不将替身成功作为真实 Harness 结论；设计验收比较相同内容下的整体层级、空间与交互。

## Open questions

无待确认的实施范围。真实 Harness 验证需使用操作者提供的隔离现场，缺失前提时如实记录；不得借用生产数据。
