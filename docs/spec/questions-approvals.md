# Agent 提问与审批

## Goal

2026-11-07 用户确认：Agent 的提问在任何权限下都能送到中书并得到回答；审批只在工作区读写和只读时询问，完全访问时全部允许。规则与依据见 [ADR 0016](../adr/0016-questions-and-approvals.md)。用户决定本切片完成后再正式开始日常使用。

Codex 的结构化提问只在 Plan 模式下出现，用户因此决定把它并入下一切片（Plan 模式）一起接入和验证；本切片的提问卡片做成通用组件，供该切片复用。用户已授权实施，本文不表示已经实现。

## Users and stories

1. **提问。** DSH 的主 Agent 发出结构化提问时：
   - 对话显示为等待，正文出现提问卡片；
   - 用户选择或填写后提交，Agent 继续；
   - 在任一设备回答一次即可，其他设备随之显示已回答。
2. **审批。** 工作区读写或只读的对话中，Agent 请求执行命令、修改文件或追加权限时：
   - 出现审批卡片，选项按原生提供的来；
   - 用户拒绝后，Agent 按原生语义继续或结束。
3. **完全访问。** 不出现审批，提问照常。
4. **子 Agent。** Codex 子 Agent 的审批出现在所属对话中，标明来自哪个子 Agent。DSH 子 Agent 不向用户提问，原生会把问题交回主 Agent。
5. **离开与恢复。** 关页、刷新、应用重启或连接中断后，仍未回答的请求保留，回来后可以回答。原生已结束或代次已变化的请求显示失效，不能提交。
6. **MCP 信息请求。** 按原生字段呈现；中书无法呈现的类型，明确拒绝并说明原因。

## Scope / Non-goals

范围：

- 两个 Harness；
- 新建对话的审批策略跟随所选权限；
- DSH 连接改为应答身份；
- 等待中的对话计入“需要处理”和未读；
- 桌面与窄屏。

非目标：

- Plan 模式与 Codex 的结构化提问（下一切片）；
- 推送通知（通知切片，[ADR 0018](../adr/0018-push-notifications.md)）；
- 修改已有对话的权限或审批策略，旧 Codex 对话仍然从不审批；
- 自动审批规则或白名单；
- 打开 Codex 默认模式下开发中的结构化提问开关。

## Implementation decisions

- 回答和审批是带稳定编号的操作，回执未知时去核对，不重发（[ADR 0004](../adr/0004-recoverable-communication.md)）。
- 服务端核实请求属于该对话，必要时还要核实属于它的子 Agent 树；浏览器提供的请求身份不是授权依据（[ADR 0006](../adr/0006-auth-session-data.md)）。
- 请求的内容不写日志。
- 展示组件只接收数据，状态和操作归功能层（[界面与设计系统](../architecture.md#界面与设计系统)）。
- 界面先在 Storybook 做原型，覆盖桌面与手机宽度下的各状态，用户确认后再接功能（[ADR 0008](../adr/0008-storybook-ui-prototypes.md)）。
- 第一步先用真实 Host 探针确认两件事：容器内的 Codex 在工作区权限下，越界操作确实变成审批请求；DSH 改为应答身份后，现有的观察与恢复不退化。结果如推翻已确认的决定，先与用户重新对齐。

## Testing decisions

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| Q01 提问 | 让真实 DSH 主 Agent 发起结构化提问，回答后原生记录的答案与提交一致，Agent 随之继续；不以模型自述为准 |
| Q02 审批按权限 | 工作区读写下，两端各触发一次越界操作：允许时原生执行，拒绝时原生拒绝。完全访问下同样的操作不产生审批，直接执行 |
| Q03 子 Agent | Codex 子 Agent 在工作区权限下请求审批，请求出现在所属对话并标明来源；回答后，原生子 Agent 继续 |
| Q04 多端与恢复 | 两个浏览器同时打开，一端回答后另一端显示已回答，再次提交被拒。刷新、应用重启和原生重连后，未答请求仍可回答，失效请求不可提交 |
| Q05 回执未知 | 在 fixture 中丢失回答的回执，显示待核实；核对时不增加原生提交次数 |
| Q06 安全 | 用其他对话的请求身份回答被拒；缺少认证或 CSRF 被拒 |
| Q07 交付 | 作者在浏览器中自测桌面与窄屏的真实路径；四项仓库检查通过；更新相应功能地图；用户在测试实例完成手机与跨端验收。不做独立执行验收（用户决定） |

## Open questions

- Codex 未答请求的恢复：源码显示，客户端重新接入对话（`thread/resume`）时，App Server 会重发该对话仍未回答的请求，中书重连本来就走这条路，有待真实 Host 证实。App Server 自身重启时，未答请求如何结束、原生终态是什么，需要实测。
- DSH 改为应答身份后，事件流的变化对现有观察和恢复有什么影响。
- DSH 定时提问超时、Agent 已经继续之后，迟到的回答以消息形式送达，界面上如何表达。
