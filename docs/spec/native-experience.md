# 原生工具展示、DSH 默认值与首发技能

## Goal / 来源

依据 2026-11-06 用户的三个体验问题及两项明确选择：采用 DSH 原生空会话保证首发技能体验；分阶段，先处理这三项问题。用户随后调用 implement 授权实施；本工作单尚未完成验收。[ADR 0011](../adr/0011-dsh-prepared-session.md) 保存创建边界的取舍；默认与复位沿用 [ADR 0010](../adr/0010-draft-first-conversation.md)。本工作单承接[原草稿工作单](draft-first-conversation.md)的试用反馈，仅替代与新 ADR 冲突的验收约束，其余要求继续有效。

## 用户路径与范围

- 阅读 Codex 工具过程：Web Search 应区分搜索、打开网页、页内查找，并呈现原生可提供的查询或目标、状态。执行事实与展示能力分开；原生信息不足不能伪造成功或结果。检查其余未适配条目，缺展示时明确表示展示限制，不能误称原生工具不可用。
- DSH 新草稿、切换模型和复位：读取有效的原生默认模型、默认深度及各模型默认深度；默认存在且可用时，不要求无意义的手选。保留原有有效草稿和偏好规则；复位只改模型/深度。缺失、失效或不可用时明确要求选择，不猜值、不静默换权限；新默认不重配已有对话。
- DSH 首发：选定工作区与 Power 后准备原生空会话，在发送前选择该上下文真实可用的技能；首发将选定技能与文字、图片、文件引用一起交接。准备中或失败时保留输入，明确可恢复状态；不得要求先发无意义的开场消息来解锁技能。
- 生命周期按 ADR 0011：首发前配置仍可编辑，正式对话在首发后进入历史；切换后保留草稿，重新核验技能与会话归属，不能携带另一 Power/工作区的标识提交。原生准备、首发与结果待核对须能区分，不以新的会话掩盖未知结果。

不接通审批与用户问答，不实现多 agent / Teams 管理、新 Harness、已有对话配置切换或生产发布。交付需列清仍缺的原生交互与能力验证，不能宣称全功能；本次不承诺把所有原生条目都做成专用 UI。

## 约束与验收

原生执行权与两端差异见 [ADR 0001](../adr/0001-native-harness-boundary.md)，操作身份与未知结果见 [ADR 0004](../adr/0004-recoverable-communication.md)，服务端认证、授权与数据归属见 [ADR 0006](../adr/0006-auth-session-data.md)。当前入口见[创建对话](../features/conversations.md)、[工具与技能](../features/conversation-usability.md)、[恢复](../features/continuity.md)；这些地图描述现状，实施时随行为更新。

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| X01 原生工具展示 | 用真实 Codex 驱动搜索及网页操作，对照原生条目身份、动作和生命周期核对页面，刷新/历史回看一致；既有 webSearch 历史正确呈现。未知条目、运行中、失败或状态不足的分支另有反例，不因收到条目或模型自述便显示成功，不把缺展示归因于原生不可用 |
| X02 DSH 默认值 | 在无有效偏好/历史的草稿中对照真实 Host 目录检查默认模型与深度；切模型、手选深度、复位及切 Power 后选择正确，首发原生实际配置一致。缺默认、不可用默认和目录变化的反例要求明确选择；已有对话与权限不变 |
| X03 首发技能 | 从 DSH 空草稿准备到选技能，发送前原生已有空会话但无用户轮，中书无正式历史项；选定技能以原生调用证据或预先确定的技能独有结果证明生效，不能只看标签或模型自述。首发后原生身份沿用、配置与材料正确、正式对话及首条输入各一份；Codex 首发技能不退化 |
| X04 身份与恢复 | 覆盖准备回执丢失、准备失败、首发回执丢失、刷新/应用重启、切工作区和 Power；独立读取原生身份、输入与产品操作证明不串会话、不重复创建/派发、不丢草稿。重复进入与切换后检查空会话资源确有有界复用/清理，且未伤及正式对话或待核对操作；原生 Host 重启分支单独记录，不能用应用重启代替 |
| X05 交付 | 桌面与窄屏真实路径可操作，材料失败不退化成仅发文字；旧对话接续与受影响的现有路径回归。四项仓库检查通过，更新相应 feature map，并按[共同入口独立执行验收](../features/README.md#独立执行验收)取得证据，用户试用确认 |

真实 Harness 证明协议和输入效果，fixture 适合目录缺失、回执丢失等可控反例，不能互相替代。交付逐项列出 PASS/FAIL/BLOCKED/UNCOVERED，并关联版本、现场和清理证据；历史研究结果不算本次实现验收。
