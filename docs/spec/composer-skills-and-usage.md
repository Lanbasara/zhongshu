# 输入区技能引用与对话用量

在当前[对话](../../CONTEXT.md)中发现可用技能并明确选用，继续写完任务再发送。写下一条消息时，可以顺手查看本对话的累计 Token 与上下文窗口占用。交互以 2026-11-04 用户确认的 Tab 选中规则和认可的 [Storybook「技能与对话用量」「只有累计用量」](../features/interface.md#driving-it-with-harness) 为准。

## 用户行为

| 场景 | 可观察结果 |
| --- | --- |
| 输入 `/` 并筛选 | 输入框上方列出当前对话可供用户调用的技能及简述。继续输入 `/zhi` 等关键词，候选即时缩小，默认高亮第一项。普通路径或 URL 保留为文本。 |
| 确认技能 | ↑↓ 切换高亮，Tab 确认高亮项，点击或触屏点按同样可选。当前斜杠词替换为带图标和强调色的行内引用，光标留在其后，可以继续输入。Escape 收起列表并保留输入；无匹配时 Tab 沿用常规焦点导航。 |
| 发送消息 | 从列表选中后，由当前 Harness 按原生方式调用选中的技能。手打完整 `/技能名` 后直接发送，文本保留原样，由 Harness 自己解释。Enter 换行、⌘/Ctrl+Enter 发送及现有草稿与操作恢复规则继续适用。 |
| 查看对话用量 | 输入框下方以低调的一行展示累计 Token，以及带细圆环的上下文占用百分比。点开同一个浮层可见精确累计值及已用量 / 窗口容量。累计量反映整段对话的原生用量，上下文占用可随压缩下降，原生估算值以「约」标明。窗口容量缺失时保留可确认的累计值，详情显示上下文暂无数据。 |

## 边界

技能可用性、调用和用量以当前对话绑定的 Harness 为准。实例已安装的插件只说明安装状态。服务端按当前绑定核对选中的技能，浏览器不指定原生文件路径。草稿恢复、排队和重试必须保留已选技能的身份；技能失效或派发路径不能保留引用时，明确反馈并保留内容。沿用[原生边界](../adr/0001-native-harness-boundary.md)、[插件范围](../adr/0009-instance-plugin-scope.md)与[恢复契约](../adr/0004-recoverable-communication.md)。

首版用量详情只有累计量与上下文占用。缓存命中、轮次、吞吐和上下文构成明细留在本切片之外。

## 验收

- 桌面从 `/zhi` 开始，切换高亮、Tab 插入并继续写。窄屏用点按走同一路径。覆盖 Escape、无匹配和手打完整名称，检查焦点、草稿与发送行为。
- 在 Codex 与 DSH 各用一项合成技能走产品发送路径，查原生接收及技能加载证据。切到技能不可用的对话，确认列表不串；验证已选技能失效时能修正草稿。对可用的排队和恢复分支，核对派发内容与原操作身份。
- 在两端完成真实模型请求，独立读回原生用量并与界面核对。覆盖刷新、切换对话、窗口容量缺失和上下文下降，确认累计值与占用各自正确。按[独立执行验收](../features/README.md#独立执行验收)保存证据并更新产品功能地图。

待实测的接入点是两端对技能调用的原生证据，以及恢复对话后用量与窗口容量的读回。Storybook 证据覆盖交互与布局。
