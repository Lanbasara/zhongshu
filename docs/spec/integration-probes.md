# 会改变架构的接入实验

## Goal

在对应功能切片开始前，用最小实验回答会改变实现或产品承诺的问题；每项只回答一个问题，保留版本、环境、复现和反例。

## Probes

### 对话基本可用性

在[对话基本可用性](conversation-usability.md)实现时核实以下技术前提，实际通道与资源归属见 [architecture](../architecture.md#消息与资源)；用户行为、范围与验收只在该 spec 维护：

- 两端分别用合成图片证明真实图片输入；对具备原生生成能力的路径，核实返回资源的形态、读取权限、寿命及重启后可用性，不能以模型自述或仅有原生条目类型判成功。
- 在不挂载中书认证数据、不扩大既有 Host 边界的条件下，证明上传资源能到达 Host、生成资源能被应用读取、当前工作区原文件能被引用。核对路径映射、越界/符号链接拒绝、失效引用、资源归属与回收；缺少通道时明确受阻。
- 验证 UI 组件和流式 Markdown 能由现有操作/历史状态驱动，覆盖同编号重试、延迟回执、恢复、旧纯文本记录及窄屏长内容。确认依赖和适配成本后再落实选型；不为复用示例改成另一套 Agent loop 或丢弃既有恢复语义。

### 两个 Harness

- 启动、原生身份、读写执行、观察连接、重连与停止，先按首条曳光弹验证。
- 在追加/提问/审批切片前，再验证运行末尾追加、审批等待时断线、两端回答竞争、请求失效与原生配置继承。
- 能力表标明固定版本、可用、限制和未验证；身份与文件权限遵循 ADR 0001。

### 文件保存

- 测试两个浏览器从同一旧版本保存，以及独立进程在版本检查与文件替换之间直接写入。
- 覆盖删除、替换、重命名及路径/符号链接变化。
- 仅比较 hash/mtime 或使用 `fs.watch`、应用内互斥不足以覆盖独立写入者。
- 原子 rename 不会把此前读取/比较变成条件事务；flock 是建议锁，不约束不参与的写入者。
- 先评估统一写入协议或独占写入窗口；若与原生工具冲突，明确“何时允许原地保存、何时保留修改并另存/合并”。

### HTML 阅读

- 使用真实报告覆盖版式、长文、宽表、图形、目录、折叠、相对底稿、外链与返回位置。
- 先测试无报告脚本的阅读路径；脚本需求由实际样本确认。
- 内容隔离与导航一起验证：报告不能取得应用身份或访问管理接口；允许脚本时另定来源和受限资源通道。
- 完成条件是明确支持范围，并通过桌面/手机真实阅读及隔离反例。

## Out of scope

- 性能与内容样本的统一测量归 [features/README](../features/README.md) 的跨功能验收；本 spec 不复制。
- 具体代理与 Tunnel 配置属于部署实例，不进入产品源码。

## Open questions

- 文件保存是否需要产品级独占写入协议，还是接受“检测冲突、保留修改、另存/合并”？
- HTML 报告是否允许脚本；若允许，隔离边界是什么？
