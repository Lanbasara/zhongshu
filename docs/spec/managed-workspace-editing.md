# 受管工作区编辑

属于[上线前联合规格](long-term-performance.md)。沿用[工作区文件阅读与编辑](workspace-file-reading-editing.md)的格式、稿件及条件保存范围；执行协调和原生能力前提唯一归 [ADR 0011](../adr/0011-managed-workspace-execution.md)。本次将 Codex 与 DSH 纳入相同的编辑窗口语义，扩展既有 DSH 维护方式。

## 用户路径与行为

| 动作或故障 | 可观察结果 |
| --- | --- |
| 打开文件并申请编辑 | 立即反馈准备状态与实际影响范围；关闭相关新增工作受理，既有已受理集合按协议排空；只核对当前未决工作，不恢复所有已结束对话 |
| 已有任务运行、等待或回执未知 | 保留阅读和处理入口，等待或核实；不因申请编辑自动取消已受理任务，也不把超时当成空闲 |
| 取得编辑窗口 | 控制器已确认写入能力收束；在窗口内可多次保存，版本冲突保留稿件 |
| 另一页面或客户端发送 | 服务端统一入口阻止与窗口冲突的新派发，不能绕过门禁；已排队条目不得在编辑期间悄悄启动 |
| 退出编辑或恢复 Agent | 等待在途保存完成，恢复原 Host 数据及绑定，核实新代次后再开放执行 |
| 页面关闭、应用/Host/控制器中断 | 稿件按既有浏览器生命周期处理；服务端门禁不因页面消失解除，未知结果保持待核实并提供恢复入口 |

## 验收

- 同一工作区分别准备 40、1,000 段有已完成历史的对话，保留相同的当前未决集合；两个 Harness 均完成进入编辑、保存和读回。核对最终磁盘字节，并从调用记录证明正常路径没有逐个恢复已结束对话，也不依赖同时保留全部观察订阅。
- 覆盖已受理未派发、回执丢失、原生排队、提前发送、等待输入、自动附带工作及终态迟到；在门禁前后用第二客户端制造交错。既有任务身份保留并可在收束阶段排空，不能因门禁造成自锁；新增工作及可编辑阶段的冲突派发被服务端拒绝，同编号未知操作不重派。
- 在父子工作区及同组多个工作区验证实际影响范围；用可控后台写入进程区分原生 idle 与副作用收束。允许保存后尝试释放旧写入者，人工内容不得被覆盖；不能只观察 Host 主 PID。
- 两页保存同一旧版本，只允许先满足条件者成功；并发恢复与保存、目录身份替换、旧代次控制请求均有确定结果。分别中断应用、Host 和控制器，再从新页面恢复，不能自动重新开放门禁。
- 迁移既有 idle 记录时先建核对基线；初始化中断可续传，未完成范围不开放编辑，历史阅读仍可用。相关驱动从[文件功能地图](../features/workspace-files.md)扩展，并遵循联合规格的性能预算与独立验收。

## 实施条件

实施顺序：[P1 真实单组编辑路径](https://github.com/Lanbasara/zhongshu/issues/25)先穿过控制器、存储、页面与原生恢复；存储契约稳定后由 [P7](https://github.com/Lanbasara/zhongshu/issues/31)推广到多组、相交目录和旧实例初始化。详细依赖与集成归联合计划。

两个 Harness 的控制器和统一入口必须实际证明上述能力；不可用不能以缓存 idle 替代。首次旧库核对与正常保存分别测量，数值预算和全部退出条件归联合规格。
