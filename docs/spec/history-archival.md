# 后台阅读存档

属于[上线前联合规格](long-term-performance.md)。存档含义、来源、完整性和容量策略唯一归 [ADR 0010](../adr/0010-durable-reading-archive.md)，不改变 [ADR 0004](../adr/0004-recoverable-communication.md) 的未知操作恢复约定。

## 用户路径与行为

| 场景 | 可观察结果 |
| --- | --- |
| 从未翻阅旧历史或关闭全部页面 | 服务端仍公平推进全部已绑定对话的可获取正文，视图归档不停止存档 |
| 打开未追平的对话 | 立即读取已有存档，显示最新成功同步、覆盖范围和补齐/暂停/缺口；不等待全部历史下载 |
| 新轮流式输出并结束 | 运行状态与存档状态分别更新，终态后补读最终正文，不能将最后一个增量当成完整回复 |
| 原生压缩、重启或游标失效 | 已有原文保持可读，沿有效进度继续或重新寻锚；已无法获取的范围明确标为缺口 |
| 中书中断或磁盘不足 | 保留最后成功提交和当前失败原因，恢复后继续；不重派用户操作，不清空已存正文 |

## 验收

- 制造已有本地正文之后新增 2,001、20,000 条历史，以及大量从未打开的对话；关闭页面，独立读回原始集合与逐条正文摘要，验证后台达到所声明截止范围，记录公平推进与资源预算。
- 在页读取后、正文块暂存中、提交前和提交后分别强杀应用，重复恢复。无静默缺口、重复条目、悬空正文引用、旧版本覆盖终态；已提交页不因后续失败全部回退。
- 两个真实 Harness 分别保留旧游标，追加新轮、断线、重启、执行实际上下文压缩并再重启；核对来源身份、边界和全部原文。另使游标失效或原生记录缺失，验证重建与缺口表达，不把成功路径当成永久游标保证。
- 流式阶段已收到增量而历史页尚无最终回复时，不能显示该轮已完整存档；完成后重读并逐字核对最终正文。重复和晚到读取不能覆盖更高代次或更新版本。
- 构造原生列表漏项、同时间戳对话、同 ID 正文更新及一个持续失败对话；绑定清单内对话不能丢失，其余任务继续推进。保持工作区停用/视图归档前后的授权边界；交错释放最新同步与旧页回填，旧来源不得覆盖新正文。
- 本地正文仍可读时断开 Harness；分别观察执行状态失效与存档保留。只让正文同步失败时，有效执行证明不被错误改成未知。完成后扩展[接续地图](../features/continuity.md)。

## 实施条件

实施顺序：[P3](https://github.com/Lanbasara/zhongshu/issues/27)先贯通单段真实长对话的分块、续传和完整读回，再由 [P4](https://github.com/Lanbasara/zhongshu/issues/28)扩展到所有绑定及公平调度。详细契约与依赖归联合计划。

旧库已加载标志不能直接迁移为完整覆盖。原生 API、分块持久化与故障现场必须真实可驱动；数值预算、备份恢复及联合运行归联合规格和[容量规格](storage-longevity.md)。
