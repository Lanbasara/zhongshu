# 原生子 Agent 的查看与停止

## 目标与依据

2026-11-06 用户确认：中书作为常驻工作台，对话中的主 Agent 自行派生子 Agent。中书让用户看见这些子 Agent，并能单独停止；中书不派生子 Agent，不给它派活，也不向它发消息。用户随后认可了 Storybook「原型 / 原生子 Agent」中的界面，原型的提示文字和状态表现是本工作单的界面依据。

长期取舍与被放弃的方案见 [ADR 0013](../adr/0013-native-subagent-observation.md)；原生执行边界见 [ADR 0001](../adr/0001-native-harness-boundary.md)，操作与未知回执见 [ADR 0004](../adr/0004-recoverable-communication.md)，认证与数据边界见 [ADR 0006](../adr/0006-auth-session-data.md)，观察生命周期见 [ADR 0012](../adr/0012-conversation-lifecycle.md)。术语见 [CONTEXT](../../CONTEXT.md)。本文是目标，不表示已经实现。

## 用户路径

1. **入口**：对话出现子 Agent 后，头部显示「子 Agent」按钮，按状态依次显示运行中数量、待核实数量、总数和结果提示；没有子 Agent 的对话不显示。
2. **正文卡片**：主 Agent 派生、等待、停止子 Agent，或子 Agent 完成时，正文出现简短卡片。
   - 卡片显示子 Agent 当前的状态，不是派生那一刻的状态。
   - 超过 3 个时折叠，可以展开。
   - 点一行即打开该子 Agent。
   - 子 Agent 的过程不写进主正文。
3. **面板**：
   - 桌面在阅读区位置打开，窄屏为整页。
   - 名单分为运行中、待核实、未运行三组。
   - 每行显示名称、任务、由谁派出（嵌套时）、是否外部执行、状态和时间。
   - 运行中的行有「停止」文字按钮。
4. **子 Agent 过程**：只读，没有输入框。
   - 先显示派生方交代的任务，不显示成用户的消息。
   - 之后的正文与工具展示沿用主对话。
   - 外部执行的子 Agent 只说明「只回传最终结果」；原生过程读不到时，明确说明原因。
   - 选中文字可引用到主对话的输入框。
5. **停止子 Agent**：按下后依次显示「正在停止…」和「已停止」，主 Agent 和其他子 Agent 不受影响。回执未知时显示「停止待核实」，可查询原生结果，不重复提交。停止不承诺工具进程退出或副作用撤销。
6. **停止主 Agent**：只停主 Agent 的当前轮。仍有子 Agent 运行时，提示数量并给出查看入口；DSH 另外说明，子 Agent 完成后可能自动继续主 Agent。
7. **后台与结果**：
   - 主 Agent 不在运行而子 Agent 仍在运行时，侧栏对话行显示「N 个子 Agent 运行中」。
   - Codex 子 Agent 在主 Agent 那一轮结束后才完成、且主 Agent 尚未开始新一轮时，提示「主 Agent 要到下一轮才会读到它们的结果」。
   - 提示中的「填入」按钮只填写输入框，不自动发送。
8. **DSH 团队**：Host 开启团队时，面板多一个「团队」标签。
   - 成员中，主 Agent 标为「本对话」，其余成员可点开查看过程。
   - 共享任务显示标题、状态、负责人、写入范围，可以展开。
   - 全部只读。
9. **无法核实**：原生连接中断或状态未知时，头部、正文卡片、侧栏和面板都显示待核实，不提供停止；面板说明这是最后已知状态，并提供重新核对。

## 范围与非目标

范围：

- 两端原生名单中的全部子 Agent，包括嵌套子 Agent、DSH 团队成员、DSH 工作流派生的子 Agent，以及外部执行的子 Agent（只有结果）。
- Codex v1 与 v2 的差异。
- 刷新、应用重启和原生重连后的恢复。
- 桌面与窄屏。

非目标：

- 由中书派生子 Agent，或在多段对话之间派活。
- 向子 Agent 发消息。
- 停止整棵子树。
- 删除单个子 Agent、解散团队、编辑团队任务。
- 子 Agent 的审批与提问：由审批切片一并处理，本次保持不请求审批的策略。
- 在中书内开启 DSH 团队或 Codex 开发中的特性。
- 把子 Agent 过程存入中书或离线阅读。
- 子 Agent 用量汇总、后台任务管理、通用的对话概况面板。
- 原生版本升级。

## 实施约束

- **共同语义**：
  - Harness 接入新增四项能力：列出子 Agent、分页读取子 Agent 过程、在租约内观察子 Agent、停止子 Agent；DSH 另外提供团队快照。
  - 两端差异用能力和结果表达，页面不依赖原生字段。
- **Codex**：
  - 接住带子 Agent 身份的事件，并归入所属对话。
  - 结合原生的后代查询、主 Agent 历史中的协作条目和状态变化来发现子 Agent。
  - 重连后核对并重新订阅仍在运行的子 Agent。
  - 主 Agent 仍有执行责任时，不释放对子 Agent 的观察。
- **DSH**：
  - 从主会话快照与投影读取子 Agent 名单、计时和团队。
  - 需要实时或历史时，按子 Agent 地址单独跟随。
  - 停止使用面向子 Agent 的原生中断。
  - 中书当前的连接不接收应答类事件，运行状态的来源要在实现中核实。
- **中书服务**：
  - 持久化子 Agent 索引，并通过现有变更流提示页面重新读取。
  - 停止是带稳定编号的操作。
  - 读取和停止前，核实子 Agent 属于该对话。
  - 对话的归档、删除条件计入运行中的子 Agent。
- **界面**：产品组件沿用原型的展示组件和设计系统，展示层不持有业务状态；状态示例保留在 Storybook。

## 实测结论（2026-11-06）

固定版本的真实 Host 已实测，结论与对行为的影响如下；原始记录在操作者实验目录。

| 问题 | 实测结论 | 对行为的影响 |
| --- | --- | --- |
| DSH 主 Agent 被停止后，子 Agent 完成时是否开启主 Agent 新一轮 | 是。停止单个子 Agent 也会向主 Agent 发送停止结果，空闲的主 Agent 随即开始新一轮 | 第 6 条提示保留；停止 DSH 子 Agent 后面板说明主 Agent 会因此自动开始新一轮 |
| Codex 主 Agent 卸载或释放观察后，子 Agent 是否继续 | 子 Agent 继续运行；无订阅的主 Agent 约 60 秒后卸载，**已交回但未读的结果随之丢失**；v1 子 Agent 无订阅空闲 60 秒后被关闭 | 子 Agent 不被中书解除订阅；结果待处理时继续观察主 Agent（不阻止归档） |
| 中书停止 Codex 子 Agent 后，主 Agent 历史中出现什么 | 什么都不出现，主 Agent 不会得知；它可能继续等待，或另行给该子 Agent 新任务。Codex 停止不终止工具进程，DSH 停止会终止 | 停止只承诺子 Agent 当前轮中断；工具进程与主 Agent 的后续反应如实说明 |
| 实际账号模型的多 Agent 机制版本 | 可见模型多数为 v2，GPT-5.6-Luna 为 v1 | v2 子 Agent 的任务说明不在公开协议中，Codex 不显示「交代的任务」，任务名取 agent path |
| 第 7 条「下一轮才读到」的依据 | 主 Agent 历史中的子 Agent 完成记录晚于其最近一轮结束、且之后没有新一轮；仅在主 Agent 保持加载时成立 | 提示只陈述该时间关系；配合上一条持续观察 |
| DSH 中书当前连接能否取得子 Agent 运行状态 | 能：按 subagent 地址跟随子会话的回合边界与计时投影 | 状态取自子会话快照 |
| 团队工具与子 Agent 控制工具是否冲突 | 团队版替换发消息、列出与中断工具，`subagent` 与 `subagent_fork` 仍在；只读展示不受影响 | 团队按只读展示；团队成员同时出现在子 Agent 名单 |

仍未实测：v2 交互/中断记录的完整形状、嵌套子 Agent、Codex Host 重启、外部执行与工作流子 Agent。DSH Host 重启已在独立验收中实测：断连期间各处显示待核实，重启后从原生重新核实，被重启中断的子 Agent 显示已停止。

独立验收另发现（已按此实现）：主 Agent 正在执行自己的工具时，DSH 子 Agent 的消息与完成通知先进入主 Agent 收件箱（`agent/inbox/spliced`），正文要到主 Agent 当前一步结束才记录；名单以收件箱到达为准重新核实。

## 验收

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| N01 看见 | 两端真实 Host 让主 Agent 派生至少两个子 Agent，与原生名单逐个核对数量、身份、父子关系和状态；子 Agent 过程与原生历史逐条对应，派生输入不显示为用户消息；没有子 Agent 的对话不显示入口 |
| N02 恢复与待核实 | 子 Agent 运行中刷新页面、重启应用、断开原生连接，名单和状态从原生重新核实；不漏掉仍在运行的子 Agent。连接中断期间，各处显示待核实且不能停止，不显示为运行中 |
| N03 停止子 Agent | 让子 Agent 执行可从外部观察的长任务后停止：原生终态为中断，主 Agent 与其他子 Agent 不受影响；另行记录工具进程是否存活。fixture 中回执丢失时显示停止待核实，查询不增加原生提交次数 |
| N04 停止主 Agent | 子 Agent 运行中停止主 Agent，提示的数量与原生一致；DSH 记录子 Agent 完成后主 Agent 是否被唤醒，并与提示文字相符 |
| N05 后台与结果 | 侧栏标记随子 Agent 状态出现和消失；Codex 结果提示只在第 7 条条件成立时出现，「填入」不产生原生提交 |
| N06 团队 | 测试 Host 开启团队，成员与共享任务与原生团队投影一致，点成员打开对应子 Agent；没有任何写操作 |
| N07 归属与安全 | 用其他对话的子 Agent 身份读取或停止被拒绝，缺少认证或 CSRF 被拒绝；两端各一次 |
| N08 生命周期 | 有运行中子 Agent 时，Codex 删除和两端归档的条件生效；Codex 删除后原生子树不存在，归档后子 Agent 已停止，原历史仍可阅读 |
| N09 交付 | 桌面与窄屏的真实路径可操作；四项仓库检查通过；更新相应功能地图，并按[共同入口的独立执行验收](../features/README.md#独立执行验收)取得证据；用户试用确认 |

真实 Harness 证明协议和原生行为；fixture 只用于回执丢失、连接中断等可控反例，二者不能互相替代。交付逐项列出 PASS / FAIL / BLOCKED / UNCOVERED，并附版本、现场和清理证据。
