# Plan 模式

## Goal

依据 [ADR 0016](../adr/0016-questions-and-approvals.md)，两端都提供 Plan 模式：在输入区开关，Agent 先规划，计划交给用户审核后再执行。Codex 的结构化提问只在 Plan 模式下出现，用户已决定在本切片接入并验证。2026-11-07 用户决定所有收尾切片完成后再更新服务器。界面先在 Storybook 做原型，用户确认后再接功能；不做独立执行验收，用户在测试实例验收。本文不表示已经实现。

在固定版本上核实的原生事实：

- Codex 的 Plan 是对话设置，切换后保持到切回默认。官方客户端每轮都显式发送模式；Plan 下产生一个单独的计划条目，本轮结束后询问是否按计划执行，执行即切回默认并发送一句执行指令。
- Codex 的结构化提问每次 1–3 题，每题单选，另有“以上都不是”和补充说明；不回答时这一轮一直等待。
- DSH 用原生命令进入和退出 Plan，状态在各端一致并在重启后保留；计划审核是一次提问，批准后原生退出 Plan 并在同一轮继续执行。
- 两端的 Plan 都只是提示 Agent 先规划，不限制工具；限制仍靠权限和审批。

## Users and stories

1. **开关。** 输入区有 Plan 开关，开着时说明“Agent 先规划，计划交你审核后再执行；Plan 不限制 Agent 的工具”。一轮运行中不能切换。各设备看到同一个状态。
2. **Codex 规划。** 开着时每轮以 Plan 运行。计划在对话中显示为单独的计划块。本轮结束、且之后没有新消息时，输入区上方出现“计划已就绪”：选“按计划执行”就关闭 Plan，并发送一句执行指令开始默认模式的一轮；选“继续规划”则保持 Plan，由用户写下意见。
3. **Codex 提问。** Plan 中的结构化提问用提问卡片作答：单选一个选项，或选“以上都不是”并补充说明。回答一次有效，各设备同步。
4. **DSH 规划。** 打开开关会让原生进入 Plan。Agent 交出计划时，卡片显示计划正文，可以选“批准并执行”或“继续规划”（可附意见）。批准后原生退出 Plan、继续执行，开关随之关闭。
5. **关闭。** Codex 的下一轮回到默认模式；DSH 让原生退出 Plan。

## Scope / Non-goals

范围：两个 Harness；Codex 结构化提问；计划块与计划审核；桌面与窄屏。

非目标：

- Codex 的“清空上下文后执行”（另开线程）；
- 把 Plan 做成只读的强制限制；
- Plan 轮改用别的模型或思考深度（沿用对话的固定配置）；
- Codex 默认模式下的结构化提问。

## Implementation decisions

- Codex 的开关保存在中书的对话记录里，每轮显式发送模式（沿用对话的模型和深度，开发者指令用原生默认）。DSH 以原生的 Plan 状态为准，切换只执行原生命令。
- 计划审核和提问复用 [提问与审批](../features/execution.md#e08e10-提问与审批) 的卡片与回答操作；“计划已就绪”由中书根据原生计划条目和本轮终态得出，不是原生请求。
- 展示组件只接收数据，状态和操作归功能层。

## Testing decisions

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| P01 Codex 规划往返 | 打开 Plan 发送任务：原生本轮为 Plan、出现计划块；就绪卡片出现；按计划执行后原生下一轮为默认模式并开始执行，开关已关 |
| P02 Codex 提问 | Plan 中触发结构化提问：选项与原生一致；选一项或“以上都不是”加说明，原生收到的答案格式与官方客户端一致，Agent 继续 |
| P03 DSH 规划往返 | 打开开关后原生 Plan 为开启；计划审核卡片显示原生计划；继续规划附意见后 Agent 重写；批准后原生退出 Plan 并继续执行 |
| P04 一致与限制 | 两个浏览器上下文看到相同的开关状态；运行中开关不可切换；关闭后两端的下一轮不在 Plan |
