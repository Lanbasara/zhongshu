# 实例级插件管理

依据 2026-11-04 的范围对齐。管理员在中书自己的「插件管理」页面发现和管理原生插件。Codex 和 DSH 各有入口、来源、安装记录和状态。同名插件可以分别安装和管理。所有变更使用[插件的全局范围](../../CONTEXT.md)，由所选 Harness 负责原生安装和生效。

| 用户动作 | 可观察结果 |
| --- | --- |
| 添加或移除市场来源 | 管理员从中书独立添加 Codex GitHub 市场或 DSH 公开索引。目录、来源和发行信息按所选 Harness 展示。 |
| 选择 Codex 或 DSH，搜索插件或打开已安装列表 | 看到该 Harness 的目录和安装状态。条目可辨认来源与目标环境，已安装项展示原生可核实的版本和启用状态。 |
| 从发现页安装 | 确认前可见来源、目标 Harness 与实例范围。中书直接在目标原生环境执行安装，成功后可从已安装列表读回。打开中书的设备无需预先安装。 |
| 停用、重新启用或卸载 | 状态反映所选 Harness 的结果。停用保留已安装的包，卸载只作用于当前条目的原生安装。刷新或换设备访问同一中书实例时，看到实际状态。 |

当原生报告已安装但尚未应用、需要重启或加载失败时，界面区分这些结果。失联或回执不确定时显示待核实，读回原生状态后才能确认结果。安装插件本身不代表关联服务已授权。

插件操作经中书服务端认证和授权，受[原生执行边界](../adr/0001-native-harness-boundary.md)约束。只能执行可确认局限在目标实例的操作。账号级安装、启停或卸载即使出现在目录里，也不能从本实例发起。同一账号的另一环境以及同一中书实例的另一个 Harness 均不受影响。

本切片管理插件及其随包能力的安装状态。工作区目录安装、独立 Skill 的管理和项目级启停不在本切片。对话内的能力查询与调用单独设计，届时按当前工作区和 Harness 查询实际可用能力，覆盖项目已有能力和实例共享能力。调用语法待定。

## 验收

- 用中书页面从零添加两个见微原生市场，并在 Storybook 中复跑添加、目录、详情与管理交互。实际安装后独立读回版本，移除来源前确认对应插件的处理提示。

- 在隔离的目标部署环境用浏览器分别搜索并安装知行的两个原生发行包。每端独立核对实际安装位置、版本及原生加载结果。DSH 以 `0.2.1-rc.5` 做一次真实安装与原生调用验证。原生调用用于验收插件生效。
- 在两端分别停用、启用、卸载并刷新页面，核对原生状态和界面。停用后包仍在，卸载后目标安装消失。先只装一端，证明同名插件的另一端未出现，再验证对其中一端的管理不改变另一端。对待生效或结果待核实的情况，界面须能区分与已生效的结果。
- 对照变更前后，核对工作区文件和使用同一账号的独立环境的插件状态。用会写入账号的来源验证服务端拒绝变更，覆盖直接请求。验收完成后按[独立执行验收](../features/README.md#独立执行验收)留证并更新功能地图。
