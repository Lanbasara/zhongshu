# 原生历史读取与存储边界

## 目标与依据

落实 [ADR 0014](../adr/0014-native-history-source.md)：对话历史以原生 Harness 为唯一来源，中书不保存正文副本，也不要求本地历史连续。用户于 2026-11-06 确认的要求如下：
- 产品要长期使用。对话无论多长、中间断开多久，都不能卡死；可以像官方客户端一样一直往上翻。
- 原生不可用时显示“暂时不可用”，不提供离线阅读旧历史。
- 中书存储设预算。达到上限只停会增加存储的动作，并提示清理。
- 原生存储不作为拦截条件，本轮也不显示原生用量。
- 旧正文投影保留到验证通过后再删。
- 模型上下文压缩交给 Harness，不进入本工作单。

本文是目标与验收约定，不代表已经实现。当前行为以[功能地图](../features/README.md)为准。原生执行与观察边界见 [ADR 0001](../adr/0001-native-harness-boundary.md)、[ADR 0012](../adr/0012-conversation-lifecycle.md)，操作、回执与旧响应防覆盖见 [ADR 0004](../adr/0004-recoverable-communication.md)，均继续有效。

## 用户路径

| 编号 | 用户做什么 | 应该看到什么 |
| --- | --- | --- |
| H01 | 打开任意长度的对话 | 首屏就是最新内容，可以继续发送；打开不需要先补齐历史 |
| H02 | 一直往上翻 | 逐页加载更早内容，直到第一条；翻得很远也不变卡，阅读位置不跳；可以一步回到最新；不在底部时，新输出提示“有新内容” |
| H03 | 中书停机或断线期间，原生产生了大量新内容，之后重新打开 | 直接看到最新内容，不出现因历史缺口导致的待核实；往上翻能连续读到停机前的内容 |
| H04 | 原生暂时不可用 | 已加载的内容保留；需要读取原生的翻页或打开显示“原生暂时不可用”；不能发送；恢复后沿原身份继续，不重复、不错位 |
| H05 | 存储接近或达到预算 | 接近时提醒。达到后上传图片、新建对话被拒绝，并说明原因、给出清理入口；阅读、在已有对话里发文字、停止、归档、删除照常；清理后立刻恢复 |
| H06 | 查看存储 | 看到中书已用多少、预算多少，以及各类别占多少；原生用量本轮不显示 |

## 范围与非目标

范围：两种 Harness 主对话历史的读取、实时更新合并、浏览器连续回溯、停止持久保存正文（包括流式中的条目与工具输出）、读取时的批注叠加、图片缓存、存储预算与清理入口、中书用量显示、旧投影的迁移与受控删除。

非目标：
- 压缩标记或手动压缩。
- 原生用量显示：DSH 没有官方用量接口，用户决定本轮不做。
- 跨对话正文全文搜索、跳到指定轮次。
- 离线阅读。
- 修改 DSH Host、删除 DSH 原生数据。
- 子 Agent 过程阅读（已经直接读原生）只复用共同机制，不改行为。

## 行为约定

1. **正文只来自原生。** 每一页都经 adapter 读取原生分页；中书数据库不写入任何正文副本。
   - 例：删除旧投影后，所有历史仍完整可读。
   - 例：重启中书后，看到的正文来自原生的当前视图。
   - 例：原生改写了历史（压缩替换、回退），页面以原生为准。
2. **没有补齐预算，也没有单对话条数上限。** 打开只读最新一页，更早的按需读取。
   - 例：停机期间新增 5,000 条，打开后首屏即最新；状态只由原生执行事实决定。
   - 反例：仍然因为“读不到交点”而显示待核实或禁止发送。
3. **游标。** 原生游标由服务端绑定到对话身份，浏览器只拿到不透明值。跨对话或伪造的游标会被拒绝。原生游标失效或原生报告索引异常时，明确提示，并从最新页重建；不能把它当成“没有更早内容”，也不能显示重复或错位的条目。
4. **浏览器窗口有界。** 向上可以持续翻页。离视口远的页面可以丢弃，之后重取；加载更早内容时阅读锚点保持不动；回到最新和“有新内容”提示保留。
5. **实时与恢复。** 流式条目只在内存中合并。断线、SSE 断档或重启后，以原生最新页重建。旧响应不能覆盖新状态（现有 R05 的保护继续有效）。
6. **读取不唤醒原生。** 翻页和冷读历史不加载、不唤醒原生会话；实时观察仍由执行责任和阅读租约持有（ADR 0012）。
7. **批注叠加，看到的内容不变。** 以下内容在读取时按原生身份或操作身份叠加：用户原始输入（文字、图片、引用、技能）、图片资源、本轮文件、回执归属。现有正文、工具组、图片、引用、本轮文件、用量等行为（[U01–U13](../features/conversation-usability.md)）只是读取来源变了，用户看到的结果相同。
8. **安全校验不放宽。** 工作区图片仍只允许正文中实际出现的路径；消息引用仍必须指向本对话的真实条目。校验依据改为原生条目。
9. **存储预算。**
   - 实例可配置，默认 16 GiB；用到 80% 时提醒。
   - 计入中书数据库；迁移期内的旧投影不计入。
   - 达到上限时，服务端拒绝上传图片和新建对话，其余动作不受影响。
   - 清理手段：删除 Codex 对话、清理可再生的图片缓存（能从原生或工作区重新取回的副本）。清理后立即生效。
   - 已经没有可清理的内容时，提示明确说明这一点，并告诉用户可以在实例配置里调高预算；不另加新的清理功能。
   - 现有的图片总额限制并入这个总预算。
10. **原生存储不拦截，本轮不显示原生用量。**
11. **迁移。** 新版本不再读写旧投影，旧数据保留。用户在自己的实例上验证通过并确认后，才执行删除旧投影、释放空间的迁移；这一步是本工作单的最后一项。

## 需要在实现中核实的技术点

这些属于工程问题，靠源码、协议和真实 Host 实验解决，不需要用户再做决定。结论影响实现方式，不改变上面的承诺。

- **DSH 最新页**：翻页接口不唤醒 Agent，但要求提供最新序号；需要找到不经 `follow` 拿到最新页的方式。
- **DSH 页大小**：按字节预算和按轮读取，避免超过 8 MiB 的消息上限；当前每次读取都经 `follow`，会唤醒 Agent。
- **Codex 页大小**：读取历史不经 `resume`；条目带内联图片字节，需要按字节控制页大小；索引停滞和旧格式线程要给出明确错误。
- **本轮文件**：一轮跨多页、不保存正文时，清单仍要完整。
- **回执认领**：发送回执的 run 认领不能再依赖本地投影。
- **用户图片**：已被原生接收的上传图片能否从原生取回，决定它属于可再生缓存，还是中书自有数据。
- **用量口径**：中书预算按 SQLite 文件（含 WAL）还是逻辑大小计算，提醒和拒绝都要用同一口径。

## 验收

按[共同验证入口](../features/README.md)建立隔离现场，不操作个人实例。

- **fixture**：扩展到超长原生历史（例如 10 万条）和停机缺口（应用停止时新增数千条），以及游标失效、原生不可用、极小存储预算。
- **真实 Codex 与 DSH**：各用一段中等长度的真实对话，跑 H01–H05 的适用分支。对话有几百条、至少能翻 3 页，包含工具调用和图片；超长和大缺口只用 fixture 验证。
- **旧数据迁移**：用真实数据库的副本做，不在个人实例上执行。

| 编号 | 证伪点 |
| --- | --- |
| H01/H03 | 首屏最新、可发送；停机缺口后不出现历史原因的待核实；中书数据库中找不到正文 |
| H02 | 从最新页连续翻到第一条，不重复、不漏项、不错位；DOM 与浏览器内存有界；丢弃后再取一致 |
| H04 | 原生下线时，已加载内容保留、不能发送；恢复后身份不变、不重复派发 |
| H05 | 上传和新建被服务端拒绝（伪造请求也一样），其余动作正常；清理后立即恢复 |
| 回归 | 现有发送、排队、停止、恢复、子 Agent、删除、归档相关场景按各自地图复验 |
| 性能 | 记录打开和翻页的延迟、每页字节、原生调用次数、无逐对话轮询；Codex 打开成本不随总长度增长；DSH 冷打开成本按原生实现测量并披露 |

完成后更新 continuity 等受影响的功能地图和 architecture。两名独立 Agent 按[独立执行约定](../features/README.md#独立执行验收)，用浏览器跑核心旅程。四项检查（typecheck、test、build、check:docs）通过。未覆盖的部分如实列出。
