# 司门：Agent 与 Chrome DevTools 之间的中间层

边界和取舍见 [ADR 0023](../adr/0023-simen-browser-service.md)。名字「司门」由用户在 2026-11-09 选定。

| 用户行为 | 可观察结果 |
| --- | --- |
| Agent 用浏览器 | 在 shell 里运行 `chrome-devtools <工具> …`，写法和官方命令行一样（官方包 chrome-devtools-mcp 的版本固定）。输出和官方一致，只多出司门自己的排队和拒绝提示 |
| 开窗口 | `new_page` 分配一个窗口。实例最多 2 个窗口，一段对话最多 1 个（靠 `DSH_SESSION_ID` 认出）。满了就排队，先来先得，命令行显示前面还有几个；等 5 分钟还没轮到，就明确失败，并说明原因 |
| 只用自己的窗口 | 已经有窗口的对话再 `new_page`，会被拒绝，并告诉它自己的窗口编号。拿别的对话的页面编号去操作，也会被拒绝 |
| 收回 | `close_page` 立刻释放窗口。窗口 5 分钟没用，司门会关掉它，并删除这段对话的临时文件（例如没指定位置的截图）。之后再用会提示窗口已收回，需要重新 `new_page` |
| 用时才开 | 有对话要窗口时，才启动浏览器和官方后台进程。最后一个窗口释放后，两者都退出，只留下一个很小的启动程序 |
| 登录保留 | 实例的浏览器始终用同一个档案。浏览器停了再开，登录状态还在 |
| 本地文件 | 浏览器能打开工作区里的 HTML（`file://`）。`--filePath` 截图存在 Agent 指定的位置 |
| 体检 | `chrome-devtools doctor`（司门加的）报告这些：连不连得上浏览器服务、浏览器是否在运行、版本、窗口归属与闲置时间、排队长度、内存。实例体检也会跑它 |
| Agent 知道有它 | 实例配置了司门时，中书给 Agent 的说明里写着"用浏览器时运行 `chrome-devtools`，先看 `--help`" |

不做：给人看的浏览器界面、针对具体网站的处理、自己造的浏览器命令、Codex 接入。

## 实现要点

- **模块**：放在 `src/simen/` 下，只用 Node 自带的库，构建到 `dist/simen/`，做法同司辰。分两部分：
  - **命令行**（实例上叫 `chrome-devtools`）：带上对话编号、当前目录和原始参数去找宿主，把宿主的输出和退出码原样交回。排队时每隔一会儿显示一次进度。
  - **宿主**：和浏览器放在同一个容器里，负责窗口表、排队、闲置计时，以及启动、停止浏览器和官方后台进程。官方命令行由宿主在 Agent 当时的目录里执行，后台进程通过 `--browserUrl` 连接本容器里的浏览器，并且关掉使用统计（`--no-usage-statistics`、`--no-performance-crux`）。
- **页面归属**：宿主对比 `new_page` 前后的页面清单，确定新页面的编号。页面类工具先核对页面编号属于谁，再放行。
- **临时文件**：每段对话一个临时目录，用作官方命令行的 `TMPDIR`。这个目录挂在两个容器里的同一路径上，Agent 能直接读到截图。窗口收回时整个删除。浏览器缓存设上限 100 MB。
- **启动程序**：
  - 启动前清掉档案里的旧锁，打开"继续上次浏览"；
  - 浏览器崩溃后，所有窗口作废；
  - 浏览器带沙箱运行，容器策略按 ADR 放开两项系统调用。
- **协议与令牌**：命令行和宿主之间带协议版本，版本不一致时明确拒绝。访问宿主要令牌，令牌不进代码、文档和日志。
- **中书**：实例配置里加"已接司门"的开关。开关打开时，MCP 服务的说明里加一句关于 `chrome-devtools` 的话。
- **实例（操作者层）**：
  - 浏览器镜像：固定版本的 Debian Chromium、中日韩和 emoji 字体、Node、固定版本的官方包；
  - 容器硬上限：1.5 GB 内存、1 核 CPU、512 个进程；
  - 卷：档案卷；工作区挂在同一路径上；共享临时目录；
  - 把 `dist/simen` 的命令行以 `chrome-devtools` 的名字只读放进 DSH 的 PATH，并交给它令牌；
  - 体检。

## 验证

- **单元测试**：
  - 窗口分配，一段对话一个；
  - 别人的页面编号和重复 `new_page` 被拒绝；
  - 排队先来先得，等待会超时；
  - 闲置收回，收回后删掉临时目录；
  - 最后一个窗口释放后停掉浏览器；
  - 参数原样转交；
  - 协议版本和令牌。
- **预发实例的真实路径**：
  - 两段对话同时让 Agent 检查一个工作区 HTML 在电脑和手机宽度下的效果，并截图；第三段对话进入排队，然后轮到它；
  - 等 5 分钟，确认窗口被收回、临时截图被删掉；没人用时浏览器和后台进程退出，容器内存回落；
  - 在一个测试站点写入带有效期的 cookie，浏览器停了再开，cookie 还在；
  - 同时加载两个重页面时，中书和 DSH 照常响应；
  - `doctor` 和实例体检都通过。
- **正式环境**：安装、体检，以及一次真实的渲染检查。
