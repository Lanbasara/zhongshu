# 界面重设计

## Goal

用户于 2026-11-06/07 对齐时认为功能可用，但设计粗糙、文字难读、配色不当、缺少动效，要求在保持功能的前提下彻底重新设计前端。本切片从头设计信息结构、视觉、组件与动效，所有现有能力保留且可达，原生执行与恢复语义不变。布局与取值方向已于 2026-11-07 通过桌面与手机两种宽度的可点击原型由用户试用确认；同日用户确认退出条件并授权实施。

## Users and stories

- 经常同时运行 2–3 段对话：一眼区分运行中、刚完成未读、失败/中断/待核实，并能快速切换。
- 找对话先想项目：按工作区分组仍是主导航。
- 记得名字就直接跳过去：搜索对话、工作区和常用操作并直接打开，电脑和手机都能用。
- 偶尔查看工作区文件：阅读器按需打开、用后收起，不再常驻占一栏。
- 阅读 Agent 过程：运行时逐步展示当前动作，结束后收成一行摘要（工具数、耗时、结果），可再展开；没有内容的条目不单独占位。
- 电脑和手机都是主力设备：两端都按主力标准设计，手机不是桌面的缩小版。
- 未读完成：服务端记住每段对话已看到的位置，电脑与手机同步；浏览器标签页标题显示未读数量。

## Scope / Non-goals

- 信息结构可从头设计。登录、新建草稿与配置、阅读与输入、停止与排队、图片与文件引用、技能与用量、子 Agent、本轮文件、工作区文件阅读与编辑、工作区与对话管理、插件管理、存储都保留并可达。
- 视觉方向为“精密工具”：冷白底、高对比、紧凑，单一靛蓝强调色，彩色状态点，细边框，快速利落的动效。
- 只交付浅色。颜色按语义命名，以后加入暗色不需要改组件。
- Storybook 重建为组件目录：每个组件的全部状态都能操作，设计基础有展示页；删除旧参考原型。[ADR 0008](../adr/0008-storybook-ui-prototypes.md) 继续有效。
- 不做：暗色主题；改变 Harness 行为或原生边界；审批/问答、语音、通用附件等其他切片的功能；生产发布。

## Implementation decisions

用户在原型中试用确认：

- 侧栏以工作区树为主导航，对话行用状态点区分运行中、完成未读、执行失败、待核实和已中断，就绪不显示圆点；不另设“进行中”分组。
- 搜索与跳转覆盖对话、工作区和常用操作。电脑端用快捷键（macOS ⌘K，其他系统 Ctrl+K）或侧栏入口；手机端用标题栏的搜索按钮，抽屉顶部也有搜索框。未输入时，需要关注的对话排在最前，兼作快速切换。
- 插件、工作区管理、存储和账户收进统一的“设置”；已归档保留独立入口。
- 手机端用抽屉导航：当前对话是首页，从左侧拉出对话列表。
- 统一使用“竖条”品牌标识，登录页与工作台一致。
- 长文正文 15px。其余颜色、行高与动效以原型取值为起点，实现时在组件目录中定稿，由用户过目。
- “看到”按打开即读：对话处于打开且可见状态时即算看到，不要求滚动到末尾。
- 需要用户去看的结果计入未读：完成、执行失败、待核实及非用户主动的中断；用户自己停止造成的中断不计入。
- 一次切换交付：新界面、组件目录与未读同步在同一个 PR 中完成，不保留新旧界面混用的中间状态。

实现约束：

- 未读状态由服务端持久化并经私有认证读写，属于新增的小范围后端数据；数据归属与接口随实现更新 [architecture](../architecture.md)。
- [原生体验补齐](native-experience.md)已交付的工具展示语义保持不变（动作区分、展示限制提示、状态不足不显示成功）；新界面只改变呈现，收起后的摘要遵守同一规则。
- [界面与设计系统](../architecture.md#界面与设计系统)中现有的方向描述（安静质感、宋体标题、时序取值等）随新界面一并替换；入口与可访问名称变化后同步更新受影响的 feature map，首先是[界面地图](../features/interface.md)。

## Testing decisions

- 作者：四项仓库检查；在浏览器中以桌面与手机宽度走通真实用户路径；信息结构变化后，重跑各 feature map 中受影响的入口路径，包括原生体验补齐的工具展示路径；在两个隔离的浏览器上下文之间自查未读同步。
- 用户：作者自查通过后，将本分支启动为本地服务并接入用户的测试实例，由用户在手机与跨端完成验收，未读同步以用户验收为准。
- 本切片不做[共同入口](../features/README.md#独立执行验收)的独立执行验收（用户 2026-11-07 决定）。原型试用只确认了设计选择，不能代替上述证据。
