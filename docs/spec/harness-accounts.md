# Harness 账号

## Goal

在设置中看到 Codex 和 DSH 的账号是否可用；需要处理时得到提醒；Codex 在页内用设备码续登，DSH 在页内用粘贴跳转地址的方式重新登录。规则与依据见 [ADR 0015](../adr/0015-harness-account-status.md)。用户 2026-11-07 决定接着做这一项。

同日用户确认：

- 界面原型可以接入；
- 账号区放在设置“账户”标签的顶部；
- 账号卡片显示 Codex 本周额度的用量与重置时间；
- 不做独立执行验收，用户配合在隔离的临时 Codex 上完成一次真实设备码登录，验证后删除临时凭据。

同日用户在测试实例试用后又决定，并入本切片：

- DSH 卡片提供 DeepSeek 官方的用量与充值链接。余额不足时任务也会卡住，但重新登录解决不了，要去充值。
- DSH 在页内重新登录（ADR 0015 已注明）。

用户已授权实施，本文不表示已经实现。

## Users and stories

1. **查看。** 每端显示：是否连上 Host、是否登录、最近一次核实的结果和时间；Codex 可用时显示本周额度用量与重置时间。可以手动重新核实。
2. **提醒。** 某一端需要处理时，界面上有提醒并能一步去处理；离开页面时按通知设置推送（[ADR 0018](../adr/0018-push-notifications.md)）。
3. **Codex 续登。**
   - 管理员发起后，页面给出验证地址和用户码，在任意设备的浏览器上完成；
   - 完成后自动重新核实；
   - 可以取消，同一时间只有一个登录尝试。
4. **DSH 续登与充值。**
   - 管理员发起后，页面给出 DeepSeek 登录页；
   - 登录后浏览器跳到打不开的本机地址，管理员把它粘贴回来，完成登录；
   - 卡片上有用量与充值链接。

## Scope / Non-goals

范围：两个 Harness；桌面与手机宽度；状态定期核实（启动后、每 30 分钟、打开设置和手动核实时）。

非目标：
- 退出登录或切换账号；
- 由中书保存或刷新厂商凭据。

## Implementation decisions

- **Codex 状态。** 由原生账号读取和额度读取共同得出。额度读取返回 401 判为失效；其他失败判为暂时无法核实（2026-11-07 探针证据见外层实验记录）。
- **DSH 状态。** 由原生账号状态和过期通知得出。平台拒绝凭据时，原生会清除它；核实资料失败时，显示“已登录 · 暂时无法核实”。
- **提醒的范围。** 未登录、失效、未连接时，对话区上方显示提醒。推送只在进入未登录或失效时发送，未连接只在页面中提醒，以免启动时的短暂未连接误报。
- **用户码、登录页地址与粘贴的跳转地址。** 只在发起或完成登录的那一次请求中出现，不入库、不写日志；登录的发起、成功、失败、取消、过期作为关键操作记录。
- **DSH 粘贴登录。** 中书只取出粘贴地址中的 code 和 state，交给 Host 自己的本机回调，不访问粘贴的地址本身。
- **界面先做原型。** 先在 Storybook 做原型，用户确认后再接功能（[ADR 0008](../adr/0008-storybook-ui-prototypes.md)）。

## Testing decisions

| 验收 | 能区分成功与看似成功的证据 |
| --- | --- |
| H01 状态 | 两端真实 Host 的显示与原生读回一致；未登录、失效、暂时无法核实各有对应的真实或隔离原生证据 |
| H02 提醒 | 状态变为需要处理时界面提醒，并推送一次 |
| H03 续登 | Codex：在隔离的 Codex 上用真实账号完成设备码登录，原生读回有效；取消与顶替有证据。DSH：在能访问 DeepSeek 平台的环境里，用真实账号经粘贴完成登录，原生读回已存凭据且核实可用 |
| H04 安全 | 未登录、缺 CSRF 的请求被拒；用户码不出现在日志、数据库和读取接口中 |
| H05 交付 | 作者浏览器自测；四项仓库检查；更新功能地图；用户在测试实例验收。不做独立执行验收（用户决定） |
