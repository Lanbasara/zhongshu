# 独立新对话草稿与首发恢复

## 目标

落实 [ADR 0027](../adr/0027-independent-conversation-drafts.md)。用户点「新对话」总能开始一份新草稿，通过「继续草稿」或原地址回到已有草稿。范围覆盖全局和工作区入口、草稿导航、首发与故障恢复、旧草稿升级。

## 用户路径

- 连续点两次「新对话」会得到两个草稿地址。工作区入口预选该工作区，新草稿正文为空且配置可编辑。输入或切换工作区后，刷新和浏览器前进、后退仍回到对应草稿及其内容。已有对话链接继续打开原对话。地址所指草稿在当前浏览器不可恢复时，显示该状态并提供新建入口。
- 旧 `#new:` / `#new:<工作区>` 仍可进入新建，工作区有效时保留预选。升级前可恢复的草稿通过续写入口找回。带未决首发的旧草稿保留原对话和操作身份，沿原操作核对。
- 配置核验明确失败且消息未派发时，「保留草稿并另开对话」把原输入带入新草稿，可修正配置后手动发送。服务端确认原对话已删除时，说明删除结果并提供同样的恢复入口。正文、浏览器暂存图片、文件引用与技能按现有有效性规则保留或提示重选。未知结果继续提供核对原首发的入口，同时允许通过「新对话」独立起草。

## 验收

| 路径 | 通过条件 |
| --- | --- |
| 同工作区独立编辑与导航 | 分别从全局和工作区入口在同一浏览器建 A、B，两稿录入不同文字和材料。刷新、前进、后退和「继续草稿」恢复正确地址、工作区、配置及材料。切换未提交草稿的工作区时地址仍指向同一草稿。首次发送前服务端正式对话无新增，确认后当前页交接到既有格式的对话地址。覆盖桌面与窄屏。 |
| 创建回执丢失与发送结果未知 | 分别注入两种故障。A 待核对时，同工作区新建 B，B 可编辑并正常发送。A 的迟到响应不改写 B 的内容、发送状态或地址。刷新并反复核对 A，创建回执恢复后可继续原提交，已派发但仍无发送回执时保持待核对。核对服务端和原生记录，两种故障下 A 均沿用原对话 ID 和操作 ID，最终各有一次原生派发、一次首条正文。 |
| 配置核验失败与管理 | 触发 Codex 配置核验失败，核实原生派发次数为零。刷新后保留草稿并另开，核对材料和可编辑配置。确认原空闲对话可按现有规则归档、恢复和删除。新稿手动发送后使用新的对话和操作编号，旧对话的派发次数仍为零。 |
| 删除后恢复 | 在另一浏览器上下文删除首发未派发的 Codex 对话，回到原草稿刷新及核对。确认明确显示已删除，可保留材料另开，旧对话不会恢复。用普通 404 和丢回执做反例，页面继续按原身份核对。 |
| 兼容与 DSH 准备 | 使用含普通草稿、待核对草稿的升级前浏览器状态，确认原内容和未决操作可通过续写入口恢复。旧新建地址及已有对话链接可用。以真实 Codex 和 DSH 各跑一次正常首发，复核同工作区的两份 DSH 草稿不会误用已占用的原生准备，并能按现有路径重新准备。 |

故障驱动沿用[创建对话](../features/conversations.md)、[对话管理](../features/conversation-management.md)与[页面历史](../features/interface.md#driving-it-with-harness)的入口。实施后更新受影响的 feature map，按[独立执行验收](../features/README.md#独立执行验收)取得浏览器、操作记录与原生证据。
