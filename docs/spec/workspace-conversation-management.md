# 会话生命周期与对话管理

## 目标、依据与交付边界

本工作单承接 2026-11-03 的工作区对话管理目标，以及 2026-11-06 对长期积累、动态加载、完整删除、订阅释放和独立验证的讨论。将它们作为**一个完整需求**实施、验证和交付，不另拆 adapter 重构项目。本文是目标与实施方案，不代表下述行为已经实现；当前行为以[功能地图](../features/README.md)为准。

用户确认的结果：

- 使用几年、积累成千上万段对话后，仍能按工作区找到、阅读、接续和管理它们。侧栏按需加载；“显示更多”展开更早对话，不把旧对话自动归档、过期或丢弃。
- 发送消息才更新最近使用排序，单纯阅读不改变顺序。重命名、归档、恢复与删除具有一致的持久化和跨页面行为。
- Codex 删除包含原生对话及中书拥有的对话数据，须二次确认。DSH 只提供归档恢复，不提供删除；不修改官方 Host、不维护自有补丁或构建、不采用社区删除插件。此项以用户后续纠正为准，替代之前的 DSH 删除要求。
- 中书负责自己的持久状态、正确的原生调用、观察订阅和恢复责任；原生 Harness 的驻留、执行器和内存释放遵循原生策略。释放中书订阅不承诺原生进程或工具立即退出。
- 实现并启动本地服务后，由独立上下文 Agent 使用 Chrome DevTools MCP 或 Computer Use 操作完整功能；不能只交单元测试、API 成功或作者自测。

范围包括两种 Harness 的完整生命周期、导航与搜索、重命名、归档恢复、Codex 删除、旧数据迁移、连接恢复及容量边界。沿用工作区和对话身份、权限与原生绑定。[工作区管理](workspace-management.md)和[工作区文件操作](workspace-file-reading-editing.md)仍归其现有工作单；本次不新增工作区管理能力。新建草稿与首次发送遵循[草稿工作单](draft-first-conversation.md)和 [ADR 0010](../adr/0010-draft-first-conversation.md)，DSH 提前准备空会话以其后续替代决策 [ADR 0011](../adr/0011-dsh-prepared-session.md) 为准。本次验证正式对话首发创建及原生准备的有界复用，不能误删首发技能能力。

以下是落实上述目标的工程方案；尚需在实现中核实的技术条件单独标明，不将它们写成已确认的原生保证。已确认的长期生命周期决策见 [ADR 0012](../adr/0012-conversation-lifecycle.md)。既有职责约定见 [ADR 0001](../adr/0001-native-harness-boundary.md)，持久化归属见 [ADR 0003](../adr/0003-local-persistence.md)。

## 生命周期模型与责任

不把“侧栏可见”“原生已加载”和“任务在跑”压成一个 active 标志。沿用现有领域词汇，以下三条轴用于内部协调，不要求界面展示额外技术状态：

| 维度 | 状态与归属 | 对资源的影响 |
| --- | --- | --- |
| 管理 | 中书保存未归档、已归档；删除中/失败/完成由独立删除操作记录 | 归档不销毁身份；删除开始后禁止新提交和重新接续 |
| 执行责任 | 创建未决、待派发、执行中、等待输入、待核对、已确认终态，以及本地/原生待办 | 有责任就需要观察或有界恢复；不能随页面关闭消失 |
| 阅读需求 | 无阅读者、一个或多个阅读者；页面离开、断开、失联均须回收 | 同一对话共享观察；阅读结束只释放阅读需求，不取消任务 |

持久数据记录“还欠什么工作”，内存 runtime 只是可重建的执行/观察载体。已归档历史也能冷读；未归档历史不必常驻。侧栏运行提示来自中书投影，不通过遍历全部原生会话维持。

### 从创建到闲置、恢复

1. **草稿与首次发送**：沿既定草稿边界，首次发送冻结配置、持久化操作身份，尽早保存原生绑定。失败后沿同一身份核对，不另建会话或重复发消息。迁移须处理旧版留下的未占用准备与部分创建，不能误认作活跃任务。
2. **提交和执行**：先建立可恢复的执行责任及必要观察，再提交原生输入。接收、消费、完成分别核对；未知回执保留原操作并核对，不能自动重发。排队、提前发送、停止沿现有语义；停止被接收不等于待办清空或所有工具退出。
3. **阅读**：先返回已有历史投影，缺页/过期/重连时按需补取。读取不更改排序，不应仅为阅读而无条件恢复执行。某端读取确实需要临时加载时由 adapter 明确表达并及时释放，不能伪装成无副作用读取。
4. **观察**：服务端汇总阅读需求和执行责任，复用同一对话观察。页面切换/关闭/失联后撤销阅读需求；可使用短暂释放缓冲避免快速切换抖动，但缓冲不能代替终态判断。失联阅读者需有到期回收机制，不依赖浏览器必定发送离开通知。
5. **终态收尾**：核实目标轮次终态、最终历史、未决回执、排队输入和待处理请求。仍有可执行待办则继续；已暂停待办保留持久状态但不必常驻。无执行责任和阅读需求后刷新未落库投影、解除观察、清理 runtime/定时器/临时缓存。旧异步回调不得写回已释放或已删除对象。
6. **重启与重连**：从持久化责任集合分页恢复，不从“最近创建若干对话”推断活跃。恢复采用有界并发和重试退避；未知状态显示未核实，不阻塞其他历史阅读。SSE 断档、原生连接断开、快照游标缺口分别触发必要核对。仅重新读到历史不能声明原任务已恢复执行。

### 事件、补偿与性能边界

取消每个曾打开对话永久存在的 5 秒 `state + history` 轮询。已有可靠事件直接更新相应投影；状态、历史、用量和列表变化分别失效，流式文本不能带来同频的全历史查询或全部导航查询。

首次观察、断线恢复、事件缺口、未知回执、终态收尾可以触发核对。某端缺少完整事件时允许针对仍有执行责任的对象做有界、退避的补偿，须记录原因、范围、停止条件和实测负载；不换个名字恢复全量扫描。页面连接心跳、失联阅读者回收和有界队列恢复与“每段对话轮询正文”不同，按职责保留。

中书成本应随正在执行/恢复、正在阅读的数量及请求页大小增长，不能随全部历史数量维持逐对话订阅或定时器。列表/搜索直接读中书索引，不借用原生全量 session 列表充当管理层。顺带核查当前 DSH 草稿准备中的 `session/list` 全量查询：保留 ADR 0011 已确认的原生准备能力，同时避免全量查询成为创建瓶颈。若选择 DSH Host 级事件流，先量测首次快照大小和覆盖范围，不能未经测量便假设它比按需 follow 更便宜。

保留必要的并发、响应大小、历史页、内存和重试预算；达到边界时明确排队/拒绝及恢复路径，不让“读过 16 段历史”耗尽执行名额。现有 10,000 条总量上限要在容量验证中显式处理：不能靠自动删除腾空间，不能仅删除保护就宣布支持无限历史。

## 对话管理体验与数据契约

| 能力 | 目标行为和实现约束 |
| --- | --- |
| 工作区导航 | 包含空工作区，可独立折叠、展开和组内新建。首次只取有限条目；显示更多追加较旧结果，保留已显示条目、选中态和阅读位置。未展开数据仍在服务端，无自动归档或淘汰 |
| 排序 | 按最近成功被原生接收的用户消息排序；无消息用创建时间，另以稳定 ID 打破同时间并列。失败提交、阅读、标题修改、归档恢复、助手增量不更新时间。未知结果核实成功时只补记一次；使用原提交时序，不能让较晚到达的旧回执倒灌排序。本地排队尚未被原生接收不提前置顶 |
| 分页与并发变化 | 游标携带排序边界及查询范围，不依赖锚点行仍存在。按身份去重；新消息置前、归档/删除移除后有明确补页/失效策略。不能静默重复或永久漏掉尚未加载的项；快速切换搜索/工作区时旧响应不能覆盖新查询 |
| 搜索与重命名 | 服务端按标题跨工作区搜索，覆盖未展开历史，结果标明工作区。未归档/已归档范围明确，搜索也分页、可重试。重命名更新中书标题，跨页和重启后保留，不更换原生身份；不额外扩张为正文全文搜索 |
| 归档与恢复 | 手动归档后进入归档视图，可阅读原历史；恢复仍是原绑定。运行、等待输入、未决提交/待办或状态未核实不能被归档掩盖。服务端在与发送竞争的同一准入边界判定，拒绝时显示原因和下一步 |
| 界面 | 沿用设计系统与已接受原型。桌面可调侧栏宽度并保存，长标题省略但完整标题可读，状态和管理入口可辨认；手机抽屉提供相同管理能力。加载、无结果、失败、确认、删除中、重试、完成都有可辨认状态 |

迁移为旧对话回填可核实的最近发送时序；没有可靠依据时用确定性的创建时间回退，不伪造精确历史。排序字段及工作区/归档过滤建立匹配索引。含糊的子串搜索仍可能扫描：须用真实查询计划及容量数据测量，不因“有索引”就宣称搜索已优化。

## Codex 删除：同一生命周期中的可恢复操作

本节仅适用于 Codex。DSH 管理界面仅提供重命名、归档与恢复，服务端也拒绝删除；归档后遵循同一观察释放机制，不保留无责任的常驻订阅。删除不是归档，也不是释放订阅。工程方案采用服务端串行准入和持久化删除操作，具体原生执行机制须在实现中证明。

1. **确认**：展示对话标题、工作区、Harness、不可恢复含义及确定的关联删除范围；取消不产生变更。运行/等待输入/待核对时不给假成功，提示先停止、处理待办并核实。无需替用户擅自停止其他对话或整个共享 Host。
2. **建立删除责任**：重复请求共用同一操作。与发送、排队、归档、创建收尾竞争时只能有一种准入结果；删除中阻止新提交、原生接续及旧页面重新打开执行观察。先保留清理所需身份与阶段，再操作原生数据。
3. **原生清理**：由 Codex adapter 使用固定兼容版本的原生删除能力，处理拒绝、部分完成及重试。Workbench 不拼原生日志路径；不扩展或修改 DSH Host。
4. **数据归属**：辨别原生父子关系、派生会话和共享资源。自有子会话随原生删除语义清理；独立派生对话、其他对话仍引用的附件及工作区文件不误删。关系或引用不明确时明确阻塞，不猜测全目录删除。当前研究没有证明通用的共享存储垃圾回收，不把全局 GC 纳入完成承诺；但不能留下该对话仍可访问的正文或专属附件而报告完整删除。
5. **中书清理与通知**：原生删除已核实后清理历史、操作正文、实时投影、队列、文件变更记录、资源引用与专属资源、旧准备绑定等。删除结果通知须独立于会随对话级联删除的变更行，使其他页面清空已选正文、草稿/缓存引用并移除列表项。旧链接返回明确不可用，不重新创建原生身份。
6. **中断与重试**：保留不含对话正文/附件的最小操作记录和防重建标记；每一步可重入，原生已不存在视为该步成功。原生已删除但本地未清完、应用重启或响应丢失时沿同一操作继续。失败仍有可到达的状态和重试入口，不提前显示“已删除”。这不是跨 SQLite 与原生存储的原子事务。

研究已经排除了“归档天然阻止原生继续写入”的假设，也证明共享附件、子会话和旧身份重建需要分别考虑。离线清理实验仅支持方向可行，不能证明在线多写者删除、工具进程退出或断电耐久性。当前交付须证明中书管理入口内的竞争隔离、实际原生删除和应用中断恢复；外部原生客户端持续并发写入、主动复用已删除 ID、全局共享 GC、任意 SIGKILL/断电的强化不作为本轮前置研究。若实际部署无法安全满足本轮原生删除条件，显式阻塞并提出具体解决方案，不能暗降为本地隐藏。

## 实施组织与需要核实的技术点

在一个工作单内联动修改 Store/迁移、Workbench、adapter 契约与两端实现、HTTP/SSE、浏览器导航和管理交互。内部提交顺序可以按依赖安排，但完成判定始终是完整用户旅程；不另交一个“adapter 整理完成”替代本需求。

实施时逐项闭合：

- 固定兼容版本下，Codex 冷读能否避免 `resume`、释放与重连如何竞态；DSH follow/状态投影能否提供所需终态及待办事实。用真实 Host 观察调用和结果，不能只从方法名推断副作用。
- 阅读者识别、共享观察和失联回收的具体机制；明确每类观察的持有原因，消除双层刷新，同时保留断档与终态保障。
- 最近发送字段回填、队列/未知回执的排序时序、并发分页的更新策略；对历史容量和搜索成本给出测量。
- Codex 实际删除结果及部分失败恢复；DSH 不展示删除入口，伪造删除请求被拒绝，归档恢复不改变原生身份。
- 删除涉及的外键、共享引用、准备身份、跨页缓存以及删除通知的寿命；验证每个持久阶段可以恢复。

上述是可通过实现、源码和实验解决的工程问题，不是要求用户再决定一次已确认的需求。新增长期决策只有在确有边界变化并获确认后进入 ADR；尚未实现的目标不写进 feature map 或当前架构图。

## 完整验证方案

### 现场与证据

按[共同验证入口](../features/README.md)建立隔离应用、数据、工作区与浏览器现场，不操作个人服务或历史。固定被测提交、Node/浏览器与两端 Host 版本；记录是否使用真实模型、连接条件和各资源归属。fixture 只用于容量、确定性竞争和故障注入，真实 Host 负责证明身份、接续、执行及原生删除，二者证据不可互换。

准备至少两个有历史的工作区、一个空工作区；同名/长标题、相同时间戳、多页旧记录、归档记录、带附件与关联会话、旧库升级数据；另有运行、等待、排队、未知回执等可重复条件。性能数据分 100、1,000、10,000 条及容量边界；合成历史不得冒充一万段真实原生执行。

### 必须覆盖的旅程

| 编号 | 用户动作与初始条件 | 应观察的结果及证伪点 |
| --- | --- | --- |
| L01 | 空工作区进入草稿、首发，另一工作区接续已有 Codex/DSH 对话 | 创建时机、固定配置和原生身份正确；失败/未知重试不另建、不重复发；与同期草稿功能无回归 |
| L02 | 在多年历史中展开更多、搜索未加载旧标题、打开阅读，再发送消息 | 按需请求而非全量；更多保留原结果；阅读不改排序，成功发送前移；失败、排队未接收、晚到回执不错误置前 |
| L03 | 多页并列时间数据，另一页面新发、改名、归档或删除当前分页锚点 | 无重复、永久漏项或旧响应覆盖；搜索范围和标题跨页一致；失败可重试、滚动与选择可用 |
| L04 | 顺序打开超过旧 runtime 上限的历史；启动十段可控任务，结束后离开所有页面 | 阅读不占满执行名额；任务不因关页取消；收尾后订阅/runtime/逐对话定时器回收，冷历史仍可接续。观察中书指标与原生调用，不要求原生 RSS 立即下降 |
| L05 | 双页面读同一运行对话，关闭一个再关闭全部；暂停队列、等待输入 | 共享观察不重复订阅；只撤销阅读责任；执行/待办状态仍可恢复。无令牌输出一段时间不误判结束 |
| L06 | 原生断线、SSE 断档、页面重连、应用重启；未完成任务不在最近 16 条内 | 按真实责任恢复；未知保持可见，不自动重发；最新历史/终态/队列一致；没有恢复所有冷历史的调用风暴 |
| L07 | 重命名、归档、搜归档、阅读、重启后恢复并接续；同时另一页发送 | 标题/归档持久化，原绑定不变；归档不被误作删除/停任务；竞争只产生合法结果，进行中的工作仍可到达 |
| L08 | 取消删除确认，再确认删除空闲对话；刷新、重启和打开旧链接 | 取消无副作用；确认后核验 Codex 原生记录不可再读、中书正文/专属附件清理、列表/搜索/其他页一致；工作区文件与独立派生历史保留 |
| L09 | 删除与发送/排队/创建收尾竞争；原生拒绝、响应丢失、清理阶段应用中断 | 不越过准入；未知/失败不假成功；同一操作恢复并最终清理；原生已不存在不阻止重试，无悬挂且不可管理的删除项 |
| L10 | 长标题、侧栏调宽和刷新、手机抽屉走搜索/更多/归档恢复/删除 | 信息层级、状态、完整标题、确认焦点和操作反馈可用；删除选中项后落点清楚，正文/草稿不残留或串到其他对话 |
| L11 | 未认证/过期会话、伪造对话或资源身份、旧删除请求重放 | 私有数据不泄露，未授权删除不发生；授权且同一操作的重放幂等，不扩大清理范围 |

真实 Codex 和 DSH 各跑适用核心旅程；DSH 验证归档恢复及观察释放、没有删除入口且伪造删除请求被拒绝，Codex 原生绑定与删除后状态通过独立读取确认，不以列表消失或 HTTP 200 为证明。关联子会话与共享附件各有保护样本；不得只测无内容空会话删除。

### 性能与验证方法的可信度

- 同机、同版本、同页大小、同活动/阅读数量，比较不同历史规模的首屏、显示更多、搜索、打开历史的延迟与响应字节；记录请求数、SQL 查询计划、DOM/缓存规模、runtime/订阅数和中书内存。流式输出期间观察导航刷新频率及原生状态/历史调用量。
- 测量空闲、十段运行、十段结束、反复打开关闭、重启恢复等阶段。释放缓冲结束后，无阅读且无执行责任的对话不应继续发周期性状态/历史请求；总历史增大不应增加逐对话常驻观察。共享连接心跳单列，不算作会话轮询。
- 同口径保留修改前基线及修改后数据。具体毫秒目标和并发容量基于基线选定并记录测试条件；本工作单不凭空保证任意机器上的延迟。页大小/响应有界、冷历史零常驻逐会话轮询、超过旧 16 条阅读不耗尽执行额度是必须证明的结构性结果。
- 验证方法须能识别失败：用旧版的阅读后持续轮询、创建时间排序/替换分页等已知行为核对；删除部分失败/晚到回执等用隔离故障注入。保持真实断言，不能通过跳过场景获得通过。

### 独立执行与完成条件

实现后更新相关功能地图的实际入口、驱动、观察、恢复与清理说明；共享职责变化再更新 architecture。至少两个 `fork_turns=none` 的 Agent 按[独立执行约定](../features/README.md#独立执行验收)，在各自隔离现场使用 Chrome DevTools MCP 或 Computer Use 操作，不继承作者聊天、成功结论或临时私有教程。分工是验收执行安排，不拆分本需求；核心旅程覆盖两种真实 Harness。

执行者按场景记录 PASS/FAIL/BLOCKED/UNCOVERED，保留浏览器动作、请求/性能记录、原生身份与清理结果、重启后的独立读取，以及版本、故障条件、清理范围和证据位置。作者核对证据，修复后由独立者复跑失败路径。现有 DSH 研究实验不是本轮功能验收通过证据。

完成须同时满足：完整目标已实现，旧数据与相关既有发送/队列/停止/草稿路径无回归，两个真实 Harness 和独立浏览器验收有对应证据，性能及容量边界有测量，`npm run typecheck`、`npm test`、`npm run build`、`npm run check:docs` 通过。未运行、受阻和未覆盖范围明确披露，不把工作单完成当成功能完成。
