# 先进入新对话草稿，首次发送时固定执行配置

> 2026-11-06 后续决定：[ADR 0011](0011-dsh-prepared-session.md) 部分替代本文关于 DSH 首发前禁止原生会话、首发后才可选技能的条款。下文保留当时决定及理由；其余约束继续有效。新决定尚不表示当前实现已变更。

## 背景与依据

2026-11-06，用户确认将新建对话交互与 Codex 思考深度一起改进：工作区内的新建直接进入输入界面，首次发送才创建；Agent Power 独立选择但放在输入框内，模型与思考深度合并呈现，支持默认与复位。用户此前明确本次不支持已有对话调整配置，并要求保留功能的完整性与流畅性。

现有弹窗先创建真实对话，再开放输入；Codex 没有接出思考深度，DSH 则把模型与深度组合展开为重复模型选项。仅移除弹窗无法处理首发之前的材料、配置和失败恢复。本决策已接受；当前实现与验证方法见[创建对话地图](../features/conversations.md)。

## 决定

- 新建入口先进入可编辑的新对话草稿，不因进入、输入或选配置而创建持久对话、原生会话或历史列表项。草稿可以有本地稳定身份，这不等于真实对话已创建。
- 首次发送是创建边界。冻结工作区、Harness、模型、思考深度、权限和本次消息材料，沿同一对话身份完成创建与首发。已产生原生绑定后，失败恢复不得另建会话；回执未知时核对原操作，不把重试变成重复发送。
- 对话创建后配置固定，恢复与后续轮次遵循相同配置；本次不开放已有对话切换 Power、模型、深度或权限。保持 [ADR 0001](0001-native-harness-boundary.md) 的原生执行权与固定配置原则，扩展固定配置以明确包含思考深度。
- Power 选择决定模型、深度、权限及技能的能力范围。两端不互套配置；模型与深度在界面组合呈现，语义上仍分别表达，能力发现、校验与原生转换归各 adapter。统一交互不意味着统一档位或保证两端原生行为等价。
- 默认与复位是创建前的配置选择能力，不能令已创建对话随将来的默认变化而漂移。用户随后确认遵循当前 Power 的原生默认模型及其默认深度；缺少可靠默认时明确选择，不猜测。复位仅恢复模型与深度，不改工作区、Power、权限或正文；不以原型值替代真实目录。
- 未创建阶段的图片、文件引用、技能和文字也属于首发路径；不能靠提前创建隐藏会话，或移除已有输入能力，规避草稿适配。失败必须保留内容并给出可继续的状态。原生能力核查后，用户确认 DSH 的技能目录必须依赖已有会话：DSH 草稿提示首次发送后可选技能，Codex 草稿保持技能选择，不能为此提前创建隐藏会话。

## 取舍与后果

采用此方案是为了让用户直接开始写，再就地调整配置，并减少未发送就创建的空会话。代价是必须补齐草稿与创建中状态、首发材料交接和恢复；原生准备耗时转移到首次发送，不能据此承诺首发更快。

保留弹窗虽然改动小，却保留了用户明确反对的步骤；后台预建会话虽然容易复用当前输入接口，却违背首次发送才创建的边界；运行中切换配置会扩展恢复和执行语义，明确不进入本次。

[ADR 0004](0004-recoverable-communication.md) 的操作身份与未知结果核对、[ADR 0006](0006-auth-session-data.md) 的认证及数据边界继续适用。共享组件与探索按 [ADR 0008](0008-storybook-ui-prototypes.md) 演进，Storybook 的模拟成功不是原生集成证据。旧对话与旧配置格式必须兼容，不通过清空数据或套用新默认值完成迁移。
