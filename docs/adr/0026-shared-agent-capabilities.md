# Codex 与 DSH 共用中书工具，各自执行定时任务

用户确认 Codex 和 DSH 在中书里都应能使用司辰、司门与通知。两个 Power 使用同一个命令和日程页面，自动任务留在所选 Power 中执行。正式环境固定版本的 Codex App Server 提供线程投递与回执查询，没有定时任务接口。

## 决定

- **保留 DSH 原生调度。** 已有和新建的 DSH 任务沿用原生调度、编号、规则、投递与历史。Codex 的任务和触发记录由中书持久化，到点经 Codex 原生接口执行。一次触发使用稳定的投递身份，回执未知时查原生队列与历史。两个来源共用日程视图和管理入口。
- **三种投递目标。** 回到原对话沿用其固定配置；每次新开或首次新开后复用都在第一次实际投递时创建。Codex 新开对话使用默认模型和工作区读写权限，DSH 沿用原生默认和预设。任务的结论归对应运行，主动通知可直达原对话。
- **共用工作区日历和实例浏览器。** 日历按工作区读写。司门用 Power 和原生会话身份识别 Codex 线程与 DSH 会话，整个实例共用一个浏览器、两个窗口的配额。受限执行环境只获得到工具服务所需的通道。

这一决定扩展 [ADR 0021](0021-automations.md) 的调度归属、[ADR 0022](0022-sichen-time-module.md) 的会话接入和 [ADR 0023](0023-simen-browser-service.md) 的首批范围。既有 DSH 任务无需迁移。中书停机时 Codex 到期任务在恢复后补最近一次错过的触发；DSH 继续按原生规则执行。定向回归与实跑入口见[司辰](../features/sichen.md)、[司门](../features/simen.md)和[自动任务](../features/automations.md)。
