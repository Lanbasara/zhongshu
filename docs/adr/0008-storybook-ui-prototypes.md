# 在 Storybook 渐进验证产品界面

界面原型和产品组件长期各自维护时，同一个交互会有两份实现，后续改动容易只更新其中一份。中书用 Storybook 展示实际产品组件，让界面验证可以早于业务接线。探索阶段可以使用独立原型，后续需要持续复跑的交互由实际组件和 story 承载。

- 改界面时先找现有组件和 story。已有示例能看出变化就直接复跑。新增组件或交互状态时，优先在现有 story 补一个能看出差异的最小示例，再接真实数据。
- Story 维护可操作的界面示例，模拟数据留在开发入口。功能地图记录独立验收需要的入口、动作和判据，真实数据与 Harness 接线由相应的产品路径验证。 [文档归属](0005-documentation-system.md) · [界面功能地图](../features/interface.md)
