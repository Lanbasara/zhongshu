# 前台有界读取，后台增量工作，永久数据与工作集分离

## 背景与适用范围

对话条数分页不能限制单条正文的解析和 DOM 成本；全量状态恢复、每次合并读取全部历史索引、目录先截断后排序和累计数量硬上限，会使系统随使用年限退化。用户已确认五类问题全部在上线前解决，并接受巨型回复在聊天中有限预览、完整阅读器按需读取。

保留 React、Fastify、同机 SQLite 和独立原生 Harness，按下面的职责重构。永久正文和容量承诺归 [ADR 0010](0010-durable-reading-archive.md)，执行与文件门禁归 [ADR 0011](0011-managed-workspace-execution.md)。这份目标架构尚未全部实现；[当前架构](../architecture.md)继续描述实际模块，不以本决定代替运行证据。

## 目标架构与数据所有权

```text
浏览器 ──阅读请求──→ 有界查询接口 ──→ SQLite 读取工作线程
   │                                      ↑
   └─用户操作──→ 执行协调器 ──→ 受控入口 / 运行控制器 ──→ Harness
                       │                                  │
                 未决操作与门禁                       状态与历史 API
                       ↓                                  ↓
                  SQLite 写入工作线程 ←── 后台存档调度 / 目录扫描
                       ↑
                容量预算与背压控制
```

| 模块 | 拥有的事实与职责 | 不承担的职责 |
| --- | --- | --- |
| 执行协调器 | 操作身份、未决集合、运行组门禁、有效代次 | 为取得编辑资格恢复所有历史或等待存档追平 |
| Harness adapter / 受控入口 | 原生身份与协议映射、状态及指定运行证明、历史范围、受控派发 | 复制工作台业务状态机或自行实现 Agent loop |
| 后台存档调度 | 最新同步、旧页回填、截止范围、续传任务、公平性 | 从页面存活推断任务寿命，或把存档失败当成执行失败 |
| 持久存储 | 元数据、正文块、覆盖关系、操作身份、事务和一致备份 | 把永久正文当作缓存淘汰 |
| 查询与浏览器 | 摘要页、正文块、有限缓存、视口和阅读位置 | 打开页面时全量读取或解析整段对话 |
| 目录索引 | 可重建元数据清单、发布代次、分页与失效 | 作为实际文件身份或条件写入的权威 |

这些是模块和并发边界，不要求引入网络微服务或外部消息队列。后台任务可在同一产品进程体系内运行，任务进度必须持久化；浏览器、主 HTTP 循环和原生执行各自独立。

## 有界工作原则

每次前台请求和后台批次同时限制条数、字节与并发。缓存按总字节和条目数淘汰；队列满时施加背压，不把同步的无界工作换成异步的无界排队。预算是可配置、可测量的运行参数，不能变成静默漏数据或对话总寿命上限。每次请求只保证完成其声明的有限范围，并给出继续入口。

### 查询、正文和渲染

列表读取只返回元数据、有限预览、大小、正文版本和完整内容入口。预览在服务端形成，不能先把全文传给浏览器再隐藏。对话、工作区、历史及目录均用包含唯一键的稳定排序与键集分页；扫描代次或视图水位明确处理分页间的变化，同时间戳不得造成静默遗漏。

聊天仅挂载视口及少量前后内容；解析前限制预览字节，再限制 Markdown 结构、高亮及表格复杂度，超预算使用明确的原文预览。输入、已完成消息与流式尾部分开更新；工具详情按需挂载，流式内容超出预览预算后继续存档而不继续扩大聊天 DOM。

完整阅读器按正文版本分块读取，块边界正确处理 UTF-8，超长单行也有界展示。普通内容保持富文本体验，极端内容可按原文阅读；复制读取实际全文，下载流式输出并支持取消，不能从截断的 DOM 复制。正文更新时重新建立一致版本，不能将多个版本的块拼成一份全文。

### 存储与调度

将同步 SQLite 工作移出主 HTTP 事件循环；写入经过有界、可调度的单写者队列，读取使用独立连接和短事务。受理、终态及门禁变更先于后台回填，同时保证后台任务在持续负载下不饿死。不得在数据库事务内等待原生网络或进程控制。保留 [ADR 0003](0003-local-persistence.md) 的同机 SQLite 和一致性约束，取代其中仅在后续测量需要时再考虑数据库 worker 的安排。

正文与元数据分离；历史追加、前插和一般补页只访问页内条目及相邻索引。稀疏排序位置不足或原生中间重排走局部修复；确需全量重建时在后台建立新索引代次，旧读取持续可用，校验后切换。不得每次写一页就遍历全对话 ID。

操作与队列不使用累计条数拒绝多年使用；已结束记录可压缩，但稳定操作身份、内容摘要及结果证据保留，旧请求不能重新执行。目录和渲染缓存可重建，存档不属于缓存。维护、备份、迁移及 WAL checkpoint 的开销也纳入预算，不能只优化查询耗时。

### 目录清单

按需后台扫描目录，分批写入元数据索引，完成后发布新代次；已有已完成代次在刷新期间继续可读。初次扫描显示进行中与已发现内容，不把部分结果标成完整。游标绑定清单代次及唯一排序键，过期明确要求刷新；排序规则在同代内固定。

文件系统监听只用于使清单失效，配合周期或显式重新扫描。稳定目录必须可完整遍历；普通目录迭代不提供文件系统瞬时快照，不承诺捕获扫描期间每个瞬时变化。打开及保存仍核对实际文件系统和权限，目录清单不授予新权限。隐藏项、链接和路径边界沿用已有约束。

### 原生接入也是预算边界

将当前执行摘要、指定运行终态证明、历史范围和正文导入分开。普通阅读只使用本地存档，不加载原生线程；原生恢复用于当前执行和后台核对。冷态恢复与连续活跃状态分别测量，不以预热结果替代重启路径。

不能只让中书返回小页而在 adapter 内重复取得整段轮次索引或全文。每端须通过原生范围能力、可核实的增量索引或兼容扩展消除反复全量工作；单次不得把全部历史装进主服务。大载荷在独立且有资源预算的导入路径解码、分块持久化，不用丢正文满足预算。

原生 API 能力不足时明确记录该项尚未满足，补齐兼容接入后再验收；不能把轮次累计上限调大就认定解决。固定版本的游标、压缩、身份、投影和状态语义必须分别实测，升级后重验。运行组活动摘要不替代执行配置、指定终态或进程收束证明。

## 取舍与退出条件

增加正文分块、后台任务、目录代次和执行协调会提高实现复杂度，也使正常前台成本不再直接依赖累计历史量。继续沿用嵌入式存储和单应用部署，避免同时引入跨服务事务；代价通过明确的数据归属、短事务、版本身份和恢复验收控制。

大规模数据仍需要后台时间和磁盘，初次目录扫描、首次旧库核对、原生冷恢复必须可见、可恢复；不能承诺所有后台工作瞬时完成。具体内存、首屏与延迟指标在实现前固定测量条件及预算，已提出的分页数字不自动成为用户承诺。整组上线条件及子规格见[长期使用规格](../spec/long-term-performance.md)。
