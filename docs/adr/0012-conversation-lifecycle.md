# 中书拥有会话管理与观察生命周期，原生 Harness 拥有执行与驻留

> 2026-11-10：[ADR 0025](0025-schedule-performance.md) 部分替代下文“旧对话……不自动归档或淘汰”：自动任务开出的对话在 90 天无活动后自动归档，归档仍完整可读；用户自己的对话仍不自动归档。

## 背景与依据

2026-11-06，用户确认长期使用中的动态对话管理、完整删除与订阅释放是一体的需求，并授权正式化决策、安排任务和实施。曾打开的历史持续按固定周期读取状态和正文，不能成为长期积累的默认成本。先单独重构 adapter 也不是本次交付目标。

## 范围修订

2026-11-06 后续确认：用户撤回自维护 DSH Host 源码、补丁和构建的授权，接受 DSH 仅归档与恢复，不提供删除。此修订替代此前将 DSH 完整删除列为交付要求的讨论；不再等待 Host 扩展决定。Codex 保留完整删除。两端仍须按执行责任和阅读需求释放中书资源，无需等待闲置十天或半个月；原生驻留不由中书强制控制。

## 决定

中书分别维护管理状态、尚未完成的执行责任和阅读需求。原生身份不因阅读、闲置、归档恢复而改变；历史是否显示在当前页不改变其生命周期。管理索引属于中书，不以加载全部原生会话实现导航。

- 侧栏按最近发送消息排序，阅读不改变顺序；旧对话通过按需展开和服务端搜索到达，不自动归档或淘汰。
- 观察由执行责任和阅读需求持有，同一对话共享观察。无人阅读且已核实无未完成责任时释放中书订阅和临时资源。关闭页面不取消任务；启动恢复依据持久化责任，不依据最近创建列表。
- 事件驱动更新投影，首次读取、连接缺口、未知回执和终态收尾做必要核对。补偿必须有范围、预算和退出条件，不维持对所有曾打开对话的永久状态与正文轮询。
- 原生 Harness 的内存驻留、会话卸载与执行器策略由原生实现负责。中书保证正确调用和自己的资源边界，不把解除订阅等同于杀进程、任务停止或删除。
- 归档保存原身份与历史。DSH 仅支持归档恢复，界面不展示删除入口，服务端拒绝删除请求；不修改、分叉或自行构建 DSH Host。Codex 删除包括原生对话及中书拥有的对应内容，需二次确认、竞争隔离和可恢复清理；失败或尚未核实不得声称完成。工作区文件和其他对话仍引用的数据不属于可随意删除的范围。
- 删除跨越独立持久化边界，采用可重入的持久操作，而不假设跨存储事务。保留恢复所需最小标记，不保留已删除正文作为隐含回收站。不使用社区删除插件，也不为 DSH 删除维护修改版 Host。

本决策延续 [ADR 0001](0001-native-harness-boundary.md) 的原生执行边界、[ADR 0003](0003-local-persistence.md) 的数据归属与 [ADR 0004](0004-recoverable-communication.md) 的未知回执规则。创建前 DSH 空会话按 [ADR 0011](0011-dsh-prepared-session.md) 有界复用，不能错误恢复已被替代的禁止准备规则。

## 取舍与后果

把阅读与执行责任分离增加了失联回收、终态收尾和恢复调度的工作，但使日常成本不再随冷历史数量保持逐会话增长。不能只删定时器而丢失未知回执和排队恢复；也不能为了立即释放内存干预原生任务。

完整删除比本地隐藏复杂，必须面对原生能力缺口、子会话、共享引用和部分成功。只有经过验证的范围才能宣称删除完成；更强的外部多写者隔离和断电保障不凭离线实验推导。具体范围、行为与整个功能的独立浏览器验收归[工作单](../spec/workspace-conversation-management.md)。
