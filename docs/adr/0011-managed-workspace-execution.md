# 受控执行入口与运行组门禁拥有文件编辑资格

后续变更：[ADR 0014](0014-observation-lifetime-and-concurrent-editing.md) 替代本文普通文件编辑必须独占运行组的要求；本文保留决策历史，当前行为见功能地图。

## 背景与适用范围

逐段恢复所有历史对话再证明工作区空闲，会让编辑成本随累计对话数增长；要求所有对话同时持有观察订阅，又会把订阅资源上限变成功能容量上限。原生 idle、工具进程退出与文件不能再被写入也不是同一事实。

本决定细化 [ADR 0001](0001-native-harness-boundary.md) 的运行托管与文件副作用边界，采用统一执行入口、持久未决登记和可核实的独占编辑窗口。它是已确认的目标，当前配置与实现仍见[架构地图](../architecture.md#工作区文件)。不改变 Harness 拥有 Agent loop、上下文和工具语义，也不让浏览器拥有任务生命周期。

## 决策

### 执行协调范围

可原地编辑的受管工作区，其所有执行入口和可写进程必须落在同一协调边界内。中书的发送、排队派发、提前发送、唤醒、原生自动工作及其他客户端的写入请求都受该边界约束；不能只拦截一个 HTTP 发送接口。工具、原生文件写入和可写子进程须受运行控制器约束。操作者提供具体隔离实现，产品定义并验证能力契约。

其他客户端若要驱动同一受管 Harness，须经过该入口；管理连接和启动权限不能旁路门禁。原生事件和廉价元数据是核对线索，不是所有写入者已收束的证明。不能提供这项能力的连接保留已有读取与执行能力，但不宣称具备受管原地编辑资格；上线验收现场必须为两个 Harness 都提供并验证所需能力。

以实际可以独立停止和隔离写入的[运行组](../../CONTEXT.md)为门禁单位，初始可使用整个专用 Host。相交目录属于冲突范围。若多个工作区共享一个运行组，编辑窗口会暂停这个组的执行入口，界面先显示受影响范围；不能承诺一个工作区编辑而同组其他写入继续。能力扩展到每工作区隔离时，必须另行证明进程与目录归属。

### 持久未决登记与代次

受理并准备派发前，事务性登记操作 ID、内容身份、工作区及目录身份、原生绑定、运行组和有效代次。已排队、派发回执未知、运行、等待请求及结果待核实均有可恢复记录；停止请求不自动结束这些记录。

运行协调器维护未决集合及原生关联，只对其核对实际接收、待处理输入和指定运行终态。终态证明与仍可能写入的原生附带工作、进程收束分别保存；不能仅凭模型回复结束就删除全部占用。迟到响应只允许更新其所属操作和代次。登记不因超时、订阅淘汰或租约到期变成空闲。

门禁和运行组代次跨应用重启有效。控制器只接受当前有效代次的变更，拒绝旧应用、旧请求和旁路重启；工作台内存互斥本身不构成此保证。数据库提交、原生投递和进程控制不是一个事务，各自的未知结果继续遵循 [ADR 0004](0004-recoverable-communication.md)。

### 编辑窗口协议

| 阶段 | 允许行为与离开条件 |
| --- | --- |
| 允许执行 | 通过统一入口受理及派发；读取和历史存档独立运行 |
| 收束中 | 原子关闭相关运行组及相交目录的新增工作受理，固定此前已受理集合；仅该集合可按原顺序受控排空，期间不允许保存；核对所有未决输入，不为编辑自动取消它们 |
| 可编辑 | 控制器已证实写入能力收束并持久保留门禁；允许在该窗口内多次条件保存 |
| 恢复中 | 先停止接受新的保存并完成在途写入，再恢复原运行组、原生数据与绑定，核对新代次后开放派发 |
| 待核实 | 暂停、恢复、进程归属或门禁结果未知；保留稿件、已受理工作和恢复入口，拒绝写入及新派发 |

收束时的排空许可只属于已经持久登记的操作及其原生关联工作；不能借排空受理新任务，也不能同时禁止所有派发却无限等待尚未派发的既有任务完成。已受理集合核实结束后关闭排空许可，再由控制器确认写入收束，最后进入可编辑阶段。结果未知时保持阻止保存，不能跳过队列。

收束证明覆盖可写工具进程，而不只是 Host 主进程。已结束轮次遗留的写入进程仍需由控制器处理；不能通过释放旧进程恢复其写入能力。有效控制器实现可采用完整容器或进程组生命周期管理，必须防止不受控重启。后台进程仍属于未决工作时，继续等待或由用户另行停止，不把编辑申请当作取消授权。

文件保存只核对当前窗口、目录身份和文件版本，在门禁内完成原子替换；窗口切换与保存互斥。两个浏览器提交同一旧版本时只允许先满足条件者成功，另一份稿件保留。页面关闭或连接断开不自动解除门禁；重新进入可显式恢复 Agent。控制器和未决登记不可信时保持待核实，不能超时自动开放。

### 重启、迁移与其他管理动作

应用重启只恢复持久门禁及未决集合，原生重启先核对控制器代次和绑定，不恢复全部历史对话以取得编辑资格。已核实结束的历史量不得决定正常保存成本；观察订阅仅用于及时展示。

旧实例首次迁移时，关闭受影响的新派发，分批登记并核查既有绑定和待处理输入，建立可追查基线。未完成初始化的范围不开放编辑；初始化进度可以续传，且已有存档可读。不能把旧数据库中的 idle 标志直接当成新协议的清洁证明。

移除工作区、Host 生命周期操作和会改变原生运行配置的插件管理动作，使用同一个协调边界，不能建立彼此不知情的锁。插件安装归属继续由 [ADR 0009](0009-instance-plugin-scope.md) 定义。本决定不扩展原生提问或审批的产品范围，已有等待状态仍阻止进入编辑。

## 取舍与替代方案

- 全历史扫描可以作为迁移或异常审计，不能作为每次保存的常规前置条件。
- 缓存 idle、增加订阅槽位或廉价批量元数据都不能关闭检查之后发生的新写入，不能单独授权保存。
- 乐观文件版本检查仍用于拒绝旧稿，但无法约束版本检查之后的独立写入者，必须与编辑窗口组合。
- 独占入口和运行控制器增加部署接入成本；以整个 Host 为单位时影响范围较大。收益是正常编辑成本取决于当前未决工作和控制器，而不随历史对话累计增长。
