# 插件安装归中书实例内的原生 Harness

中书让管理员在同一个工作台管理 Codex 和 DSH 插件。两端的市场、包身份、版本与加载方式各有自己的含义。用户也可能用同一厂商账号登录多套环境，需要能明确判断一次安装会在哪套环境生效。

## 决策

管理操作绑定到[插件的全局范围](../../CONTEXT.md)，即当前中书实例内所选 Harness 的原生安装范围。Codex 和 DSH 保留各自的市场、包身份、安装状态及加载语义。同名插件可以在两端独立安装。用户从哪个设备访问中书，不改变安装目标。账号共享目录和工作区级安装不属于这个写入边界。

中书拥有管理员入口和操作记录。安装与启停事实由目标 Harness 持有，工作台用原生读回核实结果。Codex 的管理权经专用管理进程绑定到同一原生实例，DSH 使用该实例的原生管理接口。浏览器经中书私有接口请求管理动作，执行环境不挂载 Codex 管理连接。该入口的授权范围限于目标实例。这延续了[原生 Harness 边界](0001-native-harness-boundary.md)。

## 取舍

统一插件目录和安装记录会让同名条目更容易聚合，却会掩盖两个发行包和两套加载规则，也容易让账号目录和实例操作产生相同的用户预期。沿用原生市场后，两端各自提供可用的来源与版本能力，中书可以统一导航和回执展示。代价是操作者需要为每套实例配置独立的原生连接与持久数据，界面也需要呈现原生能力差异。
