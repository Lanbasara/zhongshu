# DSH 草稿可准备原生空会话，正式对话仍在首发时建立

## 背景与依据

2026-11-06，用户反馈原生工具展示、DSH 默认模型和首发技能体验，并在对齐中明确选择：采用原生空会话，优先保证首发体验；先处理这三项问题，审批与用户问答随后独立推进，多 agent / Teams 留待专项研究。本决策已确认，尚不表示实现完成。

DSH 的公开技能目录按已有 Session 的工作目录和 preset 解析，不要求已有用户消息。其原生前端通过准备、复用 blank Session 支持输入体验。中书原先把正式对话与原生会话的创建绑定在首次发送上，导致首条消息不能选择 DSH 技能。这是产品创建边界与原生接口共同产生的限制。

依据：[DSH 技能目录](https://github.com/deepseek-ai/deepseek-harness/blob/504a01a9578abc2c6f1fb896b1dc322c9fe24f66/packages/api/session-controller/src/skill-catalog.ts)、[原生前端工作区与空会话](https://github.com/deepseek-ai/deepseek-harness/blob/504a01a9578abc2c6f1fb896b1dc322c9fe24f66/packages/client/ui-workspace/README.md)、[会话请求与模型默认协议](https://github.com/deepseek-ai/deepseek-harness/blob/504a01a9578abc2c6f1fb896b1dc322c9fe24f66/packages/api/session-controller/src/types.ts)。这些是协议依据，不替代目标版本的真实验证。

## 决定与替代范围

- 区分中书正式对话与 Harness 原生会话。选定有效工作区和 DSH 后，可以为草稿准备、复用原生空会话，查询技能；准备本身不提交用户消息，不开启用户任务。
- 中书历史列表仍在首次发送后出现正式对话。原生提前准备不代表配置已经冻结：用户首发前仍可调整配置，首次发送时按最终选择核验并固定配置及材料。
- 草稿与准备身份必须可核对。刷新、切换、准备失败和回执未知不能丢材料、串用另一工作区/Power 的会话或盲目重复创建；首发复用已准备且核验适用的原生身份。无法确定是否创建或接收时，沿原身份核对。
- 空会话需要有界的复用与清理生命周期，不能因反复进入或切换无限积累；清理不能影响正式对话、已提交操作或仍需恢复的草稿。具体回收机制属于实现设计，须依据原生能力证明，不能先承诺未经核验的删除行为。
- 本决定仅替代 [ADR 0010](0010-draft-first-conversation.md) 中 DSH 首发前禁止创建原生会话、以及因此限制首发技能的条款。Codex 保持无需提前创建的技能查询路径；首发固定配置、既有对话不改配置、材料保留、身份核对和权限边界继续有效。

## 取舍与后果

选择原生空会话，是为了让第一条消息具备完整的技能输入能力，并沿用 DSH 已有生命周期。代价是中书需管理未发送草稿对应的原生资源，而不能再用“无原生身份”简化恢复。严格首发才创建会继续牺牲技能体验；新增 Host 无会话技能接口会增加专用扩展与长期维护，本次不采用。

[ADR 0001](0001-native-harness-boundary.md) 的原生执行权、[操作与回执约束](0004-recoverable-communication.md)以及 [ADR 0006](0006-auth-session-data.md) 的认证和数据边界继续适用。准备绑定是服务端核验对象，浏览器缓存不能成为授权依据；不把原生凭据或直接访问能力交给浏览器。

本次交付边界与验收归[原生体验补齐工作单](../spec/native-experience.md)。审批、问答与多 agent 的延期不表示它们从完整原生能力目标中删除，也不能以本次完成宣称已全功能。
