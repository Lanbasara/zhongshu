# 司辰：中书的时间模块与命令行

> [ADR 0026](0026-shared-agent-capabilities.md) 补充 Codex 会话身份与定时任务接入。

## 背景与依据

2026-11-09 迁移投资工作区时暴露出时间系统不够扎实：

- **Agent 建定时任务要手写规则文本。** DSH 原生的 `schedule_create` 工具把时间交给一个 `rrule` 参数，要 Agent 自己写 RFC 5545 文本（`DTSTART;TZID=…` 加一行 `RRULE:…`）。"只跑一次"要写成"每天、共 1 次"，结束日期要换算成 UTC 的 `UNTIL`。
- **中书新建任务没有结束日期。** 迁移时有两条带结束日期的提醒丢了结束日期，只在任务内容里写了一句"结束：……之后暂停"，等于靠 Agent 记性。
- **日历条目要手写 JSON。** 写进工作区时间轴文件 `.zhongshu/timeline.jsonl` 时，Agent 自己拼 JSON 行。

用户的判断（2026-11-09，本 ADR 经用户确认）：时间系统对 Agent 最稳的形态是命令行。它是一层包装：底下仍由 DSH 原生定时任务执行，上面加中书自己的规则。它要能扩展，作为中书里一个独立、解耦的模块，名字和中书本体分开，安装和更新要管好。

核实过的事实（DSH 0.2.2-rc.1）：

- DSH 调用 MCP 工具时只带配置里的固定请求头，不带会话。中书的 MCP 工具因此在被调用时认不出是哪段对话在调。
- DSH 运行 shell 命令时会设置环境变量 `DSH_SESSION_ID`，值为当前会话。
- DSH 的 MCP 客户端会把服务器在 `initialize` 返回的 `instructions` 放进 Agent 的提示，标题为"MCP server: <名称>"。
- DSH 定时任务服务接受 `rrule`（可带 `UNTIL`），也接受 daily、weekly、cron 等写法；后几种没有结束日期。

## 决定

1. **建一个独立模块「司辰」，命令是 `sichen`。** 它和中书本体分开命名，避免混淆。模块有自己的目录和版本号，运行时只依赖 Node 自带的库。时间规则都在这个模块里：解析说人话的时间、检查、换算成 DSH 规则、算出接下来几次、描述规则。
2. **包装 DSH 定时任务服务，不另造调度器。** 到点执行仍由 DSH 负责。司辰把说人话的时间换算成 DSH 能执行的规则，有结束日期时用带 `UNTIL` 的 `rrule`。司辰包装的是任务服务本身，不是 Agent 的 `schedule_create` 工具。
3. **网页和命令行共用一套规则。** 中书「日程」页的新建和修改，与 `sichen` 命令行调用同一个时间模块。两边能设的东西一样，包括结束日期；读回的描述也一样。
4. **命令行经中书执行。** `sichen` 通过本机回环地址调用中书服务，用的端点和令牌与给 Agent 的通知工具相同。中书负责连 DSH、核对冲突、认出对话和工作区、写时间轴文件。命令行自己不连 DSH，也不直接写工作区文件。
5. **"本对话"由 `DSH_SESSION_ID` 认出。** 不在 DSH 的 shell 里运行时，这个目标直接报错。
6. **Agent 靠中书 MCP 服务的说明知道 `sichen`**，不在任何工作区写规矩。实例上关闭 DSH 原生的定时任务工具，只留一条路。这是实例配置，可以随时重新打开。
7. **可扩展。** 命令按"类别 + 动作"组织：首批是 `schedule` 和 `timeline`，以后增加新类别。每个命令都有 `--help`、中文错误说明，加 `--json` 时输出给程序读的格式。命令和中书服务之间有协议版本，版本不一致时明确拒绝，不带着不兼容的规则运行。
8. **安装与更新随中书版本走。** `sichen` 和中书一起构建，并放进中书的镜像。实例的维护脚本把它只读地放进 DSH 运行环境的 PATH，把令牌只读地交给它，体检时核对版本和连通。中书换版本时，司辰跟着换。

## 取舍与后果

- **为什么不做成中书的 MCP 工具：** 工具被调用时认不出对话，做不了"回到本对话"，而这正是跟踪类任务最常用的目标。
- **为什么不做成 DSH 插件工具：** 插件工具能认出对话，但依赖 DSH 内部的插件接口，DSH 升级就可能失效，安装和维护也更重。
- **命令行依赖 shell：** Agent 需要有运行命令的权限。工作区读写和完全访问都满足；只读权限下 Agent 不能建任务，这和"只读"的含义一致。
- **令牌对 Agent 可读：** 令牌和 Agent 运行在同一个账户下，Agent 能读到它。它只授权通知、回填结论和司辰的操作，这些本来就是 Agent 用原生工具也能做的事，没有扩大权限。令牌不进代码、文档和日志。
- **关闭原生定时任务工具后，Agent 只能经司辰管理任务。** 中书或司辰不可用时，Agent 也就建不了任务；这时任务照常由 DSH 执行，已有的任务不受影响。
- **Codex 没有自动任务，`schedule` 类在 Codex 里不可用；`timeline` 类不依赖 Harness。**
