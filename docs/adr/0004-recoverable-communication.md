# 先建立可恢复的操作与历史协议，再验证更新通道

网络稳定性、访问体验与性能从第一条相关切片开始验收。推荐同源 HTTP 命令配合 SSE 更新，保留 HTTP + WebSocket 作为比较方案；更新通道尚未定案。选择须通过[质量要求中的真实链路实验](../quality.md)，不能把任一长连接的重连功能当作业务恢复。

首个工作台已按此契约实现 HTTP + SSE，模块与运行边界见 [Harness 接入](../harnesses.md)。这是当前可验证的实现，不将本机结果扩大为所有代理/设备下的通道定案。

## 跨通道成立的契约

1. 用户动作具有稳定操作身份、目标、内容摘要与回执。同身份同内容重试查询已有结果；同身份不同内容拒绝。服务端验证权限并持久记录受理后，再派发原生动作；同一对话的派发顺序明确。
2. 分开表达“中书已受理”“原生已接收”“执行或等待”“已完成”，观察连接状态另行展示。请求超时不能推断发送失败，也不能清空未知状态下的输入并重新生成操作。
3. 派发前记录与原生效果之间存在崩溃窗口。恢复时核实原生身份和关联信息；只有能证明未派发的操作才可继续派发，可能已执行的操作保留待核实。不能承诺跨进程严格执行一次。
4. 快照带一致水位，接续事件有稳定身份和顺序。订阅与快照读取之间的变化必须可补齐；重复事件幂等应用，游标过期或代次失效明确要求重取快照。旧响应不能覆盖新状态。
5. 历史正文有稳定身份、分页顺序和完整内容入口；未加载、部分可用、读取失败与空回复分别表示。短期补发窗口与持久历史的归属见 [ADR 0003](0003-local-persistence.md)。
6. 待处理请求绑定原生会话及有效代次；多端处理只认领一次，投递回执未知时核实，过期请求明确失效。传输重试不能重复批准或重复回答。
7. 连接断开、退出或换代时停止旧补发循环并释放缓冲；慢客户端达到有界队列上限后走明确的重同步路径，不能无限缓存或丢弃后假装连续。页面关闭不取消原生工作。
8. 前台通过心跳与活动超时识别假连接，回前台主动核对身份、快照和未决操作；网络仍不可用时保留输入并显示状态。重连采用有上限的退避与抖动，避免多标签页同时循环请求。应用/原生进程重启后的连续性单独验证。

## 通道取舍

| 候选 | 对中书的价值 | 必须承担的成本 |
| --- | --- | --- |
| HTTP 命令 + SSE | 命令回执独立于观察连接；文本更新符合当前主要流量方向；原生 EventSource 有重连与游标传递 | 仍需持久事件、恢复协议和慢端控制；验证代理缓冲、超时、HTTP/1 多标签页连接限制及 HTTP/2 协商 |
| HTTP 命令 + WebSocket | 双向控制帧、订阅管理和二进制扩展更直接 | 连接重建、游标恢复、应用级流控自行实现；浏览器 WebSocket 没有接收端背压 |
| 全部使用 WebSocket | 单连接统一命令和更新 | 还需自建请求关联、超时、回执与重试；断开观察通道同时阻断命令，不是当前稀疏命令的必要成本 |

EventSource 的 `Last-Event-ID` 只传递浏览器解析位置，不证明界面已应用事件，也不提供持久事件日志；刷新后创建新连接仍须建立恢复位置。原生 API 不支持任意认证请求头。采用同源 HttpOnly 会话 Cookie，凭据不放 URL，写命令做来源/CSRF 校验。若使用 WebSocket，握手也验证来源与身份；会话失效时终止对应订阅。[SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)、[WebSocket 标准](https://websockets.spec.whatwg.org/)、[浏览器背压限制](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)

代理配置属于部署接口，需要验证流式响应不被缓冲。某些 Tunnel 要求 `text/event-stream`；WebSocket 也可能因边缘重启或空闲超时断开。源码定义通用要求，具体代理配置留给部署实例。[Tunnel 流式要求](https://developers.cloudflare.com/tunnel/troubleshooting/)、[WebSocket 连接限制](https://developers.cloudflare.com/network/websockets/)

当前命令频率较低、输出以服务端文本为主，因此优先试验 HTTP + SSE；文件上传仍走 HTTP。每个活跃页面复用一条更新连接承载多个对话，不按对话各开连接；跨标签页共享连接是否值得引入 worker，由连接限制与真机验证决定。出现高频双向交互、二进制实时数据或可复现的链路劣势时，重开更新通道选择，保持上述业务契约。
