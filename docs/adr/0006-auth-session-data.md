# 单管理员、服务端会话与私有数据目录构成身份边界

## 背景

中书是单用户、可自托管的私人工作台。私有内容和执行能力必须在服务端认证后开放；浏览器隐藏按钮、客户端地址头或本地文件路径都不能构成授权。备份与恢复还必须处理一个特殊窗口：备份中的待派发操作在备份之后可能已经执行。

## 决策

- **单管理员**：没有公开注册、默认密码或浏览器密码重置接口。初始化和重置只在可信终端通过 CLI 执行。
- **服务端会话**：登录成功后轮换会话；服务端保存随机 token 的 SHA-256 摘要。浏览器使用 HttpOnly、Secure、SameSite=Strict Cookie，不使用 localStorage 保存认证秘密。绝对有效期 7 天；退出只吊销当前会话，重置密码或恢复备份吊销全部会话。
- **密码与限速**：密码使用 Node 原生异步 scrypt 与随机盐，散列并发受限；登录限速持久化，重启不清零。
- **来源与 CSRF**：`ZHONGSHU_ORIGIN` 必须匹配浏览器访问的完整 HTTPS origin；服务端检查写请求来源，并验证会话关联的 CSRF token。应用不信任客户端转发的地址头。
- **开发例外**：只有显式 `ZHONGSHU_ALLOW_HTTP_LOOPBACK=true`，且 origin 与监听地址都是 loopback 时才允许 HTTP；开发 Cookie 使用独立名称，不用于公网。
- **数据目录是信任边界**：目录 0700，数据库与备份 0600，运行账号拥有它们。宿主机管理员和应用进程可以访问数据库；未来的 Harness 执行身份不能获得该目录。
- **备份与恢复**：使用 SQLite 在线备份 API，验证备份后保留，不覆盖已有文件。恢复只写入尚不存在数据库的新目录；先在私有暂存库吊销旧会话并执行产品恢复处理，再原子发布。备份中的 queued/dispatching 操作在恢复时一律转为待核实，不重新派发。
- **迁移**：有序执行，记录 SQL 摘要；不允许改写已应用迁移、跳号或用旧程序打开更新的 schema。失败回滚并拒绝启动私人服务。
- **审计**：只记录动作类别和时间，不记录密码、token、用户正文或原生完整响应。

## 后果

- 身份与数据边界简单、可审计，适合单用户自托管；代价是没有多用户协作和细粒度角色。
- 恢复旧备份不等于恢复原生执行现场；SQLite 备份不包含工作区文件或 Harness 数据/账号。
- 备份包含密码摘要和私有状态，必须按身份数据保护，不能作为普通 PR 附件上传。
- 具体命令与运维步骤属于操作者实例记录，不进入产品文档；用户行为见 [access feature map](../features/access.md)。
