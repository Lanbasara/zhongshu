# 可获取正文形成永久阅读存档，执行与完整性分别核实

## 背景与适用范围

中书用于按年积累对话。只有用户翻阅才复制旧正文，会让尚未阅读的内容依赖原生记录的寿命；一次追平失败又丢掉本次进度，会使积压越大越难恢复。用户已确认后台保存全部仍可获取的正文、接受增加的磁盘与同步成本，并要求在上线前解决长期积累问题。

本决定将 [ADR 0003](0003-local-persistence.md) 的历史持久投影扩展为[阅读存档](../../CONTEXT.md)。SQLite、原生上下文和工作区文件的归属保持原决定；目标尚未全部实现，现状见[架构地图](../architecture.md)，本轮交付见[长期使用规格](../spec/long-term-performance.md)。

## 决策

### 存档归属与任务来源

中书后台持续保存所有已绑定对话中 Harness 仍可提供的正文，包括从未翻阅、已从主列表归档、已停用工作区中的可授权读取历史。工作区停用不因此恢复文件访问或执行权限。任务来源是中书持久化的原生绑定清单；原生对话列表只用于交叉核对，列表结束不能证明绑定集合完整。

已提交的正文是永久数据，不参与内存或缓存淘汰；原生上下文压缩、原生记录删除、视图归档和观察连接释放均不删除已存原文。已无法获取的内容必须记录缺口。永久存档承诺是保存可获取正文及必要来源、身份、版本和覆盖关系，不是保存每个流式中间版本，也不意味着恢复原生模型上下文、工作区文件、外链内容或尚未支持的附件种类。现有已关联图片继续遵循原资源持久性承诺。

### 三种事实独立

| 事实 | 含义与权威 |
| --- | --- |
| 原生执行状态与操作回执 | Harness 的实际接收、排队、执行和指定运行终态；遵循 [ADR 0004](0004-recoverable-communication.md) |
| 已存正文与覆盖范围 | 中书已成功提交并核实的内容和连续区间 |
| 当前同步进度 | 正在扫描的边界、续传位置、失败原因与重试安排 |

历史同步失败不撤销仍然有效的执行证明；原生失联仍须撤销受影响的执行证明。正文出现不自动证明对应操作已完成，页面翻到末尾也不证明运行中回复已经完整。

### 可恢复同步

1. 每段对话分别调度最新内容同步和旧历史回填。任务由服务端持有，页面关闭不暂停它们；当前结果优先，旧历史通过公平调度持续获得处理机会。
2. 持久化原生绑定、来源代次、扫描截止边界、续传游标、已覆盖区间和已核实完成正文的水位。续传游标与完整性证明分开；不把某次 opaque cursor 的格式当成长期协议。
3. 以有界页为提交单位。条目身份、正文引用、覆盖变化与下一页进度在一个短事务内发布。失败重读相同页并幂等合并，不清空已经提交的进度。
4. 正文按块存储。大正文可以跨事务暂存；全部块和摘要校验完成后才发布对应版本。进程中断或磁盘写入失败不得留下指向不完整正文的已完成清单，也不得提前推进覆盖水位。
5. 原生条目 ID 用于去重，内容版本用于检测变化。活跃流式内容与已完成正文分别处理；同一绑定的正文发布统一校验版本、来源代次与水位，最新同步和旧页回填不能互相覆盖较新结果。来源没有可比较版本时重新核对，不以读取完成时间或字符串长度推断新旧。原生历史重写或身份分歧进入核对，不以删除已存正文消除差异。
6. 任务终态后必须再次读取最新正文，直到该轮可获取的最终内容已核实。旧页扫描结束只证明所声明截止范围；继续出现的新轮次另行推进水位。
7. 游标失效时从可核实的重叠条目重新建立扫描，必要时重新遍历并去重。来源缺失或无法连接的区间保留为缺口，不伪造完整。重试有退避和资源预算，单个故障对话不得阻塞其余任务。

### 容量与恢复

容量治理同时计算应用配额、实际磁盘余量，以及数据库、WAL、正文块、资源和暂存开销。正常、提前告警、停止新增和恢复应有明确阈值与回差；为已受理工作收尾、状态落库和管理恢复预留空间。具体阈值属于可配置运行预算，不固化为对话、消息或工作区的累计寿命上限。

达到停止新增阈值时，拒绝新增工作和上传，保留阅读、停止、核对、导出及管理恢复入口；已受理任务不因容量原因自动取消。优先保存其状态和结果，旧历史回填可以暂停。永久存档不自动删除；仅可回收可重建缓存及已确认无引用的暂存块。恢复空间后沿原任务续传，不能要求用户翻阅旧页才能继续。

有限空间无法承诺无限输出：即使预留空间仍遭物理写满，也必须保留最后成功水位和明确的写入失败，不能把未落盘结果标成已存档。此时不得声称已提供完整保存保证。

备份包含同一一致性快照内的正文块、已发布清单、绑定、覆盖关系和任务进度；恢复后先验证引用和内容，再恢复同步。备份不恢复原生执行现场；未决操作遵循 [ADR 0006](0006-auth-session-data.md)，不得重派。迁移旧库保留已有正文和身份，将未经核实范围标为待补齐；旧的已加载标志不能转换为全量完成。

## 取舍与替代方案

- 只保存翻阅过的历史成本较低，但把正文寿命交给原生记录和用户阅读习惯，不能满足长期存档要求。
- 一次性追平便于实现，却把积压量变成单次内存、超时和失败成本；逐页提交允许有界推进和恢复。
- 保留 SQLite 的一致性边界，元数据与正文分离、正文分块；暂不引入数据库与外部对象存储之间的第二套提交协议。
- 代价是持续磁盘增长、后台 I/O、完整性元数据和备份开销。使用预算与背压控制工作速率，不能靠静默截断正文控制成本。
