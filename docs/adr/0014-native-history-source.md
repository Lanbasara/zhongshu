# 原生 Harness 是对话历史的唯一来源，中书不保存正文副本

## 背景与依据

2026-11-06，用户以“长期使用、活的产品”为目标审视长对话，并在对齐中确认本决定。当时中书用 SQLite 持久投影保存展示历史，并要求本地历史连续：同步从最新页向前读，直到与投影相交为止。在真实 Workbench 与存储上做的实验确认了三类停摆：
- 原生在中书未观察期间新增超过 1000 条（或 16 MiB）时，对话持续“待核实”且不可发送；自动重试与手动重连都不能恢复，最新内容始终不可见。
- 单对话投影达到 50,000 条后，同样停摆。
- 每次同步的成本随投影规模线性增长。

此外，浏览器最多保留 500 条并要求“回到最新内容”，不能连续回溯。

两个原生的官方客户端都以原生为历史来源：
- Codex App Server 要求 `thread/resume` 使用 `excludeTurns`，再以 `thread/turns/list` / `thread/items/list` 分页。读取历史不需要加载线程；分页线程的历史由 App Server 维护带索引的存储。
- DSH 客户端先 `follow`，再以按轮对齐的 `loadOlder` / `loadThrough` 读取更早历史，并用尾页修复缺口；客户端的观察不建立持久历史。

依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Codex 历史锚点](https://github.com/openai/codex/blob/rust-v0.166.0-alpha.5.1/codex-rs/app-server/README.md#item-history-anchors)、[DSH 会话事件流与分页](https://github.com/deepseek-ai/deepseek-harness/blob/504a01a9578abc2c6f1fb896b1dc322c9fe24f66/packages/api/session-controller/README.md)。这些是协议依据，不替代对目标版本的真实验证。

## 决定

- 对话历史正文的唯一权威是原生 Harness。中书不持久保存正文副本，也不要求本地历史连续。页面按需经 adapter 读取原生分页，用原生游标向更早（需要时也向更新）方向移动，可以持续回溯。
- 中书只保存自己拥有的事实：对话索引与配置、原生绑定、操作与回执、排队、用户上传及中书生成的资源、删除日志、子 Agent 索引与变更流。需要附加到正文的批注（用户原始输入、图片资源、本轮文件）按原生身份在读取时叠加。
- 浏览器只在内存中保留有界窗口；离视口较远的页面可以丢弃，之后按游标重取。实时更新与断线恢复都以原生最新页重建；旧响应不能覆盖新状态，[ADR 0004](0004-recoverable-communication.md) 的操作与回执契约继续有效。
- 原生不可用时显示“原生暂时不可用”，只保留当前页面已加载的内容；不承诺离线阅读旧历史。
- 翻页读取历史时，不为此加载或唤醒原生会话。实时观察仍由执行责任与阅读租约持有，见 [ADR 0012](0012-conversation-lifecycle.md)。
- 中书数据库设一个实例可配置的总预算，接近上限时提前提示。达到上限只拒绝会增加存储的动作（上传图片、新建对话）；阅读、在已有对话中发送文字照常进行，并给出清理入口（删除或归档对话、清理可再生的缓存）。
- 原生存储（Codex 会话文件、DSH 会话日志）不作为拦截条件。DSH 只能归档，中书不能释放它占用的磁盘。DSH 没有官方的用量接口，用户决定首轮不显示原生用量；将来需要时单独决定。
- 现有正文投影保留但不再使用，直到新读取路径在真实对话上验证通过，之后由后续迁移删除。

## 替代范围

- 替代 [ADR 0003](0003-local-persistence.md) 数据归属表中“产品展示的历史正文与同步水位 → 中书的持久投影”一行，以及“历史正文与短期事件补发窗口分开”中关于持久正文的部分。其他归属不变。
- [ADR 0004](0004-recoverable-communication.md) 契约 5 要求的稳定身份、分页顺序与完整内容入口，改由原生身份和原生游标承担。
- continuity 功能地图中 R04（有界窗口与回到最新）和 R06（断连时保留历史）的承诺，随实现更新。

## 取舍与后果

- 去掉了缺口补齐、容量上限和随投影增长的同步成本，与两个原生的官方客户端一致。代价是原生不可用期间，未加载的旧历史无法阅读。
- 每次翻页都要访问原生。Codex 分页线程走索引查询。DSH 冷打开仍按其实现读取完整会话日志，常驻会话的翻页在内存中完成；DSH 的一页会随工具事件增大，adapter 需要按字节预算读取，不能只按消息数估计。
- 原生改写历史（压缩替换、回退）时以原生当前视图为准，不再产生本地分歧。
- 跨对话的正文全文搜索不能依赖本地副本。将来需要时，依赖原生能力或另建可清理的索引，并单独决策。
- 本决定已经确认，但不表示已经实现。范围、迁移与验收归后续工作单。
