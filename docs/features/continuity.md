# 接续与阅读：feature map

范围：恢复同一对话、保留未确认输入、读取完整历史。跨设备/网络质量目标归[质量要求](../quality.md)，持久化与原生恢复语义归 [Harness 接入](../harnesses.md)。

## 用户入口与前提

侧栏选择既有对话；恢复网络后观察自动重连，也可点“重新连接”主动刷新快照和目录。历史顶部“查看更早的内容”，旧窗口中“回到最新内容”。切换对话或重开带对话 hash 的地址都应落回相应身份。

按[通用验证能力](../verification.md)准备自己的实例和浏览器。先通过[执行地图](execution.md)建立有确定内容、稳定条目身份的历史；验证运行中恢复时，先独立确认受控工具已经开始。长历史可用明确标记的原生替身准备，但必须仍由真实应用投影/HTTP/页面读取，不能只往 DOM 塞文字。

## 按影响选择驱动分支

| 子能力 | 驱动与预期观察 |
| --- | --- |
| 关页再回来 | 运行中关闭自己创建的页面，独立确认原生工作继续；重开同一对话，恢复其输出与真实状态。另一独立登录端可读取同一对话，不要求共享未发送草稿 |
| 中书中断 | 记录产品/原生身份，运行中只终止本次中书进程，保持原生 Host 存活；重启相同数据目录，确认原生身份、已保存历史和结果接续，无替代对话或盲目重派。温和退出与突然终止分别记证据 |
| 原生断连/重启 | 单独操作本次拥有的 Host，观察未知/受阻，再按原生持久状态核对恢复。这个场景与中书重启不同；不能用 Host 从未停止的运行证明 Host 崩溃恢复 |
| 草稿与未知回执 | 同一标签页输入后切换对话、刷新；各自草稿保持。发送结果未知按[执行地图](execution.md)核对，原始编号与正文保留，确认接收后不误清后来编辑的新文字 |
| 旧响应与持续输出 | 延迟 A 的快照，切到 B 再释放 A；B 不被覆盖。持续输出时状态与停止仍可前进；重连后稳定条目无重复，缺口明确补齐或报告待核实 |
| 历史分页与长正文 | 构造带唯一首尾标记的多页历史和长条目，逐页读取，核对完整正文、顺序、边界无漏/重，再回到最新。另测从空历史实时增长到超过窗口，入口仍可达；不能只测已有长历史首次加载 |
| 慢端与连接释放 | 在可控客户端注入慢读/断连，核对有界关闭和重新恢复；反复开关本次标签后订阅/连接回落。只有响应字节受限不能证明页面内存受限 |

## 容易误判的地方

- 草稿只保存在当前标签页的会话存储；关闭标签页、新设备与退出登录不承诺恢复未发送草稿。对话历史的服务端恢复是另一项能力。
- 新快照可能补齐结果，但不能由此宣称每个流式事件都已连续送达；分别判断最终完整性和及时反馈。
- “重新连接”按钮刷新 HTTP 读取，不直接重建 SSE；流重建由断连、心跳检查及页面/网络恢复触发。验证 SSE 恢复需观察更新流实际恢复，不能只凭按钮刷新后的内容。
- 桌面手机视口、合成大历史或本机网络故障只覆盖相应范围；Android 页面回收、真实 Tunnel 和 p95 预算须在对应环境运行。
