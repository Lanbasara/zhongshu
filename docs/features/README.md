# 功能地图索引

功能地图是给独立验证 Agent 使用的操作手册：回答“现在这个能力怎么到达、怎么驱动、怎样才算真的通过”。它只描述当前行为，不是需求、设计或状态文档；状态只看 [spec ledger](../spec/README.md)，决策看功能页链接的 ADR。

## 准入

一条能力进入本目录，必须同时满足：

1. 当前 commit 真的存在，用户可操作；
2. 有真实入口（按钮、路由、CLI、页面）；
3. 有可观察结果，并能说清“什么信号看起来像通过、其实不是”；
4. 能独立驱动，不依赖“你懂的”上下文。

未实现的能力留在 [spec](../spec/README.md)，不写成 feature map。

## 共同验证方法

每次验证按五段执行；证据放在 PR、CI 或操作者实验记录中，不写进本目录。

### Launch：独立现场

- 读 [README](../../README.md) 与本次功能页；确认源码、Node 版本、端口、数据目录和原生连接。
- 同时只启动一套本次验证现场。正在供用户试用的实例不是可销毁的测试夹具。
- 使用新的数据目录、合成工作区和自己的浏览器上下文；目录分离不等于操作系统沙箱。

```sh
npm ci --ignore-scripts
zh_verify_root="$(mktemp -d "${TMPDIR:-/tmp}/zhongshu-verify.XXXXXX")"
chmod 700 "$zh_verify_root"
export ZHONGSHU_DATA_DIR="$zh_verify_root/data"
export HOST=127.0.0.1 PORT=4391
export ZHONGSHU_ORIGIN="http://127.0.0.1:$PORT"
export ZHONGSHU_ALLOW_HTTP_LOOPBACK=true
unset ZHONGSHU_HARNESS_CONFIG
npm run admin -- init
REVISION="$(git rev-parse HEAD)" npm run build
node dist/server/main.js
```

管理员初始化使用真实终端的不回显输入；自动化可用 `--password-stdin` 从临时秘密通道提供随机测试密码。密码、Cookie、CSRF 和原生连接秘密不进入命令参数、截图、日志或 PR。

### Doctor：确认准备好了

- `/api/health` 返回 `status: ok`；`/api/version` 与本次构建关联。两项通过不证明登录或 Harness 可用。
- 打开本次 origin，确认登录页、登录和工作台；创建对话前检查工作区、模型、权限和连接状态。
- 保存仓库、base、HEAD、未提交 diff 摘要、构建标记、时间与环境。构建标签不是内容证明。

### Drive：由本次问题组合场景

- 功能页给出用户入口、前提及独立观察点；通过页面完成用户动作，CLI/API 只用于准备与读回。
- 按当前可访问名称定位，不保存易失的元素编号；等待具体状态或内容，超时保留最后事实。
- 修改前后运行受影响的基础检查；用户可见的验收仍由真实路径给出。

### Evidence：版本、观察和结论

每个结论至少包含：功能/子能力、预期、实际动作与观察、内容身份、环境/真实或替身边界、证据位置、清理状态。

- `PASS`：本内容和环境下，所选路径实际运行且观察符合预期。
- `FAIL`：路径已运行，保存预期与实际不符的证据。
- `BLOCKED`：尝试被具体前提阻止，说明缺少的工具、登录或服务。
- `UNCOVERED`：本轮未运行的分支、设备或环境。

测试全绿、服务 ready、历史 PR 通过或用户说“测试好了”都不能自动扩大为整项功能通过。

### Cleanup：只清理本次拥有的资源

- 停止本次应用终端/进程；核对端口已释放，关闭自己创建的浏览器标签与故障注入，清理自己的合成材料。
- 只对可核实归属的原生 Host 和受控工具做清理；停止应用、停止原生轮次与工具进程退出是不同事实。
- 保存所需证据；未确认归属时报告残留，不按端口或模糊进程名批量杀进程。
- 若用户明确要求保留试用环境，按交接要求保留；单次验证不借此清理用户原有实例。

## 跨功能验收

这些要求随能力首次出现就验收，不设“功能先完成、最后再补稳定性”的阶段。

| 场景 | 用户应观察到的结果 |
| --- | --- |
| 命令受理后响应丢失，再次提交 | 核对同一操作，不产生第二次派发；原生结果无法确认时明确待核实 |
| 输出中断网、重复补发、游标过期 | 已保存内容不丢、不重复显示；缺口通过补发或快照恢复 |
| 页面关闭、切换对话、Android 后台或页面回收 | 服务端工作继续；重新打开恢复同一对话，展示真实运行或等待状态 |
| 应用或原生进程中断 | 依据可核实事实恢复；无法继续的工作明确失败或待核实，不能假装完成 |
| 两端回答同一问题或处理同一审批 | 一次有效处理，另一端看到结果；旧请求失效 |
| 退出、会话过期、恢复旧页面 | 私有接口和对应更新流失效；不再暴露新的私有内容 |
| 旧历史加载、持续输出、切换页面并发 | 阅读锚点稳定，旧响应不覆盖新页面；离开后释放请求与订阅 |
| 慢客户端、多标签页、长时间运行 | 队列、内存与连接数量有界；超限有可恢复的明确处理 |
| 手机中文输入、键盘、附件与发送失败 | 无误发送、无输入丢失；输入框可见，焦点与操作反馈连续 |

起始性能预算（工程建议，未实测）：输入/发送/切换的本地反馈 p95 ≤ 100 ms；冷开到首批历史可读且输入可用 p95 ≤ 3 s（下行 10 Mbps、上行 1 Mbps、RTT 150 ms）；事件到达浏览器到绘制 p95 ≤ 100 ms；短断线恢复 p95 ≤ 3 s；服务端普通读取与操作受理 p95 ≤ 100 ms。样本、设备和测量方法在具体验证中记录；未实测的预算不称为已达标。

## 维护

- 入口、行为、驱动方式或前提变化时，同一改动更新对应地图。
- 地图不写状态和未来；状态在 spec ledger，未来在 spec。
- 发现产品回归应报告并修复产品；缺少前提应记录阻断；不能删去失败路径来让地图显得正确。
- 能机械检查的结构由 `npm run check:docs` 保护；语义准确性由 review 判断。
