# Feature map：从用户行为进入实现与验证

这张地图记录当前已有的能力。按本次改动选择用户路径，读该页的前提、驱动方法和判断依据，再沿实现与回归入口深入。它不汇总完成率，也不把一次通过变成长期的验收状态。

| 用户要做什么 | 地图 | 何时连带读取 |
| --- | --- | --- |
| 登录、刷新后继续访问、退出 | [私人入口](access.md) | 修改认证、会话换代、私有 HTTP 或 SSE |
| 选择工作区、Agent、模型与权限，创建对话 | [创建对话](conversations.md) | 修改原生目录、配置、绑定与初始化恢复 |
| 发出工作、接着追问、必要时停止 | [执行与停止](execution.md) | 修改派发、回执、原生轮次、队列或状态映射 |
| 离开后回来，恢复输出、草稿和更早历史 | [接续与阅读](continuity.md) | 修改订阅、重连、分页、持久化或浏览器并发 |
| 备份恢复实例、确认运行版本 | [实例数据与版本](instance.md) | 修改管理员 CLI、迁移、构建或容器生命周期 |

## 一次迭代怎样使用

1. **修改前选行为。** 写出受影响的子能力和预期观察。跨边界修改连带选择相关地图：例如 DSH 权限映射同时影响创建后的首条发送；认证影响工作台和更新流；历史存储影响恢复与分页。地图是起点，调用关系仍需从代码确认。
2. **准备验证现场。** 按[通用验证能力](../verification.md)选择真实表面与前提，再按功能页组织正常路径和相关失败路径。现有测试提供快速反馈，不能替代真实用户路径。
3. **运行并留下证据。** 将实际版本、环境、动作、观察及未覆盖项记录在任务或 PR。没有运行的场景保留未验证；本页不存放会随版本失效的通过标记。
4. **同一改动维护知识。** 入口、用户可见行为、驱动前提或陷阱变了，更新对应地图；职责变化更新架构，重要取舍更新 ADR。纯内部修改且地图仍准确时，无需为凑流程改文档。

新增功能按一条可独立驱动的用户路径选归属：能放进现有页就补子能力，读者需要另一套前提与入口时再拆页，并在此登记。删除或合并功能时同步处理入口和原有验收保护。新增文件与测试不要求机械地产生同名地图。

## 知识归属

- 功能页保存用户入口、可组合的驱动线索、观察点和容易误判的地方。
- [架构地图](../architecture.md)保存模块职责与依赖；[Harness 接入](../harnesses.md)和[身份说明](../identity.md)保存运行契约与配置；[质量要求](../quality.md)保存跨功能目标与预算。
- [通用验证能力](../verification.md)保存现场准备、证据与清理；测试文件保存确定性断言；单次运行记录归任务、PR 或 CI。
- [交付路线](../plans/README.md)保存未实现的后续路径。当前没有运行中追加、完整审批/提问、成果阅读编辑、附件、搜索或语音能力，不能因地图包含相邻入口就视为已有。

源码中的地图与验证方法可随独立克隆使用。操作者若使用外部 DUNE profile，其 capability 只补充本机启动、账号和证据位置，并链接这些功能页；不复制一套产品行为正文，也不要求其他贡献者安装 DUNE。
