# 实例数据与版本：feature map

范围：操作者初始化/重置、备份恢复、核对运行版本。命令和数据契约的唯一归属是[身份说明](../identity.md)，构建/容器入口归[开发流程](../development.md)。本页不提供真实实例的发布授权或配置。

## 入口与前提

管理员通过终端运行 `npm run admin -- --help` 查实际 CLI；浏览器登录页页脚与公开 `/api/version` 核对运行版本，`/api/health` 只核对服务存活。使用[独立现场](../verification.md)的测试身份、数据目录和私有备份目录；命令参数显式指定目标，避免默认目录。

| 子能力 | 驱动与应观察到的事实 |
| --- | --- |
| 初始化与重置 | 全新目录初始化后走[私人入口](access.md)，重复初始化应拒绝且原身份未改；重置后旧会话失效，新密码可登录 |
| 普通重启的数据保留 | 在自己的实例创建对话并完成工作，停止/重启应用；身份、对话、操作和历史保留，原生身份一致。运行中恢复另沿[接续地图](continuity.md) |
| 在线备份与新目录恢复 | 用真实 CLI 对运行中的临时库做备份，恢复到新目录；停止旧应用后将同一 origin 的应用指向新目录启动。旧浏览器会话拒绝，重新登录能看到备份时内容，原目录保留；已存在目标库不得被覆盖 |
| 恢复后的待派发工作 | 准备可控的 queued/dispatching 窗口及备份，再让原实例继续执行，随后只在测试现场恢复备份；恢复出的待派发记录变为待核实，不重复执行。缺少精确窗口时以相关测试辅助，不虚构真实恢复证据 |
| 迁移与坏输入 | 在临时副本验证迁移失败/更新 schema/损坏备份会拒绝，不留下部分发布的恢复库；保留原件，不在用户数据上造故障 |
| 构建与运行身份 | 对确定内容构建后检查页脚和 `/api/version` 对应本次 revision；容器检查再验证重建后的同一持久卷。构建号相同不自动证明工作区干净或部署成功 |

## 实现与检查入口

- [CLI](../../src/server/admin.ts)、[数据库](../../src/server/database.ts)、[迁移](../../src/server/migrations.ts)：[auth 测试](../../test/auth.test.ts)和[恢复操作测试](../../test/workbench-store.test.ts)。
- [构建](../../scripts/build.mjs)、[版本 API](../../src/server/app.ts)、[Compose](../../compose.yaml)：[HTTP 测试](../../test/http.test.ts)及[真实容器检查](../../scripts/check-container.mjs)，完整调用/清理以 [CI](../../.github/workflows/ci.yml)为准。

证据保存目标目录的角色、命令退出码、版本读回、脱敏的恢复前后计数与浏览器身份观察。备份含私有内容和密码摘要，不能作为普通 PR 附件上传。容器检查只使用它声明的新临时项目，不能套在日常实例上。

## 容易误判的地方

- 中书 SQLite 备份不包含工作区文件或原生 Harness 的数据/账号；能登录恢复库不等于原生执行现场已恢复。
- 普通重启与从旧备份恢复采用不同的待派发处理，不能互相替代验收。
- 本地构建、容器检查、main 集成和生产发布是独立事实；真实实例升级仍走操作者提供的发布入口。
