# 创建对话：feature map

范围：从操作者允许的工作区与实际原生目录创建一段配置固定的对话。配置格式与原生边界归 [Harness 接入](../harnesses.md)。

## 用户入口

登录后点“＋ 新对话”或“开始新对话”，填写名称，选择工作区、Agent、模型、权限，再点“创建对话”。以当前目录提供的选项为准；工作区登记和原生账号登录不在这个表单里。

## 前提与可驱动分支

使用[独立验证现场](../verification.md)，为 Codex、DSH 分别准备内容相同但目录独立的合成工作区。先确认 Host 已登录、配置可读、目录真实存在；本页与[执行地图](execution.md)组合，创建成功后实际发送首条消息才能确认可用。

| 子能力 | 动作与应观察到的独立事实 |
| --- | --- |
| 目录与创建 | 从页面选择本轮实际可用配置，创建后进入同一个标题/对话；通过服务端持久记录与原生只读状态核对工作区、绑定和配置。浏览器只暴露工作区 ID，不泄露原生连接秘密 |
| 空对话恢复 | 创建后先不发消息，刷新并重启本次应用，再打开同一对话后发首条消息；仍使用原生同一身份。特别覆盖 Codex 空会话持久化，空历史不表示读取失败 |
| 权限变化后的首条发送 | DSH 选择与 Host 默认不同且适合测试工作区的权限，创建后发送一条合成请求；权限设置产生的已知被动上下文不应锁住发送。原生真实待处理输入仍须阻塞，按[执行地图](execution.md)核对 |
| 回执未知或部分失败 | 在可定位的创建/配置窗口中断连接，页面“核对创建结果”沿同一编号核对；一旦取得原生绑定就保留，未核实配置前不能发送。核对绑定/原生创建次数，不能只看侧栏有一条 |
| 原生不可用或配置漂移 | 断开自己的 Host 或在自己的测试对话改变原生配置；页面如实显示未连接/待核实并阻止新消息。恢复连接需核实原绑定，不暗换工作区、模型、权限或新建替代对话 |

保存本轮选择、页面状态、脱敏的产品与原生身份对应及首条消息回执；异常分支保存故障发生点和创建次数。前端错误先比对实际提交字段；请求正确但原生配置错误再进入 adapter。

## 容易误判的地方

- 仅以默认权限创建可能漏掉权限切换产生的原生上下文；既往“能创建”不证明新权限组合可发送。
- 当前四项配置按对话固定；修改既有会话配置不是验收步骤。漂移测试通过原生测试现场制造异常，不将其描述成产品功能。
- 重试沿原身份核对；当原生创建结果本身无法确认时，明确受阻比自动重建更可信。
