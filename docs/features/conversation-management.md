# 工作区与对话管理

## Sub-features

M01 工作区分组与接续，M02 搜索与重命名，M03 归档与恢复，M04 忙碌与并发，M05 桌面宽度与手机导航。

## How to get to it (user POV)

登录后从侧栏进入。已登记工作区各自显示最近的对话及「显示更多对话」（在现有行下继续展开），工作区标题可收起列表，「＋」在新建表单预选该组。仍保存有对话的旧工作区可在「未登记工作区」找到，能否继续执行取决于其原生连接配置。

## Driving it with Harness

使用[共同入口](README.md)准备隔离 fixture 或真实 Harness。所有标题和消息均使用合成内容。开始前记录被测版本、每段对话的 hash 和所属工作区。测试归档或恢复前记录目标身份，操作后从列表重新打开，再以同源快照和 `inspect` 独立核对历史和原生身份。

| 场景 | 动作和判据 |
| --- | --- |
| M01 分组与旧对话 | 用「＋」在 Fixture A 新建并等待七段对话就绪，首段用唯一中文标题并发送一条消息后用 `complete` 完成。Fixture B 在未使用时显示「暂无对话」。点 A 的「显示更多对话」，核对七条同时可见，再打开首段并核对原历史、选中项与 hash。折叠 A 后正文保持。再用 B 的「＋」检查表单预选 B，创建后核对归属。 |
| M02 搜索与重命名 | 刷新使 A 恢复默认列表。搜索首段标题，核对结果所属工作区和 hash。点「管理对话」并保存新的中文标题，第二个页面只用新标题能找到这段对话。用两个不同的搜索词快速切换，最终结果只匹配最后的输入。 |
| M03 归档与恢复 | 在已就绪且无未决操作的对话行打开「管理对话」并点「归档对话」。主列表和未归档搜索中消失。在「已归档」中搜索、打开旧历史并核对 hash，正文显示归档提示。保留 root 重启应用，确认仍可在归档视图找到。点「恢复对话」后在主列表打开，再发送一条消息，用原生身份、历史与调用次数确认接续。fixture 先验证产品路径，Codex 与 DSH 原生分支各核对一次。 |
| M04 忙碌与交错 | 发送后等 fixture 显示运行中再尝试归档，应保留主列表入口并提示原因。再用两个页面从已就绪对话同时发起发送和归档，记录两端动作与结果。如果发送先接收，归档应被拒绝。如果归档先保存，新发送被拒绝且输入保留。分别用真实 Harness 核对其等待输入状态，前提缺失时标记受阻。 |
| M05 宽度与移动端 | 创建足够长的标题，核对侧栏没有被标题撑宽，行操作可点。桌面拖动分隔线，刷新后核对测得宽度，聚焦分隔线用左右方向键调整。缩窄窗口验证正文可操作。在手机从「打开对话导航」走通搜索、归档恢复及返回正文。窄视口只证明布局与操作路径，真实设备单独记录。 |

## Gotchas

搜索只查标题。旧对话和归档结果从服务端查询。主列表按创建时间排序，侧栏宽度保存在当前浏览器。归档对话的历史仍可读，新提交必须先恢复。
列表以游标分批读取，界面不显示页码或上一页/下一页。工作区组内继续展开对话，工作区、搜索和归档列表滚动接近边缘时续读；浏览窗口和查询缓存有界，见[界面缓存上限](../architecture.md#界面与设计系统)。离屏与收起的组不挂载对话行。已访问的归档/未归档视图保留数据和位置；新鲜缓存不重复读取，过期或收到变更时在已有内容上核对，不先清空列表。
M01/M02 的规模分支使用 [R07 的离线合成存档](continuity.md#r07完整正文与复杂内容)：10,001 段对话、300 个工作区，其中一个工作区有 1,000 段对话。用精确标题 `Navigation 0000001` 找到此前未加载的旧对话，再从所属工作区继续展开；滚动到其他工作区后，当前对话标题仍显示正确归属。分别观察列表请求条数、响应字节、当前 DOM 行数和已有草稿，不能用累计加载所有页换取搜索正确。此数据没有对应真实原生会话，发送接续仍按 M03 的原生分支单独验证。

M01 折叠偏好回收：在上述超过预算数量的工作区现场，保持同一页面，沿列表滚动并真实点击每个工作区标题，保存点击顺序与展开状态；滚动后不刷新页面。可只读观察 `ConversationNavigation` 的 `collapsed` Map，按[界面缓存上限](../architecture.md#界面与设计系统)核对平台值，不能注入状态或响应。最近偏好在滚动返回后保持，最旧偏好淘汰后使用默认展开规则，重新操作仍可记住；当前对话与草稿不改变。另在独占 fixture 的同一工作区页准备 50 组、每组七段就绪对话（合成目录登记与空对话创建可用经过认证和 CSRF 的产品接口），逐组展开，确认每组只加载六条并可继续展开第七条；统计整个页面实际 DOM，不因用户展开更多组而一次取全组历史。批量前置仅适用于自己拥有的合成现场，浏览器驱动仍须真实点击；它不替代 M01 的创建/接续旅程。

M01 空列表与事件范围：保持一个已加载的空工作区展开，在另一工作区的对话发送、完成、重命名或归档。用真实浏览器请求记录和 DOM 观察核对：空工作区不因别处的事件重复查询，“暂无对话”持续可见；发生变化的工作区及时更新。标准 fixture 的后台存档会继续产生进度事件，静置至少 30 秒覆盖两个存档周期，不能通过关闭 SSE 或阻止请求取得通过。随后在原空工作区从另一页面真实创建对话，新行必须自动出现；同一查询确需后台核对时，持有真实响应，“暂无对话”仍保留到新数据返回。记录初始加载与稳定观测区间，分开计数。

M01 缓存与被动刷新：在七段对话组展开到第七条，记录行和位置；切到「已归档」并返回，两侧已访问内容不得清空。30 秒内没有变更时不重复查询。需要观察过期核对时，用共同入口 `browser-faults` 对 `/api/private/workbench/conversation-search` 执行 `holdNext`，明确方法为 `POST`；由另一页面的真实创建/完成事件触发读取。持有响应期间旧行仍可点击，切到另一视图仍能操作；释放后不得混入错误筛选条件。记录请求条件、行 ID 和滚动位置，不记录认证头；最后恢复故障工具。M02 主动稀疏搜索仍显示进度并可暂停/继续，普通后台重读不自动跨空批次。
M02 在上述万段数据中记录非零扫描进度，点击暂停后核对最后确认的游标及请求停止，再继续查找并确认从该游标走到精确目标。稀疏搜索命中深处批次后，在另一页面真实创建/完成合成对话；后台刷新应从当前展示批次的起点读取，目标仍在，不能用初始空批次清掉已找到结果。分别记录主动扫描、暂停、继续和被动刷新请求的游标与条数；可对真实响应加延迟提供观察窗口，不改响应内容或直接改组件状态。

## Implementation and regression

- [侧栏与管理表单](../../src/web/conversation-navigation.tsx)负责宽度、分组与视图切换，[工作台](../../src/web/workbench.tsx)负责打开对话和草稿。
- [私有路由](../../src/server/workbench-http.ts)约束输入并沿用登录与 CSRF，[Workbench](../../src/server/workbench.ts)核对原生状态，[存储](../../src/server/workbench-store.ts)保存标题和归档标记，并在提交入队时检查归档状态。
- `node --test test/workbench-http.test.ts test/workbench-store.test.ts` 覆盖查询分页、迁移、认证与归档竞态。独立运行证据按[共同要求](README.md#独立执行验收)记录。

Codex 等待输入的协议回归可用 `node --test test/codex-workbench.test.ts` 复跑。测试对端通过本地 socket 返回原生等待标志，归档请求应返回 409，读回仍为未归档。测试对端结束等待后，同一请求应成功。真实 Codex 等待状态需另行触发并记录。

标题任意子串搜索先用创建时间/ID 索引扫描最多 200 条原始元数据（另取 1 条判定后续），再执行原有 SQLite 大小写语义的匹配；返回 `scanned`、`scanLimited` 和 `olderBeforeId`。无命中的批次仍可有后续，浏览器自动继续有界批次、显示已检查数量，并在批次间让出事件循环；找到非空结果页或游标为空才停止。可点“暂停查找”，再用“继续查找”从已确认游标接续。换词立即取消旧链路，晚到的旧响应不能发布；内存只保留有界的结果窗口。未登记过滤也沿该扫描游标继续。完成整个稀疏搜索仍随候选总量增长，不能把单页预算当作全库搜索总时延保证。

`node --test test/metadata-search.test.ts test/progressive-search.test.ts test/workbench-http.test.ts` 检查空批次、中文、字面 `%`/`_`/反斜杠和大小写匹配。`node test/support/metadata-search.ts <仓库外绝对输出路径>` 用产品 repository 命令分别登记 10,000/100,000 条合成元数据，以委托给原 SQLite 函数的计数器比较旧查询与实际分页查询的 predicate 调用数，并核对完整结果和清理；这不是浏览器或原生模型实验。
