# 工作区与对话管理

## Sub-features

M01 工作区分组与接续，M02 搜索与重命名，M03 归档与恢复，M04 忙碌与并发，M05 桌面宽度与手机导航。

## How to get to it (user POV)

登录后从侧栏进入。已登记工作区各自显示最近的对话及独立的「更早对话」，工作区标题可收起列表，「＋」在新建表单预选该组。仍保存有对话的旧工作区可在「未登记工作区」找到，能否继续执行取决于其原生连接配置。

## Driving it with Harness

使用[共同入口](README.md)准备隔离 fixture 或真实 Harness。所有标题和消息均使用合成内容。开始前记录被测版本、每段对话的 hash 和所属工作区。测试归档或恢复前记录目标身份，操作后从列表重新打开，再以同源快照和 `inspect` 独立核对历史和原生身份。

| 场景 | 动作和判据 |
| --- | --- |
| M01 分组与旧对话 | 用「＋」在 Fixture A 新建并等待七段对话就绪，首段用唯一中文标题并发送一条消息后用 `complete` 完成。Fixture B 在未使用时显示「暂无对话」。翻到 A 的旧对话页，打开首段并核对原历史、选中项与 hash。折叠 A 后正文保持。再用 B 的「＋」检查表单预选 B，创建后核对归属。 |
| M02 搜索与重命名 | 刷新使 A 恢复默认列表。搜索首段标题，核对结果所属工作区和 hash。点「管理对话」并保存新的中文标题，第二个页面只用新标题能找到这段对话。用两个不同的搜索词快速切换，最终结果只匹配最后的输入。 |
| M03 归档与恢复 | 在已就绪且无未决操作的对话行打开「管理对话」并点「归档对话」。主列表和未归档搜索中消失。在「已归档」中搜索、打开旧历史并核对 hash，正文显示归档提示。保留 root 重启应用，确认仍可在归档视图找到。点「恢复对话」后在主列表打开，再发送一条消息，用原生身份、历史与调用次数确认接续。fixture 先验证产品路径，Codex 与 DSH 原生分支各核对一次。 |
| M04 忙碌与交错 | 发送后等 fixture 显示运行中再尝试归档，应保留主列表入口并提示原因。再用两个页面从已就绪对话同时发起发送和归档，记录两端动作与结果。如果发送先接收，归档应被拒绝。如果归档先保存，新发送被拒绝且输入保留。分别用真实 Harness 核对其等待输入状态，前提缺失时标记受阻。 |
| M05 宽度与移动端 | 创建足够长的标题，核对侧栏没有被标题撑宽，行操作可点。桌面拖动分隔线，刷新后核对测得宽度，聚焦分隔线用左右方向键调整。缩窄窗口验证正文可操作。在手机从「打开对话导航」走通搜索、归档恢复及返回正文。窄视口只证明布局与操作路径，真实设备单独记录。 |

## Gotchas

搜索只查标题。旧对话和归档结果从服务端查询。主列表按创建时间排序，侧栏宽度保存在当前浏览器。归档对话的历史仍可读，新提交必须先恢复。
每个工作区、搜索结果和归档列表只渲染当前页。向前或向后翻页只读取目标页，收起的工作区及搜索时隐藏的工作区暂停刷新。验证大量数据时，在隔离实例准备合成对话，统计每次翻页的列表请求与当前页行数，并从搜索打开早于已浏览页面的标题。

M01/M02 的规模分支使用 [R07 的离线合成存档](continuity.md#r07完整正文与复杂内容)：10,001 段对话、300 个工作区，其中一个工作区有 1,000 段对话。用精确标题 `Navigation 0000001` 找到此前未加载的旧对话，再从所属工作区翻页；切换工作区页后，当前对话标题仍显示正确归属。分别观察列表请求条数、响应字节、当前 DOM 行数和已有草稿，不能用累计加载所有页换取搜索正确。此数据没有对应真实原生会话，发送接续仍按 M03 的原生分支单独验证。

## Implementation and regression

- [侧栏与管理表单](../../src/web/conversation-navigation.tsx)负责宽度、分组与视图切换，[工作台](../../src/web/workbench.tsx)负责打开对话和草稿。
- [私有路由](../../src/server/workbench-http.ts)约束输入并沿用登录与 CSRF，[Workbench](../../src/server/workbench.ts)核对原生状态，[存储](../../src/server/workbench-store.ts)保存标题和归档标记，并在提交入队时检查归档状态。
- `node --test test/workbench-http.test.ts test/workbench-store.test.ts` 覆盖查询分页、迁移、认证与归档竞态。独立运行证据按[共同要求](README.md#独立执行验收)记录。

Codex 等待输入的协议回归可用 `node --test test/codex-workbench.test.ts` 复跑。测试对端通过本地 socket 返回原生等待标志，归档请求应返回 409，读回仍为未归档。测试对端结束等待后，同一请求应成功。真实 Codex 等待状态需另行触发并记录。

标题任意子串搜索先用创建时间/ID 索引扫描最多 200 条原始元数据（另取 1 条判定后续），再执行原有 SQLite 大小写语义的匹配；返回 `scanned`、`scanLimited` 和 `olderBeforeId`。无命中的批次仍可有后续，浏览器自动继续有界批次、显示已检查数量，并在批次间让出事件循环；找到非空结果页或游标为空才停止。可点“暂停查找”，再用“继续查找”从已确认游标接续。换词立即取消旧链路，晚到的旧响应不能发布；内存始终只保留当前页。未登记过滤也沿该扫描游标继续。完成整个稀疏搜索仍随候选总量增长，不能把单页预算当作全库搜索总时延保证。

`node --test test/metadata-search.test.ts test/progressive-search.test.ts test/workbench-http.test.ts` 检查空批次、中文、字面 `%`/`_`/反斜杠和大小写匹配。`node test/support/metadata-search.ts <仓库外绝对输出路径>` 用产品 repository 命令分别登记 10,000/100,000 条合成元数据，以委托给原 SQLite 函数的计数器比较旧查询与实际分页查询的 predicate 调用数，并核对完整结果和清理；这不是浏览器或原生模型实验。
