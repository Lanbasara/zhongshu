# 对话基本可用性：feature map

这是**一个完整 feature**：用户在同一段对话中组织文字、图片和引用，读懂 Agent 的正文与执行过程，并在离开后接续。范围与产品取舍归 [spec](../spec/conversation-usability.md)；本页只维护如何到达、驱动和证伪，不按工程切片拆页。

本页覆盖当前图文消息、Markdown、工具过程、输入引用、技能与对话用量。一次运行证据保存在仓库外或 PR，不在地图维护通过记录；各分支须分别驱动，不能以页面存在推导验收成功。

## Sub-features

| 场景 | 要证明的用户行为 |
| --- | --- |
| U01 | 同一段真实对话完成图文/引用输入、工具执行、结果阅读及恢复接续的完整旅程 |
| U02 | Markdown 正文、代码、表格与流式内容清晰可读；围栏保持源码 |
| U03 | 按轮阅读工具摘要与详情，能区分运行、成功和失败，并找到最终正文 |
| U04 | 选取、粘贴、拖放图片，预览/移除/重试，实际交给所选 Agent |
| U05 | 查看正文图片及原生生成图片，放大并在刷新/重启后回看 |
| U06 | 引用已有消息选段，发送所选文字并保留其来源 |
| U07 | `@` 引用当前工作区原文件，Agent 读取原文件实际内容 |
| U08 | 失败、丢回执、刷新和切换对话时，文字/图片/引用草稿不串、不静默丢失、不重复派发 |
| U09 | 私有资源授权与寿命正确，既不越界读取，也不提前清理已关联资源 |
| U10 | 桌面/窄屏完成同一旅程；旧纯文本对话及既有创建/发送/停止/恢复路径不退化 |
| U11 | 对话轮末显示有原生编辑证据的文件，点开所属工作区中的当前文件 |
| U12 | 用 `/` 筛选本对话技能，确认后发送，核对原生调用和草稿恢复 |
| U13 | 在输入框下查看本对话累计 Token 与上下文占用，刷新、压缩和缺数据时仍能区分两者 |

编号用于引用验证场景。U01 是整体验收主线，U02–U13 是其针对性分支。分支证据各自注明覆盖的 Harness。

## How to get to it (user POV)

现有入口：按[共同入口](README.md)准备独立现场并登录 →“新对话”→ 选择工作区、Agent、模型与权限 → 创建并等待就绪，见 [C01](conversations.md)。

路径：在输入区组织文字、附图、引用消息选段或 `@` 工作区文件 → 检查预览与来源 → 发送 → 阅读流式正文及本轮工具过程 → 查看/放大图片 → 完整刷新或重新打开原对话 → 继续下一轮。打开“添加图片或文件引用”菜单后选择“添加图片”，也可以粘贴/拖放；在消息中选中文本后点“引用所选文字”，文件使用同一菜单里的“引用工作区文件”或输入 `@`。正文图片点“放大图片：名称”，以“关闭图片”返回。模型和权限仍按对话固定。

## Driving it with Harness

**对象与前提。** 沿用共同入口的 Launch/Doctor/Native/Evidence/Cleanup，识别源码/工作树、构建、实际 listener、origin 和 Host 精确版本。使用独立浏览器上下文、独立管理员/应用数据及允许的合成工作区，不停止、重置或改写用户试用实例。为 Codex、DSH 分别创建唯一命名的对话，保存产品/原生身份、配置及每个操作编号。真实模型使用显式时间预算；超时记录最后状态，不自动判产品失败。

**材料与预期。** 由可信端预先准备并保存：一份含标题/强调/链接/表格/任务列表/代码的 Markdown 样本及字节；一张包含独有形状、颜色与标记的合成图片及哈希；文件 A 的旧/新两版内容及哈希；消息选段的准确文字与位置。图片答案不写在文件名、替代文本或消息里。另备一个确实不存在的工作区文件，用于只读失败；越界检查只用自有合成 canary。保留预期不能靠 Agent 自己生成预期或自述成功。

**主线 U01。** 两个真实 Harness 各完整运行一次：

1. 创建对话并核实就绪，在同一输入中加入短文本、图片、消息选段与文件 A 引用；消息选段来自本次对话中预先发送的已知文字。核对可见附件、引用来源与删除操作，不只检查输入框外观。
2. 选择 A 后、发送前，可信端把 A 改成新内容。页面要求 Agent 识图、读取 A、执行只读成功命令和不存在文件的失败读取，并输出 Markdown 结果；不在请求正文泄露图片答案或 A 的新内容。保存该次操作 ID。
3. 对照原生输入/工具结果和可信预期核对识图、文件读取及工具状态；在页面读正文、展开/折叠本轮工具详情并放大输入图片。若该端具有原生图片生成能力，再生成并核对实际输出图片；没有能力须保留依据，不能把缺少生成工具误判为渲染通过。
4. 保存对话/操作/条目/资源身份及图片字节依据。完整刷新、重新打开原对话，随后分别重启本次应用和本次 Host；每次核对原绑定、配置、正文、工具与图片仍可读取，操作不增加。不能只凭缓存缩略图判持久化成功。
5. 在原对话继续一轮，核对同一原生身份及新操作恰好一次；再按 [E03/E05](execution.md)核验停止及后续可发送，独立记录后台工具是否退出。保存整段用户路径证据并交用户实际试用。

**针对性分支。** fixture 只证明其边界控制，不提供图片模型、生成资源或原生文件读取；上传授权与存储回归另见下列测试。渲染可用真实模型输出的确定样本；原生语义和资源访问仍须 native。所有发送、引用和预览操作走真实页面，不能直接写产品数据库或替换 HTTP 正文来“补齐”功能。

| 场景 | 初始条件与动作 | 判据与独立观察 |
| --- | --- | --- |
| U02 | 将预定样本作为真实消息内容驱动渲染，另有一份整体包在围栏里的相同 Markdown；观察流式未闭合内容、完成后历史、代码复制、宽表及长行 | 正文有语义标题/列表/表格；围栏仍为代码。复制字节与输入样本对应，完成与恢复内容不变，无整页横向溢出。模型把正文包进围栏时，先判输入样本不合格，不能靠前端剥围栏获得通过 |
| U03 | 同一轮执行真实只读成功与失败读取，观察运行中及终态，展开/折叠详情；再发下一轮 | 原生调用/结果 ID 与动作摘要、命令/输出/错误对应；轮间归属清楚，无凭空重复状态，折叠后最终正文仍可读。普通正文里的“工具成功”文字不算工具证据 |
| U04 | 用独立消息分别测试选取、剪贴板、拖放；检查预览，移除一次，再实际发送；另触发明确的上传拒绝并重试 | 三种入口均得到准确图片；被移除图片不进入原生输入，重试不多派发消息。核对原生图片输入及盲测识别结果，不能以文件名或临时预览证明真实传入。若自动化无真实剪贴板能力，单列缺失前提 |
| U05 | 分别查看授权图片资源、Markdown 图片及已有原生生成路径的图片；放大后刷新/重开/重启 | 取得对应真实图片字节或可靠内容依据，与所展示资源对应；记录生成前输出标识和生成后资源身份。新页面重新请求可读，失效/读取失败明确显示，不以自然语言、图标或 HTTP 200 代替图片 |
| U06 | 在两条含相似文字的消息里选择一段不同标点/换行的文字，加入引用，检查来源并发送；另移除后发送 | 原生实际输入含准确选段且来源对应正确消息；移除后不带选段，旧消息正文不被改写，刷新后已提交选段仍可回看 |
| U07 | 选择 A 后改成新内容再发送；独立对话分别测试文件删除、失去权限及指向禁止区的符号链接 | 原生真实文件读取得到新内容，页面来源仍指向 A；读取错误明确，不能用旧快照冒充成功。越界目标不可读，不能仅凭前端候选列表过滤判断服务端授权 |
| U08 | 混合草稿分别遭遇上传拒绝、存储失败、消息 HTTP 拒绝、发送回执丢失；切换另一对话再返回，分别在未发送与 pending 时刷新 | 上传失败不自动仅发文字；未能保留操作编号时不派发。pending 保留原编号及原提交内容/资源引用，同编号重试不重复执行，另一对话无草稿串入；明确拒绝后可编辑/重试。故障注入复用 [E04](execution.md)，图片/引用不在现有工具覆盖范围时补实测入口后再签结论 |
| U09 | 独立未登录端请求本轮资源，退出后再读；测试其他工作区/越界路径。对 pending 和已提交资源跨刷新/重启取回，并检查移除的未引用上传项回收 | 未授权读取被拒绝，无宿主路径任意读取；仍被操作/历史引用的资源不提前回收。清理依据见 [architecture 的资源生命周期](../architecture.md#消息与资源)；核对实际引用与资源存在性，不以数据库计数代替 |
| U10 | 桌面与窄屏运行 U01，操作输入增长、菜单、附件移除、放大及返回最新；加载升级前的纯文本对话，回归既有地图 | 关键操作可见/可达，长内容不挤掉输入，滚动/新输出不破坏阅读位置；旧历史/草稿按兼容约定恢复。桌面窄窗口不代表 Android 输入法、键盘或后台专项已验证 |

**识别失败与收尾。** 在独立旧版本或隔离副本移除目标渲染/资源映射，用相同输入与判据取得失败；恢复后必须再跑成功分支。图片不可读、实际上传拒绝和丢回执也要分别证明断言看得到故障。不能在工作实例做破坏实验或删断言换通过。

每次证据关联场景、版本/现场、前提、动作、独立预期、观察、对话/操作/调用/资源身份、未覆盖项与清理结果，按共同入口区分 PASS/FAIL/BLOCKED/UNCOVERED。异常先分清产品缺陷、驱动错误和缺少前提。清理前恢复注入、核对自有进程/资源归属并保留证据；pending 资源与用户文件不按临时上传项清理。产品完成仍需 U01 与相关分支合格及用户试用，不能用本页建立或通用测试通过签收。

### U11 本轮文件

1. 按共同入口分别启动 Codex 和 DSH 真实测试实例。在合成工作区创建两个子目录，各放同名 `sample.tsx`。再准备 `read-only.md` 与 `manual.md`。Codex 在提示中明确要求用 `apply_patch`，DSH 明确要求用 `write` 或 `edit`。第一轮先编辑一个 `sample.tsx` 两次，再编辑另一目录的同名文件，并只读取 `read-only.md`。让 Agent 用 shell 另写 `shell-only.md`，同时由可信端修改 `manual.md`。独立核对磁盘结果及原生工具记录。
2. 等轮终态。只应在轮末看到一张清单，两个同名文件各一项，路径能区分。只读、无可归因的 shell 写入及人工修改无条目。点两行分别打开，核对各自源码与真实磁盘内容一致。检查源码没有编辑入口，直接请求保存也被拒绝。第二轮改其中一份再恢复原文，该文件仍归第二轮。若使用[提前发送](execution.md#e06--e07-排队与提前发送)，按原生实际接收轮核对归属。
3. 完整刷新并重启本次中书应用，回看第一轮及第二轮。用可信端改写一个文件并移除另一个，再从第一轮分别点击。阅读器应显示当前内容，或提示不可用并保留清单路径。窄屏重开可读文件，核对底部面板、关闭返回与焦点。跨工作区同名、越界路径和符号链接不能读到其他位置的内容。

清单按读取到的原生编辑证据建立。旧历史尚未取得这些证据时继续显示原消息。单轮超过 500 项时，清单标明只显示部分记录。

### U12 技能引用

1. 按 [Native 入口](README.md#native真实接入分支)启动隔离 Host 和应用。在工作区 A 放 `zhi-proof` 与 `zhi-secondary` 两个技能，各有 `SKILL.md`、名称和简述。Codex 用 `.agents/skills/`，DSH 用 `.dsh/skills/`。给 `zhi-proof` 的正文放独有合成标记，DSH front matter 设 `disable-model-invocation: true`。工作区 B 保持空白。分别建两段对话并核对就绪。
2. 在 A 输入 `/` 再输入 `zhi`，用方向键切到 `zhi-proof`，按 Tab 并接着输入任务。完整刷新，确认强调的引用、余下文字与选择身份仍在。另测 Escape、无匹配时 Tab、输入路径或 URL、手打完整 `/zhi-proof` 后直接发送。原生收到的手打文本保留原样。390px 视口点按候选，继续输入。
3. 发送选中的 `zhi-proof`，查原生同一轮用户输入和指令内容。Codex 查 `rawResponseItem/completed` 或隔离 rollout 的 `response_item`，核对 skill 正文标记。DSH 用 `session/follow` 或 `session/page` 查 `user/message`，要求 `source.kind=skill-invocation`、名称及正文标记同时匹配。模型复述不是调用证明。按 [E06/E07](execution.md#e06--e07-排队与提前发送)跑排队派发和回执核对，检查原操作只出现一次。
4. 切到 B 再查 `/zhi`，确认 A 的技能不出现。选中技能后在实验现场使它从原生目录消失并核对原生清单，再发送旧引用。应拒绝调用并保留草稿或排队条目。点「继续编辑」或队列行的「编辑」，核对保留内容可修改后重发。若该 Host 对旧会话冻结技能范围，使用能改变清单的原生禁用方式或下方 fixture。未登录端请求 `/api/private/workbench/conversations/<id>/skills` 应被拒绝，已登录结果只含显示信息与不透明 ID。

### U13 对话用量

原生读回先核对绑定身份。在本次隔离应用中从浏览器地址取得产品对话 ID，以只读方式在本次 `zhongshu.sqlite` 按 ID 查询 `workbench_conversations` 的 `json_extract(binding_json, '$.id')`。只保留原生 ID 及本次合成用量证据。

1. 在 U12 的两端真实对话各完成两次模型请求。对照浮层累计值、已用量与窗口容量。Codex 从隔离原生连接记录 `thread/tokenUsage/updated` 的 `total.totalTokens`、`last.totalTokens` 和 `modelContextWindow`。DSH 查 `session/projections`，累计值为 `tokenUsage` 四项之和，上下文优先用 `contextPressure.projectedTokens`，回退用 `pressureTokens`。只读本次原生绑定。记录数值和百分比，区分近似显示与精确累计值。
2. 完整刷新、切到另一对话再切回，确认数据归属。用足够长的合成对话触发原生压缩，或从隔离 Host 请求压缩。DSH 可将约 26 KiB ASCII 合成材料分两条发送，每条少于 16,000 字符，再在该会话执行原生 `/compact`。核对原生事件和独立读数。占用变小时圆环与详情随之变化，累计值不因压缩降低。只有原生缺少容量或 fixture 分支可检验容量缺失。

**Fixture 分支。** 按[共同入口](README.md)建 Fixture A 和 B。A 提供上述两项合成技能，B 为空。对本轮唯一标题运行 `node test/support/feature-fixture.ts <disable-skills|usage-full|usage-compact|usage-total-only> --root "$zh_verify_root" --title '<标题>'`。`disable-skills` 后发送旧引用，核对草稿或排队条目保留，`inspect` 的接收操作 ID 未增加。依次运行三个用量命令，观察 `18% → 8% → 暂无数据`，精确累计值一直为 `176,222,262`，最后一次只显示累计入口。刷新后核对本对话数值，B 无用量。fixture 覆盖工作台与浏览器行为，原生调用与统计口径各用真实 Host 验证。

## Gotchas

- 本页覆盖一个 feature，不因 PR 或实现阶段不同建立重复地图；跨图回归引用原场景，不复制另一套定义。
- 工具条目的独立读回以 Harness 公开历史接口为准；原生底层转录里的嵌套子调用可能没有公开条目 ID，不能把工具组数量当作全部子进程数量，也不能为补齐数量编造条目。
- 原文件引用不冻结文件字节；消息选段保留所选文本。操作 ID/提交内容稳定，不等于被引用文件永不变化。
- 对话图片、Markdown 外链图片、原生生成图片可能走不同通道；一个通道成功不证明其他通道。不得放开任意 URL/文件读取来掩盖通道缺失。
- 检查的是整个工作区原文件与资源授权边界，不能通过共享中书认证目录或借用用户 Host 换取识图成功。
- 原生生成条目、模型“已生成”回复、占位图、缓存和网络成功都不是实际图片证据。没有原生生成能力与资源读取失败分开记录。
- 待核实消息可能已经执行，未知结果下不换操作 ID、不重发；模型能再次给出相同答案不能证明未重复调用。
- 普通同文档 hash 导航不保证页面切换；按共同入口使用完整刷新或新页，并核对实际标题/身份。
