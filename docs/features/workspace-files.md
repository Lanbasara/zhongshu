# 工作区文件阅读与编辑

## Sub-features

- 可编辑格式为 UTF-8 的 Markdown、TXT、JSON、YAML、TOML、INI，上限 256 KiB。原文编辑只挂载视口附近内容。Markdown 可预览当前稿件；超过 64 KiB 时默认打开原文，按需分页渲染预览；未保存稿件同样分页，过大的单个表格、代码块或段落用原文页显示。HTML 和 HTM 只读，上限 1 MiB。报告保留支持的结构、样式、静态 SVG 与嵌入位图。脚本和网络资源不加载。
- TypeScript、JavaScript、CSS、Python、Shell、Go、Rust、Java、C、C++ 和 SQL 的常用源码扩展名以 UTF-8 原文只读打开，上限 256 KiB。
- 目录仅接受已登记工作区内的相对路径。列表隐藏隐藏项与符号链接，文件内容拒绝符号链接、硬链接和特殊文件。独立目录索引单次响应最多 100 项，界面在当前目录连续滚动续读；首次扫描显示进度，重新扫描完成前继续提供上一代清单。窗口最多保留三个响应批次，离开窗口的旧条目回收；目录变动不承诺文件系统快照。
- 写入要求操作者满足 [受管 Host 配置前提](../../README.md#harness-connections)。首次接管旧绑定时按持久检查点完成原生基线核验；此后编辑只检查未决集合，不重复审计全部历史对话。相交的可写挂载属于同一冲突集合，进入窗口时一起冻结新受理，已经受理的固定集合继续派发并等待终态。失联、未知结果或无法证明退出时不开放保存，也不自动取消任务。
- Codex 与 DSH 的受管工作区点「编辑」先查看受影响的运行组及共用工作区提示，再点「开始编辑」进入持久编辑窗口。控制器证明相应专用 Host 已退出、独占文件写者就绪后才显示可编辑；写者冷启动计入进入窗口的等待。窗口中可连续保存多个文件。点「恢复 Agent 并结束编辑」或阅读器的「返回对话」会明确结束窗口并恢复；失败时保留阅读器和草稿。关闭浏览器标签页、断线或中书重启不会自动解除门禁，回到对话可点「结束编辑并恢复 Agent」。主动编辑暂停不把已核实的空闲历史改为失联，已完成且无未决操作的对话仍可归档。
- 所有受管保存经独立文件写者，先持久化保存身份、旧版本和新摘要，再替换文件并同步目录，最后记录结果。同一保存编号重试不会再次替换文件。写者崩溃后，新写者须取得同一稳定目录的操作系统锁，核对文件摘要后才结算；外部第三种内容保留为未知。文件版本包含内容和文件身份，旧版本提交被拒绝。
- 草稿留在当前页面内存。保存被拒绝时保留稿件。「重新打开」会在确认放弃草稿后读取远程版本。
- 在线 Host 异常退出时，持久门禁允许最多三次恢复；耗尽或结果未知时显示原因，禁止新发。没有编辑窗口且仍符合恢复条件时，原有「恢复 Agent」入口可明确重新尝试。编辑窗口不会被自动恢复解除；恢复进程也不会重新发送未知任务。

## How to get to it (user POV)

在已登录工作台的侧栏选择「工作区文件」。首次进入阅读器直接展开文件列表；再次进入同一工作区时重新读取上次文件并恢复阅读位置（只保留一个文件的位置，不缓存正文）。点顶部文件名按钮展开或收起文件列表浮层。选择文件后浮层关闭。桌面可并排或展开，手机从全屏阅读器返回对话。工作区可切换，已有对话仅用于预选所属工作区。

也可从对话结果末尾的「本轮文件」打开对应工作区的当前文件，见[本轮文件验收](conversation-usability.md#u11-本轮文件)。

## Driving it with Harness

遵循[共同入口](README.md#独立执行验收)。fixture 可从[标准启动入口](README.md#launch从干净克隆开始)启动，合成工作区位于本次 root 的 `workspace-a` 和 `workspace-b`，已启用条件保存。真实 Codex 与 DSH 按[真实 Host 前提](README.md#native真实接入分支)各跑一轮。使用全新的合成工作区和管理员会话，准备 Markdown、TXT、一个配置文件及一份有长文、宽表、图形的自包含报告。报告放在子目录，分别链接一个存在、一个不存在和一个越界的底稿。以测试专用的合成私有请求和脚本标记检查报告隔离。

受管编辑 UI 分支：标准 fixture 启动命令加 `--managed`，使用该参数重启同一 root。此模式运行实际门禁、协调器、SQLite 和独立文件写者，两个 Host/controller 为明确替身，不证明原生进程隔离。分别创建 Codex/DSH 对话，发送后用标准 `complete` 完成；核对阅读时无重复暂停说明；点编辑查看实际运行组，点继续阅读不得暂停 Agent；再点编辑和开始编辑、连续保存并独立读回，关闭阅读器后在原对话发送，核对绑定不变、没有重复提交。另在编辑中刷新浏览器，聊天区应显示恢复入口；恢复后再验证归档/恢复和统一按钮样式。运行中的任务申请编辑后须等待，不能自动 stop/drop；用 `complete` 完成后才能保存。

1. 从桌面和手机侧栏打开报告，核对版式和可读内容。从滚动后的位置点开工作区内的底稿，再返回，观察原位置。拒绝越界和不存在的目标，报告不发出私有请求，脚本标记不出现。
2. 双页面打开同一 Markdown 版本。在一端编辑、预览、保存，独立检查原文件字节并在另一页面重读。另一端保存旧版本时核对冲突、草稿及磁盘仍是先保存的版本。另测试 TXT、配置样本和 HTML 只读。
   另用合法中文/emoji 构造恰好 256 KiB 的 UTF-8 文本，保存后核对独立 SHA；增加一个字节须返回 `file_too_large`，NUL 与孤立代理项须返回 `file_encoding_unsupported`。这些输入在受理保存之前拒绝，不产生未决保存、不启动新写者、编辑窗口仍可使用。合法文本经过 JSON 转义可大于原文件字节数；用可转义控制字符构造边界样本，传输预算不得使其变成“保存结果待核实”。
3. Codex 和 DSH 分别从同一工作区的另一段对话执行可观察的合成任务。请求编辑后，核对已经受理的操作继续完成、新操作明确拒绝、正文仍可阅读，直接保存尚被拒绝。终态后窗口才进入可编辑。保存两次，关闭页面再打开，窗口仍在；明确恢复后验证同一原生绑定下一轮。另核对相交挂载的两个组一起冻结。
4. 核验实例能否启用原地保存时，在自有隔离工作区驱动有超时上限的后台写入工具。让父命令退出、原生对话回到空闲，用实际进程与文件字节证明后台写者仍存在。两个 Harness 各进入编辑，核对容器及后台写者退出，再保存、尝试释放旧工具，磁盘仍须保留手动内容。暂停或恢复结果未知时，保存和派发均被拒绝。原生空闲本身不能作为进程退出证明。

5. 性能复验分别记录首次基线、后续编辑、Host 退出和接近 256 KiB 文本的文件读回；已完成基线的空闲历史不应再次产生逐对话状态查询或聊天历史读取。40/1,000 绑定的受控规模入口见下方回归；实际原生规模须明确记录，不能互相替代。本次上线按 [ADR 0013](../adr/0013-bounded-recovery-acceptance.md) 复用已有 40 段原生证据，不扩展到 1,000 段。核对隐藏页停止轮询、原文和预览往返后选区与滚动保持。目录用 201 和 10,000 个真实文件逐页核对完整且不重复，显示条目不超过 300。
   输入控件用可访问名称“文件原文”定位，而非假定 textarea；控件在开放 ShadowRoot 中，原生 DOM 观测须进入该 root，挂载量包含其内部节点。另测 256 KiB、至少两万行，以及接近上限的单行；用真实粘贴和单字符输入测响应，记录实际挂载行/DOM，不能把直接修改 React 或编辑器状态当用户输入。验证撤销/重做、选择与滚轮滚动、中文输入、CRLF/混合换行、只读时禁止修改；带 BOM 文件在首部插字及全选替换后仍保留起始 BOM，保存后核对原文件字节。核对标准应用 CSP 下无样式拒绝。由短文件编辑出未保存的 200 KiB Markdown，先预览再保存，前后都应有分页；单个巨型表格/代码块须显示有限原文页，不能一次挂载整块。
6. 在一次性数据目录运行文件写者强杀测试，覆盖持久 intent 后、rename 后、结果记录后的三个窗口；重启后核对同编号没有重复 rename、实际字节与结果一致，第三种外部内容保持未知。另恢复产品库备份，核对身份吊销、执行门禁关闭、旧窗口和未知保存日志保留。恢复不能替换独立 Host ledger 或文件写者目录来绕过旧 owner。

## Gotchas

原生轮次状态与独立进程是否仍在写入分别核对。容器隔离工作区外的文件，仍需另外约束工作区内的后台写入。保存成功以实际文件字节为准。

## Implementation and regression

定向回归入口为 `node --test test/directory-index.test.ts test/execution-coordinator.test.ts test/execution-store.test.ts test/execution-workspaces.test.ts test/workspace-writer.test.ts test/resources.test.ts`。目录测试使用真实文件；执行 store 和 Workbench 测试使用真实 SQLite worker、文件和写者，但原生 Harness 与控制器使用明确替身，不能证明容器收束。文件写者测试使用真实子进程、操作系统锁及 SIGKILL。真实浏览器及两个原生 Host 按共同入口各自留证。

`node --test --test-name-pattern="historical conversations" test/execution-workspaces.test.ts` 通过产品存储 API 登记 40 与 1,000 个真实持久绑定，记录首次基线读取数及编辑、连续两次保存的增量调用数和耗时；基线后历史 state/watch 增量均应为 0，文件必须独立读回。该入口的 SQLite worker、登记、协调器和文件写者为实际实现，Harness/controller 明确为替身，不能替代上面的真实原生进程退出证明。
