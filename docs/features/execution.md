# 执行与停止：feature map

范围：发送文本、观察真实工作、接续下一轮和停止当前轮。发送/停止契约归 [Harness 使用与恢复](../harnesses.md#使用与恢复)，回到页面与历史阅读沿[接续地图](continuity.md)。

## 用户入口与前提

从侧栏进入已核实配置的对话，在“给 Agent 的消息”输入，点“发送消息”或用 ⌘/Ctrl + Enter；Enter 换行。运行时入口变为“停止当前轮”；回执未知时使用“查询原生结果”或“核对同一发送”。

按[通用验证能力](../verification.md)准备真实原生 Host，在独立合成工作区放一份 `notes.md`，写三条本轮自定事实。两个 Harness 分别跑，避免互改文件。停止/运行中场景准备一个有独立启动信号、释放条件和外部清理手段的短小受控工具；先确认确实处于运行中再操作，不靠固定 sleep 猜时机。

## 组合驱动与判断

| 子能力 | 动作 | 通过所需的观察 |
| --- | --- | --- |
| 完成真实工作 | 发出“读 notes.md，把三条事实写入 result.md”，观察正文、工具活动和终态 | 工作区中确有符合输入的文件，页面显示该轮真实状态；模型的自述和 HTTP 接收回执都不替代文件读回 |
| 同会话接续 | 首轮只在消息里提供本轮随机标记，完成后在原对话追问 | 在原生同一绑定中得到正确上下文，模型/权限保持；标记不从工作区文件补给 |
| 原生接收与完成分开 | 受控任务开始后观察发送入口；完成后再次发送 | 接收回执不提前开放下一轮；正确轮次终态得到核实后才允许新消息。后台通知产生新轮次时也不能永久卡住或绕过当前仍在运行的工作 |
| 回执未知 | 精确地让原生已收到、但回执未被确认，再点核对 | 原操作编号不变、原始输入保留；核对原生消息/关联身份确认没有第二次派发。只有最终文件一份不能证明未重复执行 |
| 停止当前轮 | 独立确认受控工具在运行，点击停止 | 核对目标原生轮次终态与 UI；另外读回受控工具是否还活着，分别记录。保留原生队列，工具仍存活时由本次现场拥有的清理手段处理 |
| 等待、队列与权限漂移 | 在自己的现场制造相应原生状态，再尝试发送 | 状态如实展示，未支持的交互不静默批准，新消息受阻；已知 DSH 被动权限上下文的例外沿[创建地图](conversations.md)，未知输入仍保守阻塞 |
| 输入反馈 | 空白、中文组合输入、换行、有效快捷键及超长输入 | 无误发送；拒绝/未确认时输入保留，明确未发送与未知结果。真实 Android 输入另行取证 |

## 实现与回归入口

| 要改的边界 | 入口与辅助检查 |
| --- | --- |
| 输入、草稿、操作编号与反馈 | [页面](../../src/web/workbench.tsx)、[客户端](../../src/web/workbench-client.ts)；需要浏览器驱动，目前无独立前端测试套件 |
| 受理、顺序与回执核对 | [Workbench](../../src/server/workbench.ts)、[存储](../../src/server/workbench-store.ts)、[HTTP](../../src/server/workbench-http.ts)；对应 [service](../../test/workbench.test.ts)、[store](../../test/workbench-store.test.ts)、[HTTP](../../test/workbench-http.test.ts) 测试 |
| 原生状态、消息关联、停止 | [共同语义](../../src/harness/types.ts)及两个 adapter；[Codex](../../test/codex.test.ts)、[DSH](../../test/dsh.test.ts) 回归后再按受影响端走真实路径 |

证据保存用户动作、产品操作编号/状态、原生运行关联、磁盘结果或受控进程事实以及故障窗口。使用合成内容，不导出原生账号/完整日志。缺少确定性故障现场时将回执窗口记为未覆盖，保留协议测试的辅助结论。

## 容易误判的地方

- 已受理、原生已接收、运行完成是不同观察；连接“已连接”也不是任务状态。
- “已中断”不代表后台工具均已退出。外部清理后进程退出的证据不能倒算为原生停止成功，不能从 Agent 输出中的 PID 猜测并终止宿主进程。
- 当前没有运行中追加、完整提问回答或审批入口；受阻是当前边界，不能通过自动批准把这条路径跑绿。
