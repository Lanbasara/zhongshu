# 自动任务与日程

当前能力：在中书里看见、管理 DSH 原生自动任务，接住它们的运行结果；Agent 可以用一句话主动通知用户；日历把原生任务和工作区时间轴文件放在一起。决定见 [ADR 0021](../adr/0021-automations.md)，推送规则见 [ADR 0018](../adr/0018-push-notifications.md)，未读规则见 [ADR 0012](../adr/0012-conversation-lifecycle.md)。

## Sub-features

| 场景 | 可证伪的结果 |
| --- | --- |
| T01 · 看见原生任务 | 侧栏「日程」有五个标签：日历（月/周）、今天、未来、回看、全部任务。Agent 在对话里用原生工具建的任务，最迟 30 秒出现在页面上。「全部任务」按结果投递到哪分组：投递到某段对话、每次新开、首次新开后复用、中书之外的会话。 |
| T02 · 管理 | 新建、暂停、恢复、立即运行、修改、删除都写到原生，读回一致。新建可选一次、每天、每周、固定间隔；结果可选每次新开或首次新开后复用。别处先改过时，操作被拒，面板里说明“刚在别处改过”，原生保留别处的修改。跑完的任务不能修改。上一次投递还在进行时，“立即运行”提示稍后再试。 |
| T03 · 拖动改期 | 电脑上，在周视图拖动尚未运行的一次性任务。15 分钟一格，可以跨天，不能拖到过去。松手后原生时间变为新时点；原生拒绝时，块回到原位。循环任务不能拖，要在表单里改。 |
| T04 · 投递到对话 | 投递到一段没人在看的对话时，侧栏先显示运行中，结束后显示“已完成，还没看”，页面标题的未读数加一。完成本身不推送；失败、等待回答或审批照常推送。投递的指令显示为虚线气泡“自动任务投递 · 任务名”和指令原文，可以展开看原生原文。 |
| T05 · 任务新开的对话 | 每次新开或首次新开后复用的任务，原生新建的会话如果在已登记工作区里，就接入为中书对话。这些对话不进普通对话列表；侧栏在所属工作区下每个任务只占一行，显示最近一次运行的状态，点开进入最近一次运行。对话顶部的运行条可以切换历次运行。首次新开后复用的任务，第二次起回到同一段对话。不在已登记工作区里的会话不接入。任务被删除（在中书或由 Agent）后，它新开的对话作为普通对话回到侧栏，结果不随任务消失。 |
| T06 · 对话里的自动任务 | 有任务投递进来的普通对话，顶部显示「这段对话的自动任务 N · 已跑 M」。展开后列出每个任务的时间、状态，以及 Agent 在那次运行后发出的通知摘要。 |
| T07 · 主动通知 | Agent 调用 `mcp__zhongshu__notify_user`（一句话 summary，可附工作区文件），工具返回“已通知用户。通知编号 …”。中书从工具记录认出所在对话后推送：标题是对话标题，正文是这句摘要。点开直达那一轮并短暂高亮。20 秒内认不出对话时，推送改为打开日程。10 分钟内最多 30 条。 |
| T08 · 时间轴文件 | 读取每个工作区的 `.zhongshu/timeline.jsonl`（字段见下）。同一 id 以最后一行为准。带时区的时间换算成查看者的时区显示。坏 JSON、字段不合、不存在的日期、越出工作区或网址链接的行都跳过，「回看」提示跳过了几行。点条目的链接，在该工作区的新草稿旁打开这个文件。中书只读这个文件。 |
| T09 · 迟到 | 投递时间比计划晚 5 分钟以上（例如宿主重启后补投），在任务、日历和运行记录上标为迟到。 |
| T10 · 边界 | Codex 没有自动任务，日程页提示不可用，时间轴照常显示。通知工具只监听 `127.0.0.1`，必须带 Bearer 令牌，带 `Origin` 的浏览器请求被拒。其余私有接口沿用认证、来源与 CSRF 检查。通知摘要不写日志。 |

时间轴每行一个 JSON 对象：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 同一 id 以最后一行为准，改期或完成时追加一行 |
| `date` | 是 | `YYYY-MM-DD` |
| `time`、`tz` | 否 | `HH:mm` 与 IANA 时区；没有 `time` 是全天 |
| `kind` | 是 | `action`（用户要做的操作）、`event`（外部大事）、`decision`、`research` |
| `title`、`detail` | `title` 必填 | 标题与说明 |
| `link` | 否 | 工作区内的相对路径 |
| `status` | 否 | `done` 或 `cancelled` |

## How to get to it (user POV)

侧栏「日程」进入，手机上先点左上角「打开对话导航」。地址是 `#schedule`，各标签是 `#schedule:today`、`:future`、`:past`、`:tasks`。多数任务在对话里让 Agent 按计划建；日程页右上角「新建自动任务」是手动入口（手机上只显示加号）。点日历或列表里的任务打开详情面板：已跑完的任务直接打开它的结果对话。主动通知点开后的地址是 `#<对话>:notice:<通知>`。

## Driving it with Harness

遵循[共同入口](README.md#独立执行验收)。fixture 没有自动任务替身，T01–T09 都需要 [native 现场](README.md#native真实接入分支)的 DSH 0.2.2 及以上。T07 还需要操作者按 [README](../../README.md#harness-connections) 配好 `agentTools`，并在 DSH 配置里注册名为 `zhongshu` 的 MCP 服务（只走回环地址，带同一令牌）。能连上推送服务的浏览器见[通知](notifications.md)。

读回用已登录页面的同源请求：`GET /api/private/workbench/automations`、`/automations/:id/history`、`/automations/:id/runs`、`/notifications`、`/timeline`。写操作要带 `/api/session` 返回的 CSRF 令牌；不要导出会话正文。

1. **T01/T02。** 在页面表单建一个 2–3 分钟后的一次性任务，读回原生字段。测冲突：记下任务的 `updatedAt`，用它从接口改一次标题（相当于别处修改），再在仍打开的面板里点暂停或恢复。预期面板里出现冲突说明，原生保留新标题。
2. **T03。** 用真实鼠标事件拖动（CDP `Input.dispatchMouseEvent`，指针类型必须是鼠标），读回 `scheduledAt`。拖完页面不能变白：React 重新渲染后，块应出现在新的一列。
3. **T04。** 用接口建一个 2–4 分钟后、投递到某段已有对话的任务。页面停在日程，每 1–2 秒记录侧栏那一行的状态：先运行中，再“已完成，还没看”。确认推送设备的 `deliveredAt` 没有因完成而变化。
4. **T05。** 建一个首次新开后复用的任务，连续点两次“立即运行”（间隔到上一轮结束）。预期只有一段接入的对话，两次回复都在里面，侧栏那一行显示未读。再建一个每次新开的任务，确认每次运行一段对话，运行条能切换。
5. **T07。** 在对话里让 Agent 调用通知工具，读回 `/notifications` 的 `state: placed` 和 `conversationId`。在新页面加载通知地址（同一页面只改 hash 不会切换，见[共同入口](README.md#drive控制与读回)），确认打开那一段并高亮那一轮。
6. **T08。** 让 Agent 用 heredoc 原样写一份样本：有效行、重复 id、坏 JSON、不存在的日期、`../` 链接、网址链接各一行。读回 `/timeline` 的条目与 `problems`，再在日历、未来、回看里核对位置和时区。
7. **T09。** 需要宿主在某次触发前停机、过点后再启动，由操作者执行；做不到时记为未覆盖。规则由回归测试覆盖。

## Gotchas

- **首次新开后复用。** 第一次投递后，DSH 把这类任务的目标改写成普通会话。中书在第一次列出任务时记下它预留的会话，靠这个认出“这是任务自己建的会话”。如果任务在中书没运行时被创建并已投递，这段会话不会接入，任务显示为“中书之外的会话”。
- **投递文本的两种格式。** 一次性提醒是 `[SCHEDULE REMINDER]`，后面几行是 JSON 编码的字段；循环任务的批次是 `[SCHEDULE REMINDER BATCH]` 加 `reminders_json`。认不出的格式按原文显示。
- **新会话的配置。** 原生新建的会话用宿主默认的模型和权限，可能和用户常用的不同；无人值守时可能停在审批上。
- **时区。** Agent 不知道用户的时区，会按 UTC 排时间。按钟表时间触发的任务，时区要写在工作区约定里。
- **日历只显示每个任务的最近一次投递和之后的时点。** 更早的运行在任务详情的运行记录里，以及对话顶部的运行条里。
- **刷新节奏。** 页面可见时每 30 秒重读一次任务，服务端每 60 秒重读一次，原生通知变化时立即重读。别处的改动最迟在这段时间内出现。
