# 自动任务与日程

当前能力：在中书里看见、管理 DSH 原生自动任务，接住它们的运行结果；Agent 可以用一句话主动通知用户；日历把原生任务和工作区时间轴文件放在一起。决定见 [ADR 0021](../adr/0021-automations.md)，推送规则见 [ADR 0018](../adr/0018-push-notifications.md)，未读规则见 [ADR 0012](../adr/0012-conversation-lifecycle.md)。

## Sub-features

| 场景 | 可证伪的结果 |
| --- | --- |
| T01 · 看见原生任务 | 侧栏「日程」有五个标签：日历（月/周）、今天、未来、回看、全部任务。Agent 在对话里用原生工具建的任务，最迟 30 秒出现在页面上。「全部任务」是一张列表：按已开启 / 已暂停 / 已结束 / 全部筛选，可以搜索名称和指令；每行写规则、下次或最近一次的时间（带相对天数）、工作区和最近的结论。 |
| T02 · 管理 | 新建、暂停、恢复、立即运行、修改、删除都写到原生，读回一致。新建可选一次、每天、每周、固定间隔，每天和每周可设结束日期（经[司辰](sichen.md)的时间模块换算，到期由 DSH 结束）；结果可选每次新开或首次新开后复用。这两种都只能选预设（标准 / PTC），模型、思考深度和权限用宿主默认；中书不在运行之前建对话，要用别的配置就投递到自己配好的对话。投递到某段对话的任务（表单里选那段对话，或 Agent 在对话里用 `sichen … --to 本对话`）沿用那段对话的配置。可选一个工作区技能，中书把“使用技能 名称（/名称）。”写在指令开头。任务详情显示“运行配置”。别处先改过时，操作被拒，面板里说明“刚在别处改过”，原生保留别处的修改。跑完的任务不能修改：页面、接口和 `sichen` 都拒绝，原生里任务保持已结束；接口对已结束任务的改动返回 HTTP 200、正文 `{"outcome":"ended"}` 且不写入（页面不显示编辑控件），`sichen edit/pause/resume` 以非 0 退出并说明。上一次投递还在进行时，“立即运行”提示稍后再试。任务被新建、修改或删除时，DSH 往它涉及的空闲对话塞一条变更通知：对话里显示一行“自动任务「名称」已修改。这条原生通知不是投递。”，不显示成投递气泡，也不锁住发送和归档。新建的通知即时补入；修改和删除要等该对话下一次收到输入、读取原生历史时才补入（空闲时刷新或新开页不会立即显示）。 |
| T03 · 拖动改期 | 电脑上，在周视图拖动尚未运行的一次性任务。15 分钟一格，可以跨天，不能拖到过去。松手后原生时间变为新时点；原生拒绝时，块回到原位。循环任务不能拖，要在表单里改。 |
| T04 · 投递到对话 | 投递到一段没人在看的对话时，侧栏先显示运行中，结束后显示“已完成，还没看”，页面标题的未读数加一。完成本身不推送；失败、等待回答或审批照常推送。投递的指令显示为虚线气泡“自动任务投递 · 任务名”和指令原文，可以展开看原生原文。 |
| T05 · 任务新开的对话 | 每次新开或首次新开后复用的任务，原生新建的会话如果在已登记工作区里，就接入为中书对话。侧栏只放对话：任务本身不占行；这些对话和普通对话排在一起，带时钟标记和“自动任务 · 开出的时间”，运行中、未读与普通对话相同；原生运行开始时它排到前面。还没运行过的任务在侧栏没有任何东西。对话顶部的运行条说明属于哪个任务，可以切换历次运行。首次新开后复用的任务，第二次起回到同一段对话。不在已登记工作区里的会话不接入。任务被删除（在中书或由 Agent）后，它新开的对话作为普通对话回到侧栏，结果不随任务消失。 |
| T06 · 对话里的自动任务 | 有任务投递进来的普通对话，顶部显示「这段对话的自动任务 N · 已跑 M」。展开后列出每个任务的时间、状态，以及 Agent 在那次运行后发出的通知摘要。 |
| T07 · 主动通知 | Agent 调用 `mcp__zhongshu__notify_user`（一句话 summary，可附工作区文件），工具返回“已通知用户。通知编号 …”。中书从工具记录认出所在对话后推送：标题是对话标题，正文是这句摘要。点开直达那一轮并短暂高亮。20 秒内认不出对话时，推送改为打开日程；之后在读到的历史里认出时，通知列表补上所在对话，不再推送第二次。运行太快、中书还没开始观察就结束时，靠读到的历史认出。10 分钟内最多 30 条。 |
| T07b · 回填结论 | 被定时任务叫起来的运行结束时，Agent 调用 `mcp__zhongshu__record_result`（一句 summary），工具返回“已写到任务卡上。结论编号 …”。中书 MCP 服务在 `initialize` 的说明里写明这是定时运行的最后一步（只靠工具说明时，长任务会漏掉）。中书从工具记录认出所在对话，挂到那段对话里在它之前最近的一次投递上：日历那一格、今天/未来列表和任务的运行记录都显示这句结论。不推送。没有调用时卡上只显示状态。 |
| T08 · 时间轴文件 | 读取每个工作区的 `.zhongshu/timeline.jsonl`（字段见下）。同一 id 以最后一行为准。带时区的时间换算成查看者的时区显示。用户的操作（`action`）过了时间但没写完成，显示“已过时间”，不打勾。注意非 action 的过期条目（例如过时间的决定）现状是日历上用 ✓ 加 aria「已过」，与「已完成」同字符；判据按 aria/文字区分，不能只看勾。坏 JSON、字段不合、不存在的日期、越出工作区或网址链接的行都跳过，「回看」提示跳过了几行。点条目的链接，在该工作区的新草稿旁打开这个文件。中书只读这个文件。 |
| T09 · 迟到 | 投递时间比计划晚 5 分钟以上（例如宿主重启后补投），在任务、日历和运行记录上标为迟到。 |
| T10 · 边界 | Codex 没有自动任务，日程页提示不可用，时间轴照常显示。通知工具只监听 `127.0.0.1`，必须带 Bearer 令牌，带 `Origin` 的浏览器请求被拒。其余私有接口沿用认证、来源与 CSRF 检查。通知摘要不写日志。 |

时间轴每行一个 JSON 对象：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 同一 id 以最后一行为准，改期或完成时追加一行 |
| `date` | 是 | `YYYY-MM-DD` |
| `time`、`tz` | 否 | `HH:mm` 与 IANA 时区；没有 `time` 是全天 |
| `kind` | 是 | `action`（用户要做的操作）、`event`（外部大事）、`decision`、`research` |
| `title`、`detail` | `title` 必填 | 标题与说明 |
| `link` | 否 | 工作区内的相对路径 |
| `status` | 否 | `done` 或 `cancelled` |

## How to get to it (user POV)

侧栏「日程」进入，手机上先点左上角「打开对话导航」。地址是 `#schedule`，各标签是 `#schedule:today`、`:future`、`:past`、`:tasks`。多数任务在对话里让 Agent 按计划建；日程页右上角「新建自动任务」是手动入口（手机上只显示加号）。点日历或列表里的 Agent 卡，先打开这张卡（像 DSH 官方 App）：状态、下次运行（带“6 天后”）、最近一次的结论和通知、「打开对话 ›」；名称、任务内容和时间在卡上直接改，「放弃 / 保存修改」；运行记录逐次显示结论，点哪次打开哪次的对话。「全部任务」是一个列表，按已开启、已暂停、已结束、全部筛选，可以搜索。主动通知点开后的地址是 `#<对话>:notice:<通知>`。

## Driving it with Harness

遵循[共同入口](README.md#独立执行验收)。fixture 没有自动任务替身，T01–T09 都需要 [native 现场](README.md#native真实接入分支)的 DSH 0.2.2 及以上。T07、T07b 还需要操作者按 [README](../../README.md#harness-connections) 配好 `agentTools`，并在 DSH 配置里注册名为 `zhongshu` 的 MCP 服务（只走回环地址，带同一令牌）。能连上推送服务的浏览器见[通知](notifications.md)。

读回用已登录页面的同源请求：`GET /api/private/workbench/automations`、`/automations/:id/history`、`/automations/:id/runs`、`/notifications`、`/timeline`。写操作要带 `/api/session` 返回的 CSRF 令牌；不要导出会话正文。

1. **T01/T02。** 在页面表单建一个 2–3 分钟后的一次性任务，读回原生字段。再建一个“首次新开后复用”的任务，选 PTC 预设和一个合成技能：创建后侧栏不出现任何新行，接口也不接受带配置的新开目标；点“立即运行”，这时才出现一段对话，回复里有技能正文里的合成标记，原生事件里有一次技能工具调用。两种新开目标都只显示预设选择。测冲突：记下任务的 `updatedAt`，用它从接口改一次标题（相当于别处修改），再在仍打开的面板里点暂停或恢复。预期面板里出现冲突说明，原生保留新标题。
2. **T03。** 用真实鼠标事件拖动（CDP `Input.dispatchMouseEvent`，指针类型必须是鼠标），读回 `scheduledAt`。拖完页面不能变白：React 重新渲染后，块应出现在新的一列。
3. **T04。** 用接口建一个 2–4 分钟后、投递到某段已有对话的任务。页面停在日程，每 1–2 秒记录侧栏那一行的状态：先运行中，再“已完成，还没看”。确认推送设备的 `deliveredAt` 没有因完成而变化；`GET /api/private/push` 的设备列表为空时，这一项记 UNCOVERED，交给[通知](notifications.md)批次。
4. **T05。** 建一个首次新开后复用的任务，连续点两次“立即运行”（间隔到上一轮结束）。预期只有一段接入的对话，两次回复都在里面；它作为普通对话出现在侧栏，每次运行开始时排到最前，结束后显示未读。再建一个每次新开的任务，确认每次运行一段对话，运行条能切换。
5. **T07。** 在对话里让 Agent 调用通知工具，读回 `/notifications` 的 `state: placed` 和 `conversationId`。加载通知地址（新页面，或在已打开的页面改变 hash），确认打开那一段并高亮那一轮。
6. **T08。** 让 Agent 用 heredoc 原样写一份样本：有效行、重复 id、坏 JSON、不存在的日期、`../` 链接、网址链接各一行。读回 `/timeline` 的条目与 `problems`，再在日历、未来、回看里核对位置和时区。
7. **T07b。** 在已登记工作区建一个 2–3 分钟后、每次新开对话的任务，指令里只写要做的事，不提回填。运行结束后读 `GET /automations`：这个任务的 `lastDelivery.result` 是 Agent 写的一句结论，原生事件里有一次 `record_result` 工具调用，推送设备没有收到新推送。日历那一格和任务的运行记录显示同一句结论；点那一格先打开任务卡，卡上的运行记录或「打开对话」打开这次运行的对话。没有推送设备时，“没有收到新推送”记 UNCOVERED。
8. **T09。** 需要宿主在某次触发前停机、过点后再启动，由操作者执行；做不到时记为未覆盖。规则由回归测试覆盖。

## Gotchas

- **刚建好的会话。** DSH 刚为任务新建会话时，可能还没记下它的模型和权限；中书每 3 秒重试接入，最多 10 分钟，接入后照常观察并补上通知的位置。
- **首次新开后复用。** 第一次投递后，DSH 把这类任务的目标改写成普通会话。中书在第一次列出任务时记下它预留的会话，靠这个认出“这是任务自己建的会话”。如果任务在中书没运行时被创建并已投递，这段会话不会接入，任务显示为“中书之外的会话”。
- **投递文本的两种格式。** 一次性提醒是 `[SCHEDULE REMINDER]`，后面几行是 JSON 编码的字段；循环任务的批次是 `[SCHEDULE REMINDER BATCH]` 加 `reminders_json`。认不出的格式按原文显示。
- **新会话的配置。** 原生新建的会话只带工作区和预设，用宿主默认的模型、思考深度和权限，可能和用户常用的不同；无人值守时可能停在审批上。宿主默认在实例的 DSH 配置里改；要用别的配置，投递到已配置好的对话。
- **以前预先建好的空对话。** 2026-11-09 之前“首次新开 + 指定配置”会在运行前建对话。这种会话 DSH 不能删除，而且排队的设置命令让它显示“有待处理输入”。从没运行过的会话允许归档，用归档清理。
- **技能。** 定时投递里的 `/技能名` 不会被原生当成显式调用。中书写在指令开头的那句让 Agent 自己用技能工具加载；技能的 front matter 若禁止模型调用（`disable-model-invocation: true`），加载会被拒绝。技能列表跟着表单里选的工作区走（来自该工作区的草稿准备会话，与新对话页相同）：工作区技能放在 `.dsh/skills/<名称>/SKILL.md`，已安装插件带的技能也会列出；工作区里没有就显示为空。
- **时区。** Agent 不知道用户的时区，会按 UTC 排时间。按钟表时间触发的任务，时区要写在工作区约定里。
- **日历只显示每个任务的最近一次投递和之后的时点。** 更早的运行在任务详情的运行记录里，以及对话顶部的运行条里。
- **刷新节奏。** 页面可见时每 30 秒重读一次任务，服务端每 60 秒重读一次，原生通知变化时立即重读。别处的改动最迟在这段时间内出现。
