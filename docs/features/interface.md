# 界面与组件工作台：feature map

本页维护界面交互、设计基础的消费入口和开发资源的发布隔离。职责及扩展规则归 [architecture](../architecture.md#界面与设计系统)。业务行为仍按各能力地图验证；Storybook 不证明原生执行。

## Sub-features

| 场景 | 要证明的行为 |
| --- | --- |
| I01 | 侧栏工作区树、搜索与跳转、设置与归档页、阅读器面板在桌面和手机上协调，状态点含义一致，切换工作区不改变主题 |
| I02 | 输入增长、材料菜单、配置浮层、键盘及窄屏操作可用，减少动效有对应行为 |
| I03 | 新视觉下真实应用的创建、发送、停止、草稿与刷新路径保持正确 |
| I04 | Storybook 组件目录用产品组件展示每个组件的可操作状态，设计基础页由 tokens 生成 |
| I05 | 产品构建和最终产物不含开发界面，隔离检查能识别反例 |
| I06 | Agent 过程默认收起，只在读者点击时展开；运行中摘要行显示转圈与当前步骤名，结束按原生终态与步骤事实显示完成、未成功、整轮失败、中断或状态未明，不把个别命令失败写成整批失败 |
| I07 | 每个页面有自己的地址，后退、前进和改变地址都能换页；手机上的返回手势先关闭打开的浮层，再离开页面 |
| I08 | 原生状态无法核实、操作结果未确认或对话被阻断时，正文区顶部只有一条紧凑提示，说明状态、已知原因、保留内容与不自动重发，并可「查询原生结果」；正常的发送等待不出现提示条 |

## How to get to it (user POV)

产品按[共同入口](README.md)启动并登录。侧栏顶部“新对话”进入草稿，首次发送才创建；“搜索与跳转”（macOS ⌘K，其他 Ctrl+K）搜索对话、工作区和操作，未输入时先列需要关注、再列最近的对话。侧栏中部是工作区树，底部为“工作区文件”“已归档”“设置”（工作区、插件、存储、通知、账户五个标签）与连接状态。侧栏右上“收起导航”（⌘\），收起后标题栏出现“展开导航”。对话标题栏有“打开工作区文件”（手机移入“对话操作”菜单）和“对话操作”菜单；运行中输入框右侧为带细转圈的“停止当前轮”，写下内容后才出现“加入队列”；阅读器与子 Agent 面板从右侧滑出，可展开到整个正文区。窄屏使用“打开对话导航”抽屉，标题栏“搜索与跳转”打开全屏搜索，浮层改为底部面板。输入框为“给 Agent 的消息”；加号的可访问名称为“添加图片或文件引用”，菜单内选择“添加图片”或“引用工作区文件”。已有对话模型按钮为“当前对话配置”；草稿输入区为“选择 Agent Power”“模型与思考深度”“执行权限”，配置浮层紧凑且模型/effort 触发区无常驻底色。普通 Enter 换行，Cmd/Ctrl+Enter 发送；中文输入法合成期间不发送。

开发入口：仓库根运行 `npm run storybook`，打开终端给出的本地地址（默认 6006）。它是组件目录：设计基础页由 tokens 生成，每个组件的状态都能通过控件切换；没有产品账号、连接配置或真实会话，也不再包含历史原型。

## Driving it with Harness

沿用共同入口的 Launch/Doctor/Evidence/Cleanup，记录版本与差异，使用自己的数据目录、浏览器上下文和空闲端口。I01–I03 使用真实产品构建加 fixture 可验证界面与应用边界；原生任务需另按 [E05](execution.md)、[U01](conversation-usability.md) 实际驱动，不能从 fixture 或 stories 外推。

**I01：布局与导航。** 创建 Fixture A 与 Fixture B 下各一个唯一命名对话。在两者间切换，比较 body、按钮、选中项的计算颜色，变化应表达选中与状态，不跟随工作区换肤。运行中、完成未读、失败的对话行分别显示蓝色转圈、绿点（标题加粗）、红点，标题栏状态与之一致。用 ⌘K/Ctrl+K 打开搜索，输入标题片段后方向键与 Enter 打开；未输入时列表含“需要关注/最近”。打开「设置」各标签与「已归档」页，再回到对话。在 1280px 及 390px 视口分别操作导航、搜索、切换和关闭；在 320px 输入长中文及无空格长串。以 documentElement 的 scrollWidth 不超过 clientWidth、主要按钮处于视口内、输入仍可编辑为判据。桌面收起/展开导航后草稿仍在。窄屏打开导航，Tab 不离开抽屉，Escape 关闭后焦点返回触发按钮；分别在提示气泡可见/不可见时检验。打开抽屉里的“管理对话”子框，第一次 Escape 只关闭子框，第二次才关闭导航；忙碌时仍遵守原操作的关闭限制。为本次合成工作区放入一个普通 Markdown 文件（可信端只准备文件，不写产品 DB），从“打开工作区文件”选择阅读；在 1000px 展开为全屏再收回，关闭后回到原对话。工作区读取细节另见 [workspace-files](workspace-files.md)。

**I02：输入与状态。** 草稿先按 [C08](conversations.md) 操作 Power、模型、深度、默认/复位；截图检查输入区内紧凑排列、无独立大表单或常驻灰色胶囊。鼠标与键盘打开浮层，Escape 关闭并恢复焦点；320px/390px 下按钮和浮层不超出视口。 输入多段文字，确认增长到上限后在内部滚动，不挤出发送按钮。打开材料菜单，用键盘进入项目，再 Escape 关闭；打开配置浮层，核对模型/权限来自当前对话且长名称仍可查阅，Escape 回到触发按钮。文件引用按 [U07](conversation-usability.md)；图片选择与失败重试按 [U04/U08](conversation-usability.md)。查看实际附件预览，移除后不进入提交。普通 Enter 只换行，Cmd/Ctrl+Enter 只发送一次。中文合成、真实剪贴板、拖放与手机软键盘分别记录覆盖，工具不能驱动的项目不可写 PASS。通过浏览器模拟或系统减少动态效果设置切换 prefers-reduced-motion，查看抽屉/菜单/附件区与加载图标；减少动效下无持续旋转与位移，不仅检查媒体查询字符串。结束恢复测试视口与系统设置。

**I03：真实应用接线。** 两个独立 fixture 对话各跑 [C01](conversations.md)。在其中一段发送唯一消息（保存操作编号），执行中输入下一条草稿，再“停止当前轮”；按 [E03](execution.md) 独立 inspect 核对 stopCalls 与原操作。完整刷新，核对同一对话/历史/草稿，再发送并用 fixture complete 结束；inspect 中提交计数只增加一次。切换另一对话再返回，输入不串。另按 [E04](execution.md) 真实发送拒绝/丢回执路径检查错误与输入恢复；这些故障方法不应因 UI 改造改变。与真实 Harness 相关的输入、工具、恢复走既有 U01/E05，记录模型时间预算和文件独立读回。

**I04：组件目录。** `npm run build:storybook` 后产物只在 `.artifacts/storybook`。目录按「设计基础 / 基础 / 模式 / 工作台」排列：「设计基础/设计令牌」从 tokens 读取颜色、状态色、文字、间距、圆角阴影与动效（可播放）；「基础/控件」覆盖按钮、图标按钮、菜单、浮层、状态点与快捷键；「模式/…」分别覆盖工作台框架、侧栏、搜索与跳转、提示、对话内容、过程展示、本轮文件、输入框、新对话、子 Agent 与插件库；「工作台/整体」组合桌面、运行中、阅读器、子 Agent 面板与手机抽屉；「工作台/Harness 账号」「工作台/通知与安装」「工作台/Plan 模式」「工作台/提问与审批」分别展示对应能力的各状态。用控件切换每个组件的状态，工具栏 viewport 选 `phone`（390×844）查看手机布局。逐个切换全部 story，检查没有渲染异常或控制台错误（示例图片指向不存在的私有资源，404 属预期）；演示操作不提交真实任务，截图不能代替组件动作。开发服务端口冲突时用 `npm run storybook -- --port <空闲端口>`，不要停止他人的进程。

在「模式/输入框」的「输入框」story 中，输入 `/` 加名称片段，观察候选随输入变化；按 ↓ 移动后按 Tab，核对高亮项出现在草稿中，光标可继续输入。手打完整名称后直接发送，演示消息保留原文。点按用量查看累计值和上下文占用，再用 Escape 关闭；390px 视口点按候选和用量，核对没有横向溢出。「对话用量 · 全部档位」中只有累计用量的一档展示窗口容量缺失时的状态。示例数据只验证交互与布局。

在「模式/本轮文件」中，单文件与多文件分别点开，多文件先露出三项，展开后点靠后的文件；文件不可用仍显示路径和状态。「工作台/整体」的“打开本轮文件” story 在右侧面板中显示阅读器占位。

**I06：过程展示。** 在 fixture 对话发送后，执行 `node test/support/feature-fixture.ts tool-step --root "$zh_verify_root" --title '本轮标题'` 两到三次：正文出现默认收起的过程块（摘要按钮 `aria-expanded=false`），摘要行显示转圈、“正在执行”与当前步骤名，并带操作计数；块不会自行展开，读者点摘要行才展开步骤，再点某一步展开输入与输出（步骤行同样默认收起）。`complete` 后摘要变为“已完成 N 项操作”（计数由独立样式分隔），回复出现，读者此前的开合选择不被改变；再发下一轮也不重置。另一段用 `fail` 结束时原生轮次终态为 failed：摘要为“本轮失败”且相关步骤标“未完成”，不出现“失败于「步骤名」”这类按单步推断的措辞。中途某一步失败、之后的步骤完成用 `tool-step --stepStatus failed`（把上一步置为失败并开始下一步）后 `complete`，摘要为警示色“N 项未成功”（TriangleAlert），展开后失败步骤带 X 与退出码；整轮成功时不会因为曾有个别失败而写成整轮失败。在页面点「停止当前轮」结束：摘要为“已中断”，没有结果的步骤显示“已停止”而不是转圈。状态未明用 `tool-step --stepStatus unknown`：该步骤只能显示“状态未明”，不能显示为对勾；整个轮次状态不足时摘要也是“状态未明”，不显示成功或进行中。刷新页面后所有过程块回到默认收起。没有名称、输入、输出的已完成工具记录用 `tool-step --empty` 模拟，不单独占位。减少动效下无流光、无旋转位移。

**I07：页面地址、前进后退与返回手势。** 用 390px 触屏视口和 fixture。

1. 从首页点「新对话」，记录 `#draft/<草稿ID>`。写入独有文字，在工作区选择里选 Fixture A，确认地址、`history.length` 和文字不变。再次点「新对话」得到不同地址和空输入。后退、前进、刷新，核对两份草稿的地址和内容。首次发送后地址变为对话 ID，`history.length` 不变。打开原草稿地址时若已完成交接，显示草稿不可用，并提供开始新草稿的入口。
2. 再建第二段对话：打开导航抽屉，`history.state.zhOverlays` 有一项。在抽屉里点「在 Fixture A 新建对话」，抽屉那一项被收回、草稿页压入，没有多余的空记录。发送后后退，回到第一段对话且正文是它的；前进再回到第二段。
3. 从抽屉打开「设置」，首次进入为 `#settings`；切到「存储」标签，地址变为 `#settings:storage` 且 `history.length` 不变；完整刷新仍停在该标签；后退回到原对话。再次打开设置会保留标签。点侧栏「工作区文件」会回到设置下面保留的对话或草稿，再打开阅读器；从首页进入设置时则回到 `/`。
4. 浮层：打开抽屉、标题栏搜索、「对话操作 › 打开工作区文件」各一次，各用系统后退关闭，确认留在原页面、地址不变。再打开阅读器并用左上「返回对话」关闭，随后的一次后退直接回到上一个页面，不出现“按了没反应”。日程页打开任务卡片后用后退关闭（需要能读取自动任务的现场）。抽屉或搜索打开时 `body` 的计算 `overflow` 为 `hidden`，关闭后恢复。
5. 在已打开的页面依次改变 hash 为另一段对话、`#archive`、`#schedule:tasks`，页面依次切换且日程停在「全部任务」；连续后退按相反顺序回来。
6. 1280px 下打开搜索，`history.state` 仍为空：桌面浮层不占历史记录。

原生 `<dialog>`（管理对话、选择文件、放大图片、工作区管理）由浏览器在返回手势时关闭，不写历史记录，按各自地图检查。

**I08：对话级状态提示。** 在 Storybook「模式/对话状态提示」逐个切换状态：正常等待（none）不渲染任何内容；状态无法核实为问号图标、标题“运行状态暂时无法核实”、次行含原因句与保留/不重发/自动重试，并带「查询原生结果」；被阻断的对话按原因给出标题（未知机器码只能出现在次行，不能当标题）；结果待核实为时钟图标且不承诺自动重试。390px 下长文案换行、按钮移到文字下方，页面无横向溢出。状态未知要持续约 2 秒仍未核实才出现提示，创建或切换对话时的短暂未知不显示。真实接线、正常发送不显示提示以及输入框上方不再出现「正在核对…」提示见 [对话基本可用性 U15](conversation-usability.md#u15-对话级状态提示)，不能用 Storybook 代替。

**I05：发布隔离与反例。** 运行四项仓库检查，再 `npm run build:storybook && npm run check:release`。以 `node --test test/design-boundaries.test.ts` 检查静态/动态/type import、公共资源改名/混入与构建后文件修改的反例；还要在一次性源码副本进行以下真实构建检查，不能污染正在验证的应用：

1. 给产品入口追加一个指向 `design/` 的 import（即使未使用），构建应以 Build boundary 拒绝；恢复后能构建。
2. 将任意原型 HTML 复制到 `src/web/public/prototype.html`，构建应拒绝；恢复后能构建。
3. 正常构建完成后将示例文件放进 `dist/public/` 或改写 index.html，`npm run check:release` 应拒绝；重建后通过。
4. 构建真实 Docker 镜像，Dockerfile 的最终阶段执行 `--image` 检查。独立检查运行镜像里没有 design、.storybook、storybook-static、Storybook npm 包；不能以 .dockerignore 或源码 grep 代替镜像证据。

检查防止误引入和打包漂移，不抵抗恶意修改检查本身。新增公共资产时须同时审查文件和摘要；不要为了反例通过而修改清单或关闭插件。测试结束删除自己的副本和测试镜像，保留构建输出/退出码与失败判据。浏览器或 Docker 前提缺失分别记录 BLOCKED。

## Gotchas

- Stories 的示例文字不是产品默认数据；stories 只证明组件状态与布局，不证明真实接线。
- I03 中停止轮次不等于所有后台工具退出；沿用执行地图的真实语义。
- 统一 token 不是禁止所有几何尺寸；语义颜色/字体/时序从基础层消费，具体布局仍由模式负责。
- 本地窄窗口不证明 Android 真机、输入法或后台唤醒；仅有 CSS 规则不证明减少动效的实际执行。
- 浏览器工具的“后退”与 Android 返回手势走同一段历史，但真机的手势、已安装 PWA 和浏览器对无用户操作写入的历史记录的跳过规则，只能在真机上确认。
- 控制台里 Radix 插入内联样式被 CSP 拒绝的报错是已知现象：滚动锁的规则已写在 `style.css`，报错本身不代表功能失效。
- 构建后不要继续让旧应用提供新旧混合资产，重新启动 fixture；不要覆盖用户试用的实例。
- 过程块与步骤行的开合状态只存在组件内存里：刷新、切换对话或重开页面都会回到默认收起，这是约定行为，不是丢失用户设置。
- 对话级状态提示是状态说明，不是可关闭的错误弹窗；它随原生状态变化出现和消失，「查询原生结果」只是再读一次原生事实。
