# 连接原生 Harness 与接续工作

浏览器只连接中书。中书通过两个 [adapter](../src/harness/types.ts) 访问独立运行的 Codex App Server、DSH Web Host；停止中书或关闭页面只释放观察连接，不停止原生进程。模型执行、工具与原生上下文归 Harness。

## 由操作者提供连接

先按[身份说明](identity.md)初始化中书，再在独立受保护的运行环境启动并登录原生服务。中书不安装 Harness、不读取其账号凭据，也不启动或监管它们。当前兼容验证针对 Codex CLI `0.164.0-alpha.11.1` 与 DSH `0.2.1-rc.4`；协议仍在演进，升级前重跑真实接入路径。版本不同不能仅凭 schema 编译通过认定兼容。

设置 `ZHONGSHU_HARNESS_CONFIG` 为操作者配置文件的绝对路径。文件须归中书运行账号所有，不允许组或其他用户修改。未配置时应用仍可登录，但没有可执行工作区。以下仅为目录示意，不是自动创建命令：

```json
{
  "workspaces": [
    { "id": "notes", "label": "个人笔记", "directory": "/srv/workspaces/notes" }
  ],
  "codex": { "socketPath": "/run/private-codex/app.sock" },
  "dsh": { "launchFile": "/run/private-zhongshu/dsh-launch" }
}
```

两端可按需省略。工作区须预先存在；服务端规范化路径并拒绝与中书数据目录重叠，浏览器仅提交工作区 ID。目录配置是允许列表，不代替操作系统访问隔离。真实部署应使原生执行身份只能访问它自己的 HOME、原生数据和允许的工作区，不能访问中书数据库、备份或部署凭据。

- **Codex**：使用官方 `codex app-server --listen unix:///absolute/private/app.sock` 的 Unix IPC。操作者负责 socket 所在目录及访问权限。适配器读取原生模型与命名权限，并在对话中固定模型、权限及 `approvalPolicy=never`。未接入的交互不会自动批准。
- **DSH**：使用官方 Web Host 的本机回环入口。`launchFile` 内容为原生启动 URL，含连接秘密，文件必须为运行账号拥有的普通 0600 文件，父目录不可被组或其他用户写入；不接受符号链接或公网地址。Host 重启后由操作者原子更新该文件，适配器重连会重新读取。不要把 URL 放浏览器地址、Git、日志或公开配置示例中。

容器部署需要显式提供上述 IPC、只读连接文件与正确的工作区路径映射，保持原生看到的 cwd 一致。默认 Compose 只运行中书和持久卷，不暗中开放宿主目录或管理 socket。具体进程监管、账号登录、文件交接和 TLS/代理配置归实例运维。

## 使用与恢复

创建时选择工作区、Harness、实际可用模型和权限；这四项在本对话中固定。每段对话拥有自己的原生绑定，初始化中途失败也保留已取得的身份，不自动创建替代会话。界面显示文本、简要工具活动和原生状态；文件正文与执行效果仍以工作区为准，尚无通用成果阅读器。

发送先在 SQLite 记下稳定操作编号，再派发原生请求。浏览器保留原始发送编号和输入，直到原生确认接收；未知结果只查询或以同编号核对，中书不会盲目重复派发。已接受与已完成分别判断；同一对话需核实上一条消息对应的原生运行终态后，才能发送下一轮。运行中追加、审批与提问回答不属于此切片。

关闭页面后重新进入，读取同一对话与原生状态。历史使用稳定条目身份和分页，实时正文与完成历史核对后合并；原生记录与中书展示历史都可能包含私有内容。当前没有自动删除或保留期清理，按数据目录及备份策略保护它们。浏览器仅在当前标签页会话存储草稿和待确认的发送，不保存认证秘密；确认退出会清除这些草稿。

停止以当前运行编号为目标，等待原生终态。DSH 的取消接口只接收会话身份，中书会先核对运行，但原生不提供原子条件取消；也不会清空原生待处理输入。原生进程崩溃后的工具残留须由外部监督器处理，不能把“已中断”当作所有副作用都已停止。

应用重启把派发中的操作标为待核实，重新读取原生关联信息。备份恢复比普通重启更保守：备份中的 queued 或 dispatching 在备份后可能已经执行，恢复时一律转为 unknown，并吊销旧登录会话。恢复不会重新派发它们。

## 边界与修改入口

| 修改对象 | 唯一入口 |
| --- | --- |
| 原生协议、配置与消息身份映射 | [Codex adapter](../src/harness/codex/index.ts)、[DSH adapter](../src/harness/dsh/index.ts)及各自协议测试 |
| 操作顺序、历史投影与持久水位 | [workbench-store.ts](../src/server/workbench-store.ts)及[迁移](../src/server/migrations.ts) |
| 派发、恢复与观察生命周期 | [workbench.ts](../src/server/workbench.ts)及故障契约测试 |
| HTTP 校验、公开数据与有界更新流 | [workbench-http.ts](../src/server/workbench-http.ts)、[共享契约](../src/shared/workbench.ts) |
| 页面恢复、草稿、阅读和发送反馈 | [工作台页面](../src/web/workbench.tsx)、[请求与草稿](../src/web/workbench-client.ts) |

观察数量、恢复页数、事件保留、正文和响应字节等上限以这些模块的常量与行为测试为准。超出恢复窗口时保留待核实状态，不把缺口伪装成完整历史。HTTP + SSE 已作为当前实现；通道定案与质量预算仍按 [ADR 0004](adr/0004-recoverable-communication.md) 的实际链路实验判断，不能用本机单元测试签发 Android、代理或性能验收。
