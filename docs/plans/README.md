# 渐进交付路线

每次完成一条用户可操作的路径，让其需要的基础随之形成。已有公开版本与连通页的实际结构见[架构地图](../architecture.md)。下表是后续方向，不是已实现能力，也不是预先创建整套目录的清单。

| 顺序 | 完整用户行为 | 此时需要建立的基础 |
| --- | --- | --- |
| 1 | 登录私人入口，刷新/重启后恢复身份，退出后失效 | 最小应用栈、认证、SQLite、迁移与恢复；详见[下一切片](first-private-slice.md) |
| 2 | 选择工作区和配置，完成首段真实对话，关页后从另一端接续 | 首个 Harness、原生绑定、操作记录、完整历史、可恢复更新；先完成通信实验，断线和性能随本切片验收 |
| 3 | 执行中追加、停止、回答问题或审批 | 逐个动作实现原生语义、多端认领和未知回执处理 |
| 4 | 使用第二个 Harness 完成对应工作 | 以第二个真实实现校验接口与能力差异；两个 Harness 都是首版要求 |
| 5 | 从对话打开成果，跳转到底稿再返回 | 文件引用与 HTML 阅读；只读小样本可提前到首个对话之后 |
| 6 | 编辑 Markdown/TXT、预览、保存并处理其他写入者的改动 | 编辑器、文件版本与条件保存可行性 |
| 7 | 上传图片/常见文档交给 Agent，并能回看 | 上传生命周期、真实原生输入、失败处理与清理 |
| 8 | 搜索、语音转文字、安装后恢复工作 | 分成独立小切片；语音先转成可编辑输入再发送 |

[质量要求](../quality.md)贯穿每行，从功能首次出现即检查手机交互、长内容及失败恢复；不单设最后的稳定性补课。HTML 原型只指导设计意图，具体布局与实现通过真实行为验证。

只有第一行展开实施步骤。遇到会推翻架构的未知项，先运行[针对性实验](integration-probes.md)，将产生的决定归入对应 ADR；结果日志留在任务/PR。后续切片开始时再细化，完成后移除过期计划。
