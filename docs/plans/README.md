# 渐进交付路线

每次完成一条用户可操作的路径，让其需要的基础随之形成。[私人入口](first-private-slice.md)与当前工作台的实际实现见[架构地图](../architecture.md)。第一条 Agent 曳光弹已接通两个 Harness 和受保护的浏览器路径，仍按[验收边界](first-harness-tracer.md)区分本机、目标设备与部署链路。后续各行尚未实现。

| 顺序 | 完整用户行为 | 此时需要建立的基础 |
| --- | --- | --- |
| 1 | 选择 Codex 或 DSH，完成一段真实工作，关页后回来接续；必要时停止 | 两个最小 adapter、原生绑定、操作记录、完整历史与可恢复更新；[私人入口](first-private-slice.md)是浏览器交付的前置步骤 |
| 2 | 在多个自选工作区开展工作 | 将首条曳光弹的配置工作区扩展为用户可登记/选择的目录 |
| 3 | 执行中追加、回答问题或审批 | 逐个动作接通两端的原生语义、多端认领和未知回执处理；首条已包含显式停止 |
| 4 | 从对话打开成果，跳转到底稿再返回 | 文件引用与 HTML 阅读；只读小样本可提前到首个对话之后 |
| 5 | 编辑 Markdown/TXT、预览、保存并处理其他写入者的改动 | 编辑器、文件版本与条件保存可行性 |
| 6 | 上传图片/常见文档交给 Agent，并能回看 | 上传生命周期、真实原生输入、失败处理与清理 |
| 7 | 搜索、语音转文字、安装后恢复工作 | 分成独立小切片；语音先转成可编辑输入再发送 |

[质量要求](../quality.md)贯穿每行，从功能首次出现即检查手机交互、长内容及失败恢复；不单设最后的稳定性补课。HTML 原型只指导设计意图，具体布局与实现通过真实行为验证。

先完成第一行的适用验收，再展开下一条用户路径。遇到会推翻架构的未知项，先运行[针对性实验](integration-probes.md)，将产生的决定归入对应 ADR；结果日志留在任务/PR。后续切片开始时再细化，完成后移除过期计划。
