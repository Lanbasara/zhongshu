# 第一条 Agent 曳光弹：完成真实工作，离开后接续

状态：固定版本下的有限原生契约实验已完成，产品路径未实施。目标是在同一套中书界面中选择 Codex 或 DSH，各自完成一次工作区任务，关闭页面后回来看到完整结果，并在原生同一会话继续。两个 Harness 各自维护对话，不在一段对话中切换 Harness。

两端最小契约实验先回答“哪些行为能统一、哪些差异必须保留”，不替代产品验收。随后形成可以交付的完整路径；[单管理员私人入口](first-private-slice.md)仍是浏览器访问私有能力的前置步骤。登录、核心接入和界面可以分小提交完成，不要求一个大 PR。

## 唯一主场景

准备两份内容相同、目录独立的测试工作区，各有一份包含可核对事实的 `notes.md`，避免两个 Harness 相互改写验收结果。

1. 选择 Harness、该端实际可用模型与一组明确的测试权限，创建对话；配置按既定规则固定。
2. 发送“读取 notes.md，概括三条事实，并写入 result.md”；看到文本输出、简要工具活动与真实执行状态。
3. 在确认任务仍运行时关闭页面，之后重新打开或从另一端进入；看到同一对话的结果与完整正文。
4. 在原会话继续追问，验证原生会话身份未变、上下文仍在。独立检查工作区确实生成了预期文件，不能只相信模型声称已写入。
5. 另发一个可控制执行时长的小任务，显式停止并等待原生终态；停止不承诺撤销已经产生的文件效果。

第一条界面只需要 Harness/配置选择、一个对话视图、输入、状态和停止。工作区先从部署配置指定；文件成果以回复中的引用及验收读取证明，通用文件浏览器、HTML 阅读器和编辑器留到后续。工具由 Harness 执行，中书不自行模拟 Agent loop。

## 第一步：两端原生契约实验

只用小型协议客户端，先后访问固定版本的 App Server 与 Web Host。实验隔离数据和原生配置，在受控本地/私有环境运行；不将实验接口接到公开演示页。模型账号登录与客户端到 Host 的连接认证分别验证，使用各自原生流程；不将个人凭据提交到仓库或写入实验输出。

| 要回答的问题 | 可核对的证据 |
| --- | --- |
| 能否按约定创建工作上下文 | 真实 cwd、原生会话身份、选定模型/权限与实际生效状态；部分初始化失败可识别 |
| 能否执行而非仅文本问答 | 原生工具活动、工作区读取和实际文件产物 |
| 回执、增量和完成分别是什么 | 关联同一操作与原生运行的观测；完成正文与增量重建一致 |
| 离开观察者会发生什么 | 分别断开浏览器观察与 adapter 到原生的连接；确认哪些资源属于任务，哪些只属于观察者 |
| 重连如何找回工作 | 重新认证、恢复原身份、读取历史/当前状态与补齐缺口；恢复读取不重新触发模型执行 |
| 如何停止及解释异常 | 原生取消回执、最终状态及保留队列的行为；回执丢失时能核实或明确未知 |
| 重启改变什么 | 分别终止中书进程、原生进程；记录任务是否继续、可恢复还是已中断，不预先承诺无损续跑 |

两端各完成上述最小路径后即收束，产出实测能力表及可重复探针；不在实验阶段覆盖完整首版功能。认证无法完成时记录具体卡点，已有账号不等于部署实例已登录。

## 从实验收敛接入接口

接入模块的职责划分见 [ADR 0001](../adr/0001-native-harness-boundary.md)。以下是待实验修正的概念接口，不预先固定 TypeScript 方法名或基类层级：

| 上层意图 | 接入模块应承担的复杂度 |
| --- | --- |
| 查看可用配置 | 原生模型与权限选项，以及此版本可验证的能力与限制 |
| 创建/恢复对话 | 原生握手、身份、配置生效和会话绑定；全部准备完成才允许发送，恢复不偷偷创建新会话 |
| 提交一条文本 | 原生请求关联与接收结果；未知回执不能伪装为失败或完成 |
| 读取当前状态与历史 | 原生分页、稳定条目身份、覆盖范围及待处理原因 |
| 观察变化 | 原生订阅、增量转换和重连；解除观察不会隐式停止任务 |
| 停止当前工作 | 原生目标定位、取消请求与最终状态核实 |

中书应用统一持有操作记录、对话配置与展示历史；两个 adapter 各自拥有原生协议、连接身份、错误解释与恢复细节。业务操作去重和浏览器恢复不在两个 adapter 中各写一遍，沿用 [ADR 0004](../adr/0004-recoverable-communication.md)。

创建会话不假设原生一次请求完成所有配置。例如 DSH 创建、模型选择、权限设置分步进行；中间失败时保留已取得的绑定及准备状态，不开放发送，也不因重试悄悄创建第二段会话。原生连接恢复与中书浏览器游标分开，不能将中书补发游标直接传给不支持它的原生接口。

消息身份、状态和失败模式形成小而明确的共同契约，原生类型留在接入模块内部。能力差异以有语义的描述提供，例如追加能否限定当前轮；不只用一个 `supportsSteer` 布尔值掩盖差异，也不把整包原生事件交给每个页面解释。

首个 adapter 可以改变草案接口；第二个 adapter 必须在扩展首个 Harness 的高级功能前接入。两端跑通相同行为后才固定这版契约，避免抽象围绕一个供应方长成。上层稳定意味着常规协议变化在 adapter 内消化；新增产品语义仍可能需要共同演进。

## 浏览器路径与交付验收

完成[身份前置步骤](first-private-slice.md)，使用 React/Vite、Node 应用与 SQLite 贯通同源浏览器路径。前端只观察中书状态；中书持有原生工作所需连接，原生进程不按浏览器请求创建和销毁。通信选型与预算按[质量要求](../quality.md)执行。

| 场景，两端分别执行 | 完成条件 |
| --- | --- |
| 主场景 | 同一套界面与业务路径通过两个 adapter；真实读取、产物和后续上下文均有证据 |
| 发送后回执丢失、重复请求 | 不盲目再次派发；显示可查的结果或待核实，输入不无声丢失 |
| 运行中关页、重开、第二端进入 | 工作未被页面关闭取消；原生身份、配置和历史保持一致 |
| 重连时仍有输出 | 历史与新事件无缺口、不重复显示，旧连接不覆盖当前状态 |
| 显式停止与原生故障 | 终态可核实；若原生保留待处理输入则明确展示，不承诺队列清空；进程中断不能被显示为成功完成 |
| 权限等待或不支持的请求 | 明确显示等待/限制，允许停止；未适配的交互不静默批准或放宽原策略 |
| 桌面与 Android | 真机输入、后台切回及实际代理链路通过适用质量项；模拟和真机证据分别记录 |

完成的是可复用的两端最小执行闭环。运行中追加、完整提问/审批、任意工作区管理、附件和成果阅读仍按后续切片逐项扩展；本条记录其原生能力线索，不提前完成全部界面。

探针与真实浏览器验收走同一接入接口；模拟事件只用于可控故障和负载，不能代替两端账号下的真实运行。成功后把实际模块入口更新到架构地图，将协议证据与已知限制就近维护；单次结果归 PR/CI，不另建平行研究长稿。
