# 下一切片：单管理员私人入口

状态：计划，未开始实现。目标是管理员登录后能访问真实受保护入口，刷新及正常应用重启后按有效期恢复身份，退出后旧会话失效。公开版本与健康接口继续可用。

## 最小范围

- 按 [ADR 0002](../adr/0002-application-stack.md) 建立 TypeScript、React/Vite 与服务端链路，保留既有版本追溯和容器接口。只实现登录、私人入口、退出。
- 单管理员本地初始化/重置，使用成熟密码散列实现及随机不透明服务端会话；无公开注册或默认密码。初始化只在管理员不存在时可用，秘密经交互或受保护入口提供。
- 登录轮换会话，退出吊销当前会话，重置凭据吊销已有会话；使用 HttpOnly/Secure/SameSite Cookie、来源/CSRF 防护、登录限速、有界请求与不含秘密/正文的诊断。
- 按 [ADR 0003](../adr/0003-local-persistence.md) 引入真实持久化、迁移和数据目录。私人入口读取服务端真实身份，不以模拟工作区或 Agent 状态代替认证验收。

会话期限、散列参数及兼容插件属于实现决定，在代码和操作文档中维护。实际初始化时再由管理员提供秘密，本计划不采集凭据。

## 实施与完成条件

1. 固定首个切片用到的版本，验证 SQLite 驱动与现有安装、基础镜像和目标架构。跑通开发、构建与容器；框架和驱动验证结果更新对应 ADR。
2. 通过真实数据库验证初始化、失败/成功登录、过期、退出与重置；受保护接口统一执行认证和授权。数据迁移失败时不提供半初始化的私有服务。
3. 接入浏览器路径，检查桌面和手机的输入、错误、焦点、刷新和退出；[质量要求](../quality.md)中的适用项同时验收，记录首屏与交互基线。
4. 用临时持久卷验证容器替换、故障与一致备份恢复。恢复后的实例应能验证原账号及会话策略，不能以复制空库证明恢复。
5. 补实际模块地图和本地操作入口，完成相关审查与 CI；按[开发流程](../development.md)交付可审阅 PR。此计划不包含生产初始化或发布。

| 验收 | 证据要求 |
| --- | --- |
| 访问边界 | 未登录、伪造、过期、吊销会话均被拒绝；公开资源无私有状态 |
| 两端会话 | 两个独立浏览器同时登录；退出仅影响当前会话，重置使全部旧会话失效 |
| 写入边界 | 非法来源/CSRF、重复初始化和过量尝试被拒绝，日志无凭据 |
| 故障与数据 | 登录响应丢失后可恢复身份或安全重新登录；重建保留账号，迁移与备份恢复可重复 |
| 用户路径 | 真实浏览器完成登录到退出；Android 真机输入及未执行检查分别标明 |

并行于可独立进行的应用工作，尽早核查[两个 Harness 的启动条件](integration-probes.md)，避免首个接入完成后才发现另一个的生命周期差异。原生运行、流式通信和文件能力不由本切片的通过推断成立。
