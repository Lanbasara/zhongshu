# 会改变架构的接入实验

以下均未执行。每项只回答一个会改变实现或产品承诺的问题；保留版本、环境、复现、反例和结果，产生的决定就近进入 ADR。网络与内容性能实验统一见[质量要求](../quality.md)。

## 两个 Harness：在首个接入前开始

启动、原生身份、读写执行、观察连接、重连与停止先按[首条曳光弹的原生实验](first-harness-tracer.md)验证，避免平行维护两份实验清单。

后续在追加/提问/审批切片前，再验证运行末尾追加、审批等待时断线、两端回答竞争、请求失效与原生配置继承。能力表标明固定版本、可用、限制和未验证；实际身份与文件权限遵循 [ADR 0001](../adr/0001-native-harness-boundary.md)。

## 文件保存：在开放原地编辑前

测试两个浏览器从同一旧版本保存，以及独立进程在版本检查与文件替换之间直接写入；覆盖删除、替换、重命名及路径/符号链接变化。仅比较 hash/mtime 或使用 fs.watch、应用内互斥不足以覆盖独立写入者。

原子 rename 不会把此前读取/比较变成条件事务；flock 是建议锁，不约束不参与的写入者。先评估可实施的统一写入协议或独占写入窗口；若与原生工具能力冲突，带着复现明确“何时允许原地保存、何时保留修改并另存/合并”的产品取舍。保存副本不能冒充冲突保存要求全部完成。[rename](https://man7.org/linux/man-pages/man2/rename.2.html)、[flock](https://man7.org/linux/man-pages/man2/flock.2.html)

## HTML 阅读：在成果阅读交付前

使用真实报告覆盖版式、长文、宽表、图形、目录、折叠、相对底稿、外链与返回位置。先测试无报告脚本的阅读路径，脚本需求由实际样本确认；不能以静态模板证明任意报告可读。

内容隔离与导航一起验证：报告不能取得应用身份或访问管理接口；隔离文档可能是 opaque origin，父页面不能假定可读取其 DOM。允许脚本时另定来源和受限资源通道，避免同源内容同时获得脚本与同源权限。完成条件是明确支持范围并通过桌面/手机真实阅读及隔离反例。[iframe 语义](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)
